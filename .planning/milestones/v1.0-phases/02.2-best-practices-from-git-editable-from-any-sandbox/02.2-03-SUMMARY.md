# Phase 2.2 Plan 03: Edit rights and first-run wrappers Summary

**Managed settings let Claude edit the best-practices clone from any project folder while the skills stay denied, three tiny wrappers (sbx-gh-login, sbx-bundle-clone, sbx-claude) ship in the Claude image, and a sandbox can no longer be named state or best-practices.**

## Accomplishments

- Tracer rehearsal passes with Claude 2.1.285: without `additionalDirectories` the clone rule stays `sbx-perm-before`; with the managed settings it becomes `sbx-perm-after`; an Edit through `state/claude/skills/...` leaves the skill file unchanged.
- `claude/managed-settings.json` is exactly `additionalDirectories` (the clone) plus a deny on the skill list and `skills/**`; the rules deny is gone.
- `sbx-gh-login`, `sbx-bundle-clone` and `sbx-claude` are in `claude/bin` at mode 100755, copied with `COPY --chmod=755 claude/bin/ /usr/local/bin/`, covered by `SHELL_FILES`, shellcheck clean.
- `sbx-bundle-clone` refuses an existing folder (a planted file stays), a failed clone exits 1 naming `sbx-gh-login` and leaves no folder; on success it runs `/etc/sbx/start.d/10-best-practices`.
- `sbx-claude` printed the marked warning and waited 5 s with nothing linked, passed `--version` through (`2.1.285 (Claude Code)`), and was silent once the rules link resolved to the clone.
- `check_sandbox_name` refuses `state` and `best-practices` with `[sbx] ERROR: SBX_NAME "..." is taken: ...`; `my-project` and `a` still start.
