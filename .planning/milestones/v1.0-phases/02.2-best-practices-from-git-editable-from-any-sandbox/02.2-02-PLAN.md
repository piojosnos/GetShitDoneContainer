- Open Question 2 is a checkpoint, as asked: rewording is cheap before the push and a one-way door after it. Recommended: reworded (the user's rule bars planning IDs from committed source; the seeded history becomes another repo's committed history).

- Reversibility: the repo name is costly (versions.env, image ENV, docs, every clone's remote); the seed push is one-way (rewording a published main needs a force push and a new clone everywhere). Both sit behind a blocking checkpoint.
- Coexistence: nothing here touches this repo's tree, so the plan can run beside plan 01. After the seed, nobody edits `best-practices/` in this repo; plan 07 deletes it.
