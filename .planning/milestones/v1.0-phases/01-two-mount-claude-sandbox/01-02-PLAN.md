## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-09 | Tampering | gh release tarball | high | mitigate | Exact `GH_VERSION=2.102.0`, `sha256sum -c` against the release's `gh_${GH_VERSION}_checksums.txt`, single-member extract with `--no-same-owner`. Static check "gh 2.102.0 pinned and checksum-verified" |
| T-01-10 | Information disclosure | gh token in state/gh/hosts.yml (plain text, no keyring in container) | medium | mitigate | `state/gh` sits outside `workspace/`, so it is never in a git work tree. SANDBOX.md tells the user about the plain-text token. The residual risk (the agent can read the token) is accepted as inherent to giving the agent gh and goes to the Phase 5 threat-model section (DOC-03) |
| T-01-11 | Information disclosure | bash history in state/shell | low | accept | History can capture secrets typed at the prompt. The stock skel `.bashrc` sets `HISTCONTROL=ignoreboth`, so a command typed with a leading space is not recorded. This is the same exposure the old whole-home layout had |
| T-01-12 | Tampering | agent-writable git global config in state/git | low | accept | Read only by git inside the container. The Mac's git reads `~/.gitconfig`, never `state/git/config`. Hooks the agent plants in workspace repos are a Phase 5 DOC-03 item |
| T-01-13 | Elevation of privilege | new mount sources | medium | mitigate | All three new sources are under `${SBX_DIR}/state`. Static checks "every mount source is under SBX_DIR", "exactly five bind mounts" and "no short-syntax mounts" |
| T-01-SC | Tampering | package installs in this plan | high | mitigate | No registry installs in this plan. The only new download is the checksum-verified gh tarball. The npm legitimacy gate (01-01 Task 1) still governs `@anthropic-ai/claude-code` |
</threat_model>
