Reviewed the new code of the split (the shared libs, every run-all.sh, the group programs, the fake docker structure, the new end-of-run text in `tests/host/run-all.sh`, the doc edits). The four suites run green in the dev sandbox (guard: all rules hold; entrypoint, bundle and host self-tests: all cases pass), no work folder leaks after a run, and an INT sent to the process group stops the run and cleans up. ## Warnings

### WR-01: A group program missing from a run-all list is silently never run

**File:** `tests/guard/run-all.sh:15`, `tests/selftest/bundle/run-all.sh:15`, `tests/selftest/entrypoint/run-all.sh:14`, `tests/selftest/host/run-all.sh:17`
**Issue:** Each runner holds a hand-written `groupList`. In the old single-file suites a new case ran by being written. Now a new group file that is not added to the list is never executed, and nothing reports it. The guard is the safety net, so a rule group forgotten in `tests/guard/run-all.sh` is the worst case: the rule stops existing and the run still says "All rules hold." A listed-but-missing file is caught (exit 127 becomes a counted failure), but the reverse is not. The project already has the precedent for this check: `host_checks_declare_dependencies` in `tests/guard/host-tests.sh:82` fails when a host check is not named in `tests/host/run-all.sh`. The same hole exists for the selftest of a new host check (`tests/selftest/host/` needs a group by hand).
**Fix:** Add a guard rule that every program in each suite folder is named in that suite's runner, for example in `tests/guard/host-tests.sh`:
```bash
# suite_groups_are_listed: every group program in a suite folder is named in its run-all.sh.
suite_groups_are_listed() {
  local suiteDir group
  local ok=0

  for suiteDir in tests/guard tests/selftest/bundle tests/selftest/entrypoint tests/selftest/host; do
    for group in "$suiteDir"/*.sh; do
      case "$(basename "$group")" in
        lib.sh | run-all.sh) continue ;;
      esac

      if ! grep -Fq "$(basename "$group")" "$suiteDir/run-all.sh"; then
        echo "    $group: is not named in $suiteDir/run-all.sh"
        ok=1
      fi
    done
  done

  return "$ok"
}
```

### WR-02: `nowhere_matches` passes when a file it is meant to scan does not exist

**File:** `tests/guard/lib.sh:30`
**Issue:** `hits=$(grep -En -- "$regex" "$@" 2>/dev/null)` discards grep's exit status 2 and its error text, then `[ -z "$hits" ] && return 0` reports the rule as held. Every rule in `supply-chain.sh`, `planning-ids.sh` and `bundle-wiring.sh` passes `$VAR` lists and globs unquoted, so a renamed file, a typo, or a glob that matches nothing (the new `tests/selftest/*/support/*` and `tests/selftest/*/*.sh` patterns are exactly this kind) leaves the literal pattern as the grep argument, grep fails, and the rule passes with nothing scanned. Verified: `nowhere_matches docker does/not/exist.txt` returns 0 with no output. This breaks the project's own shell rule: "Fail closed: an input the script cannot use stops it with an error. Never skip it silently." The same pattern is in `host_code_lines` (`tests/guard/host-tests.sh:12`).
**Fix:** Fail the rule when grep reports an unreadable input (status 2), and print its message:
```bash
nowhere_matches() {
  local regex=$1
  local hits
  local grepStatus

  shift
  hits=$(grep -En -- "$regex" "$@")
  grepStatus=$?

  if [ "$grepStatus" -gt 1 ]; then
    echo "    grep could not read one of its input files"
    return 1
  fi

  if [ -z "$hits" ]; then
    return 0
  fi

  echo "$hits" | sed 's/^/    /'

  return 1
}
```
(Keep stderr visible so the missing path is named.)

### WR-03: The guard's portability rule does not cover the guard files that run on the Mac

**File:** `tests/guard/lib.sh:21`, `tests/guard/host-tests.sh:43`
**Issue:** `tests/guard/lib.sh` states the guard may run by hand on the Mac with stock bash 3.2 and BSD tools, and `tests/guard/*.sh` is a new set of 9 files. But `HOST_FILES` is only `tests/host/*.sh tests/host/manual/*.sh`, so `host_tests_are_portable` never scans `tests/guard/`. Today the files are clean (checked by hand: no `sed -i`, `grep -P`, `timeout`, `mapfile`, `stat -c`, `readlink -f`), but the next edit can add a GNU-only construct and the guard that exists to catch it will pass. The selftest and entrypoint suites are Linux only by design, so this concerns only the guard.
**Fix:** Run the portable rule over the guard files too. In `tests/guard/lib.sh` add `GUARD_FILES="tests/guard/*.sh"`, and in `host_tests_are_portable` add a second call that scans `$GUARD_FILES` with the same regex. The rule's own regex literal contains the forbidden words, so exclude `tests/guard/host-tests.sh` from that scan, or build the regex from pieces.

### WR-04: The new "see tests/host/manual/" line is a relative path in a runner documented as run "from anywhere"

**File:** `tests/host/run-all.sh:159` (asserted at `tests/selftest/host/runner-healthy.sh:48` and `tests/selftest/host/runner-failures.sh:19,43,81,123`)
**Issue:** The old Next block printed absolute, copy-pasteable helper paths (`${HOST_DIR}/manual/...`). The replacement prints `tests/host/manual/`, which only resolves when the user's shell is in the repo root. The header says "Usage, from anywhere", and the cleanup line right above it uses an absolute `cd`. On the Mac the user is likely in some other folder when the run ends. The line also prints on every end state, including a failed build or an unreachable daemon, where none of the helpers (login, rebuild-resume, doctor, bundle behaviour in Claude) diagnose the failure, so "If something looks wrong" points at the wrong tool for most failures.
**Fix:** Print the absolute folder and name what the helpers are for:
```bash
printf '  The attended helpers (login, rebuild and resume, claude doctor, bundle behaviour) are in %q\n' "${HOST_DIR:-}/manual"
```
and update the five selftest assertions to match.

### WR-05: Documentation overclaims what a passing `run-all.sh` proves

**File:** `SANDBOX.md:193`, `tests/host-checklist.md:3`, `tests/host-checklist.md:45`, `tests/host-checklist.md:47`, `tests/host-checklist.md:57`, `tests/host-checklist.md:60-62`

But the checklist's own table lists H-07 (Claude login lands in the state folder) and H-19 (skills, rules and the managed settings as Claude shows them) as "helper only", and H-09's "the login and the session survive too" and H-13's `claude doctor` agreement as "helper for the rest". The project's core value is that a rebuild delivers tools without losing the agent's login. The login path (H-07) and the login surviving a rebuild (H-09 helper part) now have no automated proof, so a green run cannot support "the build is good". Line 3 ("cover the steps that need you; run one when something looks wrong") and line 60 ("Not a required step ... or after a change the automated checks cannot see") also disagree about whether the helpers are needed.
**Fix:** State the limit in `SANDBOX.md` and make the checklist consistent, for example: "When it passes, the automated checks hold. The login and Claude behaviour checks (H-07, H-09 second half, H-13 doctor, H-19) are only covered by the helpers in `tests/host/manual/`; run them after a Claude Code pin change, a change to the managed settings, or a change to login handling." ### WR-06: `lacks_text` and `lacks_match` pass when the file cannot be read

**File:** `tests/selftest/lib-expect.sh:41`, `tests/selftest/host/lib.sh:46`
**Issue:** `lacks_text() { ! grep -Fq -- "$2" "$1"; }` negates grep's status, so grep exit 2 (missing or unreadable file) becomes "true" and the case prints PASS. Verified: `expect x lacks_text /nonexistent/file foo` prints PASS (grep's error line is the only hint). Negative assertions guard the safety claims of the host self-test ("nothing is removed or pruned", "the caller's decoy values never reach docker", "Compose 1.x builds nothing"). Today the files exist, so the cases are real, but a renamed output file or a failed `sed` that writes `args.*` would turn them into vacuous passes.
**Fix:** Require the file to be readable first:
```bash
lacks_text() { [ -r "$1" ] && ! grep -Fq -- "$2" "$1"; }
```
and the same for `lacks_match` with `grep -Eq`.

### IN-03: `run_groups` and `enter_repo_root` exist in two near-identical copies

**File:** `tests/selftest/lib-expect.sh:71-109`, `tests/guard/run-all.sh:22-47`, `tests/guard/lib.sh:51-59`
**Issue:** The guard cannot load `lib-expect.sh` (it is Linux only), so `run_groups` and `enter_repo_root` are duplicated, differing in the counter name and the words "rule" and "case". Two copies are within the stated tolerance, but any fix to the crash accounting (for example, the output buffering below) has to be made twice. `HOST_UNATTENDED_FILES` in `tests/guard/lib.sh:22` is also used by `host-tests.sh` only, which the layout rule says belongs in that script.
**Fix:** Put `run_groups` (taking the label word as an argument) and `enter_repo_root` in a Mac-safe library that both suites load, or accept the duplication and add a comment in each copy naming the other.

### IN-04: Six cases in the H-17 group use runs of spaces instead of line continuation

**File:** `tests/selftest/host/h17-start-offline-and-failing-hook.sh:19,22,23,24,25,30`
**Issue:** `expect "name"   command ...` joins the name and the command with three spaces on one very long line (up to about 190 columns), where every other group breaks the line after the name with a backslash. Harmless to behavior, but it is the visible seam of a mechanical move and is inconsistent with the rest of the suite.
**Fix:** Break after the name with ` \` and indent the command, as in `h14-bundle-in-image.sh:19-20`.

### IN-05: Group output is buffered, so an interrupted or hung group shows nothing

**File:** `tests/selftest/lib-expect.sh:81`, `tests/guard/run-all.sh:32`
**Issue:** `groupOutput=$(bash ...)` prints a group only when it ends. A group that hangs (the fake API probe allows `timeout 90`) shows no progress for minutes, and Ctrl-C mid-group discards that group's PASS and FAIL lines. The crash accounting is correct (a non-zero exit with no FAIL line counts as one failure), so this affects diagnosis, not results.
**Fix:** Stream the group's output with `tee` to a temp file and count `FAIL:` lines from the file, or print each group's name before it starts.
