## Phase Goal

ROADMAP.md Phase 01.4 goal (verbatim): "The test suite is small enough to read and change. The root cause of its size is fixed: most of `tests/host-selftest.sh` is a fake docker that exists only because the dev sandbox has no real Docker. The suite is simplified and split into logical units, and the three big test scripts get the script layout rule. From the PR #9 review."

Planning notes:
- Spec-less probe fallback skipped (no requirement IDs; visible skip).
- Size of the fake, said plainly for the user: dropping the three dead knobs removes about 25 lines, and the layout rule (a banner per function, Main) adds about 50, so the file stays about 480 to 520 lines. The gain is that it is its own file, one function per docker subcommand, with every knob listed in one header table. A much smaller fake would need dropping whole check simulations, which D-04 and D-17 rule out. A backlog entry to retire the fake is added in plan 07 (D-18).
- Cut and move: each task cuts its sections out of tests/host-selftest.sh into new group programs. The old file keeps its heredoc fake and its helpers until plan 05 deletes it; prove.sh compares the old remainder plus the new runner with the baseline after every task.
- Plans 03, 04 and 05 share the code worktree and the old file, so they run one after the other.

<objective>
Move the fake docker out of the heredoc into tests/selftest/host/support/fake-docker in the layout style, dropping only its dead knobs, and prove it answers exactly like the old fake. Build the host self-test folder (lib.sh, run-all.sh) and move the first eight check groups into it.

Purpose: SC2 (the fake in its own file, slimmed to what is still needed) and the start of SC3 for the biggest suite, proven at every step.
Output: support/fake-docker, lib.sh, run-all.sh, eight group programs, harness/fake-transcript.sh; eight sections cut from tests/host-selftest.sh.
</objective>
