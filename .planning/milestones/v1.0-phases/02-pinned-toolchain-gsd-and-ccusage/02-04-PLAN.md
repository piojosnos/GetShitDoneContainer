## Phase Goal

ROADMAP.md Phase 2 goal (verbatim): "The sandbox has the full development toolchain plus Claude Code, GSD, and ccusage baked into the image at versions pinned in one `versions.env`. Rebuilding with changed pins delivers the new versions into the sandbox while login and history persist."

This plan delivers the new requirement IMG-07 (D-15 to D-17): the npm, uv and Maven caches survive a recreate, so a rebuild or upgrade does not download everything again.

Planning notes:
- Traps from research Pattern 5: the Claude image replaced SBX_STATE_DIRS, which would silently drop the base's cache folders; and NPM_CONFIG_CACHE from the base would make the Claude image's build-time npm installs write a root-owned cache under the mount point. Both get a fix and a guard rule here.
- The base owns these caches because npm, uv and Maven are base toolchains (D-19).
- The entrypoint needs no change: create_state_dirs already splits SBX_STATE_DIRS on spaces and runs `mkdir -p` for each entry, so `cache/npm` works; a new entrypoint self-test case proves it.
- Task 2 touches eight files because a new host check is tied by the guard to its run list, its self-test group, its checklist row and the runner counts.
- Reversibility: caches are deletable folders; reversible.
