## Phase Goal

ROADMAP.md Phase 2 goal (verbatim): "The sandbox has the full development toolchain plus Claude Code, GSD, and ccusage baked into the image at versions pinned in one `versions.env`. Rebuilding with changed pins delivers the new versions into the sandbox while login and history persist."

This plan delivers success criterion 1: in the container shell, git, gh, node (24.x), python3, uv, java (Temurin 21) and mvn work as native arm64 binaries and come from the shared base image.

Planning notes:
- Values come only from 02-PINS.md rows marked approved. The research values are given as the expected ones; if the approved value differs, the approved one wins.
- Each pin ARG sits directly above the RUN that uses it; the apt layer has none, so a pin bump does not invalidate it (research A1, Pitfall 6).
- The probe lives in tests/host/support/ because it runs inside the container with GNU tools; the host check itself only reads its output. The host check finds Python by its version text, so its own code never needs the command name the portability rule bans on the Mac.
- No `fontconfig`: the Temurin tree copied from its image is enough for Maven and plain Java (research A7); add it only if a Mac check shows a font error.
- Task 2 touches nine files because a new host check is tied by the guard to its run list, its self-test group, its checklist row and the runner counts in one step.
- Reversibility: base image contents behind pins; reversible.
