## Kept (considered, not proposed)

- kept: `old_layout_untouched` and `OLD_LAYOUT_COMMIT`, because they are 5 lines and the only guard of `ClaudeCode/` and `OpenCode/` until Phase 5. R-04 relies on them.
- kept: the `docker.sock` and `privileged` grep in `no_docker_socket_or_privileges`, because it is 2 lines, gives feedback in the sandbox, and its `sudo` half is not covered by H-26.
- kept: `tests/selftest/guard/helpers.sh` (57 lines, cases for `nowhere_matches`), because a rule that passes after its file was renamed is the guard's own silent failure, and no plant exercises the missing-file or empty-glob branch.
- kept: `make_scratch_repo` copying the whole tree, because the guard self-test runs in 2.5 s and the tree is 4.8 MB (mostly `.planning`); a file list is more code than the `tar` pipe.
- kept: `run_groups` and `enter_repo_root` in both `tests/guard/` and `tests/selftest/lib-expect.sh`, because two copies is the project's tolerance; the rule extracts at three.
- kept: `tests/selftest/guard/linters.sh` (96 lines), because its missing-tool case backs the "missing linter fails" rule; cutting the passing case would save about 15 lines.
- kept: `base/sbx-start-lib.sh` apart from the `[ ! -f ]` branch (R-11), because every other branch has a self-test case or a Mac check, and the dotfile, fifo and dangling-link self-test branches are already gone.
- kept: H-03 (84 lines), because the `:?` refusals and the uppercase `name-check` service are Docker behaviour nothing else exercises; H-21 covers only the entrypoint rule.
- kept: the `check_privileges` function in H-26 (42 lines, the longest new function), because it asserts four independent facts and each message names the property.
- kept: `report_outcome` in H-20 and H-10 (36 and 31 lines), because each is a flat if chain with one distinct failure message per branch.
- kept: `run_groups` in both runners (33 lines each), see above.
- kept: H-18 and `tests/host/support/fake-claude-api.js`, because they are the only automated cover of the managed deny and the path scoped rules.
- kept: `manual/h07-login.sh`, `manual/h16-gsd-bump.sh`, `manual/h19-bundle-behaviour.sh`, because they are the only cover for Claude's login and behaviour (see `tests/README.md`).
- kept: automated H-09, H-16, H-23, `tests/host/lib-bundle.sh`, and the start-folders name rule cases, because each backs a data loss, fail-closed or name rule property and has several callers.
- kept: the rest of `host-test.sh` (a step list, new, no dead function), and the Dockerfiles and `compose.yml` (smoke tests and `name-check` do work other rows rely on).
