## Phase Goal

ROADMAP.md Phase 3 goal (verbatim): "The user registers each sandbox once, then starts, stops, and upgrades it by name alone. One command rebuilds the images and recreates the sandbox, and login and history survive."

The roadmap marks this phase `mvp`, but the goal line is not in user-story form; it is quoted verbatim as in earlier phases (run `/gsd-mvp-phase 3` if a story is wanted).

This plan is the phase tracer: a sandbox registered once with `sbx-add` starts and stops by its name alone. One path runs end to end and is proven here without Docker (a throwaway docker stand-in records the calls): the registry file, the shared library, the one name rule read from the image's start library, and the single Compose call shape. Plan 02 adds `sbx-upgrade` on the same library, plan 03 the version line and the docs, plan 04 the gate and the Mac run.

Planning notes:
- Decisions D-18 to D-22 were settled with the user after research and are locked. D-01 is rated costly by the discussion (every `sbx-*` script and the later list and remove commands read the path and the format): flagged on Task 1, not gated, because the user already chose it. No decision in this plan is a one-way door: the registry holds about four two-line files on one Mac.
- "Registry folder" means `SBX_CONFIG_DIR` (default `$HOME/.config/sbx`); entries sit in its `sandboxes/` subfolder, as research recommended. D-21's "holds the registry folder" check uses that folder.
- Planner choices (Claude's discretion, each cheap to undo):
  - Usage lines use the repo's uppercase placeholder style (`build.sh` prints `[DOCKER_BUILD_OPTION...]`): `Usage: sbx-add NAME HOST_PATH`. The key message phrases are fixed in this plan because the self-test and H-28 match them.
  - D-21 says "a host path that another registered sandbox already uses". The plan also refuses a folder inside, or holding, another sandbox's folder: either way one sandbox's agent would see the other's `state/` (its Claude login and gh token). It is the same one `case` check; drop the nesting half if it is not wanted.
  - The entry is written with the shell's noclobber (`set -C`) instead of research's temp file plus `mv`: creation is exclusive, so two `sbx-add` runs for one name cannot both win, and no temp file needs removing.
  - Paths are compared as text after normalising (no trailing slash, no empty, `.` or `..` part); symlinks are not resolved. The real cases (`/`, `$HOME`, the same folder twice, nesting) are all literal; resolving symlinks needs existing folders and more code.
  - The docker-free self-test puts a two-line stand-in `docker` first on PATH that records the call and exits 99. It models nothing; it makes "a case reached Docker" a visible failure and keeps the Mac run of the suite off the Mac's Docker. The stand-in docker in the tracer verify command is throwaway and not committed.
  - Each host check (and the attended helper of plan 02) gets its own registry and its own spaced sandbox folder inside the run folder, so the checks are independent and the printed cleanup removes everything.
  - The start wait in `bin/sbx-lib.sh` is called `wait_until_ready` so it is not confused with the host tests' `wait_for_start_hooks`.
- Canon items not minted as prohibitions: path traversal through the name and code injection through the registry are canon (covered by `/gsd-secure-phase` and the threat model below); they are tested as threats T-03-02 and T-03-03.
- `.dockerignore` is an allowlist (`*`, `!base`, `!claude`, `!versions.env`), so `bin/` never enters an image build.

## Conventions carried into every edit

- Comment shape: a banner is a rule line of `# ` plus 78 dashes (80 columns), a title line, a rule line, then at most two "why" lines and a closing rule; with no why, the title sits between two rules. No comment line over 80 columns; never three plain comment lines in a row.
- Shell: `set -eu` in the bin scripts, `set -u` in tests; libraries set no options and run nothing; functions plus a `# Main / Entry Point` banner over a short list of calls; braces always; a blank line before and after every `if`/`for`/`while`/`case` block (an `else` stays cuddled); full camelCase variable names; list variables end in `List`.
- Stock bash 3.2 and BSD tools (the scripts run on the Mac): no `mapfile`, `readarray`, `declare -A`, `${var,,}`, `${var^^}`, `&>>`, `|&`, `[[ -v ]]`, `local -n`, `sed -i`, `readlink -f`, `realpath`, `stat -c`; split `local name` from `name=$(command)` when the status matters; never expand a possibly empty array under `set -u` (`"$@"` is fine); keep `case` blocks out of `$( ... )`; the regex for `[[ =~ ]]` always in an unquoted variable.
- Quote every expansion; host paths may hold spaces.
- The text of every `bin/` file (code, comments and messages) never contains the words rm, rmdir, prune, kill or down, nor the option --volumes, nor the word eval: plan 02 adds a guard rule that refuses the destructive ones. `bin/` never sources or evaluates a registry entry.
- ASCII only. No em or en dash, no ` -- ` or spaced ` - ` used as a dash, in comments, messages or docs; punctuation after a closing quote.
- No planning IDs in committed source, tests, fixtures, comments or commit messages: no D-xx, SCR-xx, T-03-xx, phase numbers, assumption IDs, CONTEXT.md or .planning references. Host check IDs such as H-28 are product IDs and are fine.
