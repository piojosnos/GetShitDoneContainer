## Phase Goal

ROADMAP.md Phase 5.2 goal (verbatim): "A sandbox builds and runs on a Mac behind a company HTTPS proxy (Zscaler) by trusting one optional root certificate file; without the file, the image is unchanged. Runs before 5.1: it blocks every build on the work Mac."

Not in user-story form; quoted verbatim as in earlier phases.

This plan is the code of the phase. Task 1 is the tracer: one valid certificate travels from the Mac variable through `build.sh` into the base image's system store, which alone fixes the `gh` download that fails today, and the guard stays green. Task 2 makes the tools with their own store trust it too. Task 3 makes every bad input loud and adds the banner. Plan 02 documents it in README.md; plan 03 is the Linux gate, the clean code branch and the Mac runs (home Mac first, then work Mac).

Planning notes (each a choice the user can object to at review):
- Variable name `SBX_CA_CERT` (Claude's discretion, `SBX_*` naming).
- Delivery: a BuildKit named context, `--build-context cacert=<temp folder>`, overriding a `FROM scratch AS cacert` stage. A build arg would need an ARG without a `versions.env` pin (guard `every_dockerfile_arg_is_pinned` refuses it) and puts PEM text on a command line; a BuildKit secret is not part of the cache key, so a new or changed certificate would not rerun a cached step. `.dockerignore` and the repo tree stay untouched.
- No ENV: ENV cannot be conditional, and D-05 allows settings only when a certificate was given. Every setting is a file written by step two. Known limit (documented in plan 02): `NODE_EXTRA_CA_CERTS` comes from `/etc/bash.bashrc`, so a non-interactive `docker exec sbx-NAME node ...` does not get it. Claude Code needs no setting: it is a native binary that reads the system store by default.
- `build.sh` splits the file into one certificate per file on the Mac: `update-ca-certificates` skips the hash link of a multi-certificate file, `keytool` imports only the first certificate of a file, and a Keychain export can hold several. The split keeps only certificate blocks, so a private key in the same file never reaches the build.
- The closing banner is printed at the end of Main, not from a trap: D-06 asks for it "after they finish". When a build fails, `set -e` stops the script and only the opening banner is in the log.
- `/etc/sbx/extra-ca.pem` is not on the tool-versions line (D-07); it is the marker the deferred sandbox doctor can read later.
- Work stays on the current branch. That branch sits on an older main (before the retirement merge); `build.sh`, `base/Dockerfile`, `tests/guard/supply-chain.sh` and `README.md` are the same there as on origin/main, which Task 1's precondition checks. Each task commit holds only its code paths, so plan 03 can cherry-pick them onto a clean branch cut from origin/main.
- Reversibility: `SBX_CA_CERT` is rated costly (a rename means editing the shell profile on both Macs and the README); the rest is reversible.

Edge coverage: the spec-less probe fallback was skipped, because the phase has no requirement IDs to probe (visible skip). The edges come from CONTEXT.md and RESEARCH.md instead: unset and empty (Task 1), multi-certificate file with junk and a key (Task 1), every bad input of D-02 (Task 3).
