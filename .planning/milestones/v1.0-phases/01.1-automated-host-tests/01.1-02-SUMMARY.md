## Decisions Made

- **Coexistence baseline handling.** It reads `logs/old-containers.before`, writes only `logs/old-containers.after`, compares with `cmp -s`, and on a difference prints both snapshots plus "if you started or stopped a cc_ container during the run, re-run". With no baseline it checks git alone and the PASS text says "git only; no baseline".
- **Coexistence git call uses `--untracked-files=all`.** Without it, a new file under `ClaudeCode/` shows only as `?? ClaudeCode/`, which hides the path. Found when the self-test's dirty-folder case did not show the file name.
- **H-08 first half gates the second.** If the marker never reaches the history file while the first shell is open (10 s poll), the check fails with "before the recreate" and does not take the sandbox down. A second FAIL text says "after the recreate" when the fresh shell lacks the marker.
- **H-10 restart note.** A failed final `compose_up` is appended to whichever line is printed, and a would-be PASS becomes a FAIL, so a green H-10 always means the real sandbox is back.
- **No Co-Authored-By trailer** on the six commits, following the user's saved rule over the dispatch note (same call as plan 01).

## Host-side git lines in H-06 (acceptance criterion)

The only host-side git call in `tests/host/h06-git-and-identity.sh` is line 14, which carries both guards on the same command:

```
14:GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1 git init -q "$RUN/hosttest"
```

All other `git` lines are `in_container git ...` calls, comments, or message text. The self-test proves it with a fake `HOME` whose `.gitconfig` sets `init.templateDir`: the template marker never appears in the new repo, and the `.gitconfig` is byte-identical afterwards.

## Things the Mac run should double check

- **H-08 history text.** The fresh shell is fed `history` and `exit` on a non-tty `docker exec -i ... bash -i`; the check counts lines containing the marker in its stdout. If bash on the Mac's image prints `history` differently (for example nothing, because a non-tty shell skips reading the history file), H-08 fails in its second half. The history file on the host is the other evidence and is included in the FAIL detail.
- **H-08 background pipeline.** The held-open shell sleeps 25 s then ends; its output is fully redirected to `/dev/null`. The fake cannot show whether `docker exec -i` exits with the container teardown.
- **H-09 mounts template.** It uses `{{.Type}} {{.Destination}} {{.Source}}{{println}}`. If Docker rejects `{{println}}` with no argument, the check reports "expected exactly one mount; got 0" with the Docker error text in the detail.
- **H-09 Source form.** Compared by last path component only; the actual Source is printed on failure so the first Mac run shows the real form.
- **H-10 real outcome.** The likely Mac result is the second line (Compose creating the folder); that FAIL is a correct report and the fix is the env_file change in SANDBOX.md, which needs the user's approval and is outside this plan.
- **H-11 timing.** The self-test has no case for a 10 s or longer stop (it would need a real 10 s sleep); the threshold logic is a single comparison.
- **H-06 and Docker Desktop.** `git init` on the host needs git 2.32 or newer for `GIT_CONFIG_GLOBAL` to be honored; the Apple git that ships with current macOS is newer than that.
