## Pattern Assignments

### `tests/host/run-all.sh` (runner, batch)

**Analog:** `tests/guard.sh`

**Header and strictness** (guard.sh lines 1-10). Copy the comment-header style, `set -u` only (no `set -e`: checks must report and continue), and the cd line:
```bash
#!/usr/bin/env bash
# Guard: a few rules the sandbox files must never break.
# - Reads the files only. Builds nothing, runs nothing; no Docker needed.
# ...
# - Usage, from anywhere: bash tests/guard.sh   (exit 0 = all rules hold)
set -u
cd "$(dirname "$0")/.." || exit 1
```
For `run-all.sh` the header should say: unattended, builds images, creates a throwaway sandbox, never deletes anything, exit 0 = all pass. Use `cd "$(dirname "$0")/../.."` since it lives one level deeper (or resolve `REPO_DIR` via `lib.sh`).

**Runner loop and tally** (guard.sh lines 99-124):
```bash
FAILS=0
for rule in \
  no_compromised_gsd_package \
  ...
  old_layout_untouched
do
  if "$rule"; then
    echo "PASS: $rule"
  else
    echo "FAIL: $rule"
    FAILS=$((FAILS + 1))
  fi
done

if [ "$FAILS" -eq 0 ]; then
  echo "All rules hold."
  exit 0
fi
echo "$FAILS rule(s) broken."
exit 1
```
Adapt: loop over an id list in the order of the `# Depends on:` headers (whitespace-separated strings, not arrays; bash 3.2 plus `set -u`), run each check as `bash "$dir/$script"`, count PASS/FAIL/NOT RUN, `exit 1` if any FAIL. Order from RESEARCH "Runner order": fatal setup, then H-02 H-03 H-12 (no sandbox), `up`, then H-01 H-04 H-05 H-06 H-13 (keep going), then chain H-08 H-11 H-09 H-10 (stop at first failure), then Coexistence always, then summary. Install `trap print_next_block EXIT` and `trap 'exit 130' INT TERM` (RESEARCH Pattern 6). Per the project convention, add blank lines around every `if`/`for`/`while` and braces/`then`...`fi` always (guard.sh itself is looser; follow code-conventions.md for new files).

### `tests/host/lib.sh` (utility, sourced)

**Analog:** `tests/guard.sh` helpers section.

**Helper style** (guard.sh lines 25-36): comment line gives the signature and truth meaning, then a small named function:
```bash
# nowhere_matches REGEX FILE...: true if no line matches; prints the offending lines.
nowhere_matches() {
  local regex=$1; shift
  ...
}

# has_line FILE LINE: true if FILE has a line exactly equal to LINE.
has_line() { grep -Fxq -- "$2" "$1"; }
```
`lib.sh` is sourced, never executed, and must not set `set -u` or `cd` on its own beyond what `host_init` does. Functions to provide (names are discretionary): `host_init`, `resolve_run_dir`, `assert_test_sandbox`, `require_test_sandbox`, `in_container`, `pass`, `fail`, `expected_arch`, `claude_pin`, `snapshot_old_containers`, `run_timeout`, `remove_leftover_test_container`, `print_next_block`. Take bodies from RESEARCH.md:
- `host_init` (Pattern 1): unset `COMPOSE_PROJECT_NAME COMPOSE_FILE COMPOSE_PROFILES COMPOSE_PATH_SEPARATOR`, hard-set `SBX_NAME=hosttest`, `CONTAINER=sbx-hosttest`, never read ambient `SBX_DIR`.
- `assert_test_sandbox` (Pattern 2): label `sbx.name=hosttest` and mount source ending in the run folder name, via `docker container inspect --format`.
- `pass`/`fail` (Pattern 5): `PASS: <ID> <text>` / `FAIL: <ID> <text>` plus indented detail lines. This matches guard.sh's `PASS:`/`FAIL:` prefix (lines 112-114).
- `run_timeout` (Pattern 4), `expected_arch`, `claude_pin`, `snapshot_old_containers`, `remove_leftover_test_container` (RESEARCH "Code Examples").

**Compose invariant to honor** (compose.yml lines 7-9, 11, 42): every compose subcommand, including `down`, needs both variables:
```yaml
name: "sbx-${SBX_NAME:?SBX_NAME is required (lowercase letters, digits, - and _)}"
...
source: "${SBX_DIR:?SBX_DIR is required (absolute host path of the sandbox folder)}"
```
So a lib helper such as `compose_cmd()` should always run `SBX_NAME=hosttest SBX_DIR="$RUN" docker compose -f "$REPO_DIR/compose.yml" "$@" </dev/null`.

**Run folder** (D-05): `mktemp -d "${TMPDIR:-/tmp}/sbx-hosttest-$(date +%Y%m%d-%H%M%S).XXXXXX"` (strip a trailing `/` from `TMPDIR`; Xs last), then `cd ... && pwd -P`; create `hosttest/`, `state/`, `logs/` inside it (entrypoint requires both folders, base/sbx-entrypoint lines 32-33).

### Check scripts `tests/host/h*.sh` and `coexistence.sh` (test, request-response)

**Analog:** RESEARCH "Check script shape" for form; `tests/host-checklist.md` for each check's command and pass condition. The shape:
```bash
#!/usr/bin/env bash
# H-04: the container runs as the non-root sandbox user (uid 1000).
# Depends on: nothing
# Needs: test sandbox running
. "$(dirname "$0")/lib.sh"
host_init
require_test_sandbox H-04 || exit 1

output=$(in_container id)

if [[ "$output" == "uid=1000(sandbox) gid=1000(sandbox)"* ]]; then
  pass H-04 "container user is uid=1000(sandbox)"
  exit 0
fi

fail H-04 "expected uid=1000(sandbox) gid=1000(sandbox)" "got: $output"
exit 1
```
Rules for every check: one `PASS:`/`FAIL:` line carrying its ID, exit 0/1, a `# Depends on:` header line, no `read`, no `-it`, `</dev/null` on docker calls, host-side commands BSD/bash 3.2 safe.

## Shared Patterns

### Script style
**Source:** `tests/guard.sh` lines 1-10, 25-36
**Apply to:** every new `.sh`. Shebang `#!/usr/bin/env bash`, comment header with bullet lines (what it reads or touches, usage, exit code), `set -u` (never `set -e` in runner or checks), `cd "$(dirname "$0")/.." || exit 1`, named helper functions with a one-line signature comment, `PASS:`/`FAIL:` output prefix. New files additionally follow code-conventions.md (braces, blank lines around control flow, full variable names, `...List`/`...Map` suffixes, no planning IDs in comments, ASCII only).

### Never delete, only touch the test container
**Source:** RESEARCH Patterns 1 and 2; compose.yml line 10 ("Never ask down to remove volumes")
**Apply to:** `lib.sh`, `run-all.sh`, all checks and helpers. No `rm`, `rmdir`, `docker rm/rmi/prune`, no `down -v`. Container removal only via `compose down` after `assert_test_sandbox`. Cleanup is printed text.

### Ambient environment isolation
**Source:** RESEARCH Pattern 1
**Apply to:** `host_init`, called first in every script. Hard-set `SBX_NAME=hosttest`; unset `COMPOSE_*`; derive `SBX_DIR` only from `SBXTEST_DIR` or the test container's mount.

### bash 3.2 and BSD portability
**Source:** RESEARCH Pitfall 2; memory note on BSD-portable shell
**Apply to:** all host-side code. No `declare -A`, `mapfile`, `sed -i`, `grep -P`, `readlink -f`, `date -d`, host `stat -c`, `timeout`, `jq`, `echo -e`; no arrays under `set -u`; compare `wc -l` numerically. `stat -c` and GNU tools are fine only inside `docker exec`.

### Unattended contract
**Source:** context D-01 and RESEARCH Pattern 4
**Apply to:** everything outside `manual/`. No `read`, no `-it`/`-t`; `</dev/null` on docker calls; `run_timeout` only around `compose up --wait` and the builds if bounded.

### Prose and printed text
**Apply to:** all comments, printed messages, Markdown. No em/en dashes, no ASCII `--` as punctuation (CLI flags like `--no-cache`, `--wait` are fine); punctuation outside closing quotes; no `D-xx`, `HT-xx`, `Phase 1.1`, `.planning` in committed scripts. Check IDs `H-00..H-13` are allowed.
