## Phase Goal

ROADMAP.md Phase 01.3 goal (verbatim): "Every shell script in the repo follows the bundle's script layout rule: an 80-column banner before each logical section, longer sections moved into functions, and a `Main / Entry Point` banner over a short list of calls at the end. Behaviour does not change. From the PR #9 review."

Success criterion 4 (verbatim): "`base/sbx-entrypoint` stops the start with `[sbx] ERROR` when a start hook exists but is not executable, instead of skipping it (review WR-04; accepted risk AR-01 in `01.2-SECURITY.md`), with a self-test case."

Planning notes:
- Spec-less probe fallback skipped: the phase has no requirement IDs to probe (visible skip).
- Reversibility: rated reversible, no checkpoint. The new rule (every file in the hook folder must be an executable hook) is one line to undo, and the user locked it in D-11. Stopping at the first non-executable file, after earlier hooks ran, matches D-11's "like a failing hook".
- Test seam: a source guard around Main (Main runs only when the file is executed), so a test can source the file and call run_start_hooks against a fixture folder. No environment override of the hook folder is added: a test-only knob in a root-owned start script is avoidable, and an override alone would not help because the script stops at the mount check first.
- The new self-test is its own file; adding cases to tests/bundle-selftest.sh would change that script's output, which D-10 says must stay identical.
- Out of scope (Phase 1.5): the project-folder check that cannot fire under compose (review finding 01 WR-01) stays exactly as it is. Do not remove or change it.
- Closes the accepted residual AR-01 (threat T-01.2-02 of the previous phase).

| image layers -> /etc/sbx/start.d | root-owned, outside the mount; agent images add hooks there at build time |
