## Phase Goal

ROADMAP.md Phase 01.3 goal (verbatim): "Every shell script in the repo follows the bundle's script layout rule: an 80-column banner before each logical section, longer sections moved into functions, and a `Main / Entry Point` banner over a short list of calls at the end. Behaviour does not change. From the PR #9 review."

Planning notes:
- Spec-less probe fallback skipped: the phase has no requirement IDs to probe (visible skip).
- No one-way decisions; no reversibility checkpoint.
- Out of scope (Phase 1.5): the flaky H-09 volume compare and run_timeout not stopping a shell function. Keep H-09's volume logic and H-10's run_timeout call exactly as they are.
- Library rule applied here (D-03 with D-08): a piece moves to a library when three or more scripts use it, or when two scripts carry byte-identical code and messages so a change must be made in both. restart_test_sandbox qualifies (H-08 and H-16 are identical). The sentinel loops of H-09 and H-11 do not (their messages differ: "after the rebuild" and "after the stop"), so they stay in their checks.

<objective>
Convert the chain of checks that stop and restart the sandbox (H-08, H-16, H-11, H-09, H-10) to the layout and the reporting pattern, and move their one shared piece, the restart, into lib-sandbox.sh.

Purpose: the chain is where a reordered call would change what the user sees (compose hints, the restart at the end of H-10); doing it as one plan keeps those orderings in one reviewer's view.
Output: restart_test_sandbox in lib-sandbox.sh; H-08, H-09, H-10, H-11 converted; H-16 uses the shared restart and stop_check.
</objective>
