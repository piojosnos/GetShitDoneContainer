From tests/host/lib-report.sh (plan 01): add_problem MESSAGE; report_result ID FAIL_SUMMARY PASS_TEXT (prints FAIL with the collected problems or PASS, empties the list, returns 1 or 0, never exits); stop_check ID SUMMARY [DETAIL...]; first_lines TEXT [COUNT]; info TEXT.
New in tests/host/manual/lib-manual.sh:
- failCount=0: the number of FAIL result lines printed so far.
- require_terminal: when stdin or stdout is not a terminal, prints "This helper needs a terminal. Run it directly, not through a pipe or a script." to stderr and exits 1 (byte-equal to today's inline check).
- run_claude [ARG]: with no argument runs docker exec -it -w /home/sandbox/workspace/hosttest "$CONTAINER" claude; with one argument the same plus that argument. Uses an if on the argument count instead of forwarding "$@", so no empty "$@" is ever expanded under set -u on bash 3.2.
- claude_logged_in TEXT: true when printf of TEXT piped into grep -Eq for '"loggedIn":[[:space:]]*true' matches.
- count_result ID FAIL_SUMMARY PASS_TEXT: calls report_result "$1" "$2" "$3"; adds one to failCount when it returned 1.
- ask_judgment ID QUESTION PASS_TEXT FAIL_TEXT: local answer; printf '%s [y/N] ' QUESTION; read -r answer; any answer other than y or Y adds the problem "answer: ${answer:-<none>}"; then count_result ID FAIL_TEXT PASS_TEXT.
- exit_with_result: exit 1 when failCount is above 0, else exit 0.
The fake docker in harness/manual.sh matches the exact argument strings "exec -it -w <dir> sbx-hosttest claude", "... claude --continue" and "... claude doctor", so run_claude must produce exactly these.
Conventions for every file this plan touches (.claude/CLAUDE.md, ~/.claude/code-conventions.md): braces always; a blank line before and after every if, for, while and case block (else chains stay attached); full variable names (only i, j, k and e are short); ASCII only; no dash used as punctuation in comments (no em or en dash, no spaced double hyphen); no planning or review IDs in source (no D-NN, WR-NN, AR-NN, T-NN, phase numbers, .planning paths); no comment about what the code used to do; host scripts stay portable to macOS bash 3.2 and BSD tools.
</interfaces>
