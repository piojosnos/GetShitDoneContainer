Planning notes:
- Spec-less probe fallback skipped (no requirement IDs; visible skip).
- compose.yml passes `SBX_NAME: "${SBX_NAME}"` in `environment:`. Compose lowercases only the top-level project name, so the entrypoint sees the value exactly as typed (checked in compose.yml at ebfa086, line 27). H-21 still uses plain docker run: it sets the value directly and does not depend on Compose.
- Why the check sits right after check_workspace_mount: the name becomes a path (`$ws/$SBX_NAME`) in the very next step, so a name such as `../x` must be refused before any folder is looked at. A plain docker run without a mount still fails first on the mount check, so H-12 is unchanged.
- Locale: the image sets LANG=C.UTF-8 and the self-test machine may use another locale. `local LC_ALL=C` inside the check makes `[a-z]` the 26 ASCII letters everywhere.
- Task 2 is not a red/green pair: the fix and its red are Task 1. H-21 is the real-Docker proof of that fix inside run-all.sh (D-11), as H-20 was for the mistyped name. Its self-test proves it can fail (FAKE_ENTRY_NAME_CHECK_OFF=1 and FAKE_OFFLINE_FAIL=1). Its commit must not be listed as a red commit in the SUMMARY.
- Task 2 touches eight files because the guard ties a new host check to its run list, its self-test group, its checklist row and the runner counts in one step (same reason as plan 09).
- host_init exports SBX_NAME=hosttest, so the fake must give the entrypoint copy only the run's own `-e` values (a clean environment), as a real container gets.
- Mac-only assumption for the final run (M3): `docker run -e SBX_NAME=HostTest` reaches the real entrypoint unchanged and its [sbx] ERROR line appears in the run's output (H-21).
- Reversibility: a check in the start library and one line in the entrypoint; reversible.
