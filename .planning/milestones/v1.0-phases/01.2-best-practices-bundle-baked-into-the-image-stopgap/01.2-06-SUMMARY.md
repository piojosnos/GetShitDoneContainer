# Phase 01.2 Plan 06: Fake API proof of path-scoped loading and managed deny Summary

**A 130-line scripted fake Anthropic API (node core only) proves, against the real Claude 2.1.285 with no login and no network, that shell.md loads only after a .sh read and that the managed deny holds under bypassPermissions; H-18 repeats the proof inside the real image as a droppable last check of the sandbox stage.**

## Accomplishments

- `tests/host/support/fake-claude-api.js` answers the streaming and non-streaming requests Claude sends, replies with one scripted tool call per step, logs `step=<n> always=<yes|no> scoped=<yes|no>` per main-loop request, and exits by itself after 120 seconds.
- `tests/bundle-selftest.sh` gained two sections behind the pinned-Claude gate. Scope: step 0 has the always-on rule and not the scoped one; a later step has the scoped one after the scripted Read of `h18/deep/probe.sh`. Deny: with the managed rules re-rooted into the scratch config's `settings.json`, the project file ends as "h18 control after", the synced rule equals the repo file, and neither planted file exists.
- The deny assertions are not vacuous: the same script without the settings file edits the control file and plants the file in `rules/`.
- `tests/host/h18-scope-and-deny.sh` runs the same scripts inside the test container with `run_timeout 120 docker exec`, and is the last entry of `sandboxCheckList`, so its failure or removal leaves every other check running and counted.
- `tests/host-selftest.sh` has a fake docker branch for the H-18 exec and the knobs `FAKE_SCOPE_EAGER`, `FAKE_DENY_BROKEN`, `FAKE_H18_TOOLS_OFF`. The healthy runner now prints 19 PASS lines; the failing-id case reads "18 passed, 1 failed".

## Decisions Made

- The research protocol needed no change at 2.1.285 (no extra request type), so there is nothing to record about server adjustments.
- Rule and planted-file checks are skipped when the control file shows the tools never ran, so a dead harness cannot read as a holding deny.
- The H-18 failure messages carry the scope log and the head of the run output, so a Mac failure points at the image or the harness without a second run.
