<objective>
Close the start-hook hole found in the phase 01.3 code review (WR-01, plus IN-04 for the Dockerfile comment): the entrypoint silently skips a dangling link, a fifo or a socket in /etc/sbx/start.d, which can start a half-configured sandbox with exit 0. After this plan, only folders (and the unmatched glob of an empty folder) are skipped; every other entry must be an executable regular file. The rule is proved on Linux by tests/entrypoint-selftest.sh and on the Mac against the real image by H-17, which tests/host/run-all.sh already runs.

Purpose: the start hook folder fails closed, so an image that lost its hook (or holds junk in that folder) never starts a sandbox silently; the docs state a rule the code really enforces.
Output: fixed run_start_hooks, two new self-test cases, two new H-17 real-image containers with a matching fake docker response and self-test assertions, and matching wording in SANDBOX.md, base/Dockerfile and tests/host-checklist.md.
</objective>

Current behaviour this plan changes (base/sbx-entrypoint, run_start_hooks, lines 72-90):
- Loops `for hook in "$hookDir"/*`; skips every entry where `[ ! -f "$hook" ]` (this is the hole: a dangling link, a fifo, a socket are skipped silently).
- Then `[ ! -x ]` prints `[sbx] ERROR: start hook $hook is not executable; the container was not started.` to stderr and exits 1.
- Then runs the hook; on failure prints `[sbx] ERROR: start hook $hook failed; the container was not started.` and exits 1.
- Main is behind `if [ "${BASH_SOURCE[0]}" = "$0" ]`, so sourcing the file runs nothing; tests set `hookDir` after sourcing, in a subshell.

Reporting API for host checks (tests/host/lib-report.sh): `add_problem MESSAGE`, `report_check ID FAIL_SUMMARY PASS_TEXT`, `stop_check ID SUMMARY [DETAIL...]`, `first_lines TEXT [COUNT]`.

Fake docker in tests/host-selftest.sh (heredoc `<<'SHIM'`, around lines 228-265): the `run` branch for `*"--network none"*` handles H-17 today. It parses every `type=bind,source=*` argument into one `mountSource` (the LAST bind mount wins), runs the real `claude/start.d/10-best-practices` into `$mountSource/state/claude`, then runs the last argument with `sh -c`. Knobs: `FAKE_OFFLINE_FAIL`, `FAKE_HOOK_IGNORED` (only for runs with `CLAUDE_CONFIG_DIR=/proc/`). `FAKE_REPO` is the repo root. With an extra hook-folder mount and no change, the fake would treat the hook folder as the workspace and run the command, so H-17 would fail in the self-test: the fake MUST change.
