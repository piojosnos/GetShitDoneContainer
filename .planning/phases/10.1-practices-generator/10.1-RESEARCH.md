## User Constraints (from CONTEXT.md)

### Locked Decisions

### The pattern: masters, model, templates per agent
- **D-01:** Agents read rules in different formats (Claude: `.md` with `paths:`; Cursor: `.mdc` with `globs:` and `alwaysApply:`; OpenCode, per Phase 10.2: likely `AGENTS.md` or an `instructions` list). Skills share one format (`SKILL.md` with `name` and `description`) but still go through the same pipeline. So the best-practices repo has masters plus scope metadata, and renders them per agent.
- **D-02:** The pipeline is: a reader parses every master into a typed model (for example `Rule(name, scope, description, body)` and `Skill(name, description, body, extra files)`); a small per-agent profile says where each output goes and how it is named (extension, folder, one file per rule or one combined file); one Jinja template per agent and kind (for example `templates/cursor/rule.mdc.j2`) renders the model. Differences between agents live in the templates, not in Python string building. Jinja is pinned with uv in the best-practices repo (a new `pyproject.toml`). **Reversibility:** costly: the templates and the reader are the whole mechanism.
- **D-03:** The master format is picked on merit, not because Claude's format works today. Research compares Claude `.md` + `paths:`, Cursor `.mdc`, an `AGENTS.md` style and plain `.md` with a separate manifest, against these criteria, and brings the pick back to the user before planning:
  1. Expresses every scope we use: "always" and "only for these file globs". Cursor's "agent picks it by description" mode is not required.
  2. Renders to every target (Claude, Cursor, OpenCode, the next agent) without loss.
  3. Plain and readable: normal Markdown, renders on GitHub, easy to edit from any agent's sandbox.
  4. Stable: a documented format likely to last, or an emerging cross-agent standard.
  5. Tie-breaker only: at least one agent can use it as is.

  No invented format for its own sake; leaning towards plain `.md` with a small frontmatter block. If the pick is not the current Claude format, converting the 13 rule masters is part of this phase. **Reversibility:** costly: every master and every template follow the format.
- **D-04:** No Jinja inside master bodies, at least at first. Masters stay plain Markdown; only the templates wrap them. Placeholders such as `{{ config_dir }}` in rule text are rejected for now: they turn masters into templates and break code samples that contain `{{`. Revisit only if agent-neutral wording proves insufficient.
- **D-05:** The generator walks the two shallow master folders with a plain sorted `rglob`. No visitor-pattern traverser: `base/selfcheck/tree_walk.py` lives in the sandbox repo's image and cannot be imported here, and copying it would make a second copy to maintain. Adopt the visitor pattern (as in the user's `util-file-traverser`) only if the generator grows several different walks.

### Output layout
- **D-06:** Layout of the best-practices repo:
  ```
  best-practices/
    rules/              masters (paths unchanged, so history stays)
    skills/             masters
    templates/<agent>/  Jinja templates per agent
    generated/          never edited by hand

- **D-07:** Everything is generated, skills included, even where Claude's output equals the master. One plain rule for agents and humans: agents only ever see `generated/`.
- **D-08:** Each `generated/<agent>/` mirrors that agent's config directory (`generated/cursor/` has the shape of `~/.cursor/`), so the Phase 10.1.1 linker stays agent-neutral.
- **D-09:** The generated output is committed (the "commit generated code the build needs" rule), so a sandbox only links it and never runs the generator.

## Summary

The best-practices repo is tiny and clean: 13 rule masters in `rules/`, 2 skill masters in `skills/`, a README and a license, no code, no `pyproject.toml`, no tests. `main` equals `origin/main` (`eae35ce`) [VERIFIED: `git rev-list --left-right --count main...origin/main` printed `0	0`]. Everything this phase adds is new: a `pyproject.toml` with `uv.lock`, a Python package, one Jinja template set per agent, a committed `generated/` tree, pytest tests, the `update-practice` skill, and edits to five masters.

The mechanics work as designed. I built a scratch project with `jinja2==3.1.6`, `pyyaml==6.0.3` and `pytest==9.2.0`, locked and synced it with uv, parsed all 13 real rule masters and both real skill masters, and rendered them through Claude and Cursor template probes. Output is byte-stable (one SHA-256 over the whole rendered set), master bodies containing `{{` and `{% if x %}` come out literal, and a shared `{% include "_header.j2" %}` partial works. The only template quirk is Cursor's `globs` line, which is not valid YAML (`yaml.safe_load("globs: **/*.java,**/*.xml")` raised `ScannerError`), so the Cursor template must be tested as text, not parsed with a YAML library.

The master format question (D-03) has a clear answer on the five criteria: keep the current Claude format, plain `.md` with an optional `paths:` list in a small frontmatter block. It wins on merit (criteria 1, 3 and 4), and no rule master needs converting. It also has a transition benefit worth stating: until Phase 10.1.1 lands, existing sandboxes still link `rules/` directly (`state/claude/rules -> ../../best-practices/rules` today [VERIFIED: `ls -la` of the dev sandbox state directory]), so masters in any other format would break every running Claude sandbox the moment this PR merges. The pick must go back to the user before planning (D-03); the one-paragraph version is at the end of this file.

**Primary recommendation:** Keep Claude's `.md` + `paths:` as the master dialect (list form only, strict keys, no commas in globs); build `practices/` as a pure `render_all(repo) -> {relative_path: bytes}` function plus a writer and a byte-comparing drift check; pin `jinja2==3.1.6`, `pyyaml==6.0.3`, `pytest==9.2.0`; run everything with `uv run --locked`.

## Master Format Comparison (D-03)

Criteria numbers are the ones in D-03.

| Candidate | 1 Scopes (always, globs) | 2 Renders to all targets | 3 Plain Markdown, GitHub, easy edits | 4 Stable, documented | 5 Used as is by an agent |
|-----------|--------------------------|--------------------------|--------------------------------------|----------------------|--------------------------|
| **Claude `.md` + `paths:`** | Yes. No `paths` = always; `paths` = glob list | Cursor: lossless (`paths` -> `globs`, `alwaysApply` derived). Claude: identity. AGENTS.md / OpenCode: always-rules concatenate; scoped rules cannot be enforced there (target limit, see below) | Yes. Normal Markdown; GitHub shows the frontmatter as a small table | Documented by Claude Code; `paths` is the only field read, others ignored | Claude, unchanged |
| Cursor `.mdc` | Yes (`alwaysApply` + `globs`), plus modes we do not use | To Claude: needs a parser for a non-YAML `globs` line; otherwise fine | No. `.mdc` is not Markdown to GitHub or most editors; the `globs` line is not valid YAML (probe: `ScannerError`) so no standard parser reads it | Weak. Forum thread "Documentation Page - Schema undocumented for rules"; the comma format was only confirmed by staff on 2025-12-16 | Cursor only |
| `AGENTS.md` style | No. Plain Markdown, no frontmatter, no glob scoping; nesting maps to directories, not globs | Good as a target (Cursor CLI, OpenCode, Claude read it) | Yes | Yes. Stewarded by the Agentic AI Foundation under the Linux Foundation | Several agents, but cannot carry our scopes |
| Plain `.md` + separate manifest | Yes, in a second file | Yes | Bodies yes; but scope lives apart from the rule, so two files per edit and a manifest that can name a rule that no longer exists | Invented schema | No agent, so criterion 5 fails entirely |

**Why the lossless claim in criterion 2 is honest.** OpenCode documents no frontmatter and no per-glob scoping: "No frontmatter support or per-glob scoping mechanisms are mentioned" in its rules page, which loads `AGENTS.md` files plus an `instructions` list of paths and globs of files [CITED: opencode.ai/docs/rules]. That is a limit of the target. No master format can make OpenCode enforce a glob, so the template decides what to do with a scoped rule (for example a heading "Applies to files matching ..."). The master keeps the scope; nothing is lost at the source.

**Recommendation: Claude's format, constrained to a strict dialect.**

- Frontmatter is optional. No frontmatter means "always". The only key is `paths`, a YAML list of strings. Claude also accepts a comma-separated string, but masters use the list form only [CITED: code.claude.com/docs/en/memory, "Rule frontmatter reference": "Accepts a YAML list or a comma-separated string"].
- The reader fails on any unknown key. A typo such as `path:` would otherwise silently turn a scoped rule into an always-loaded one.
- The reader fails on a `,` inside a `paths` entry. Cursor splits `globs` on commas, so a brace glob such as `**/*.{ts,tsx}` (valid for Claude) would render wrongly for Cursor.
- The 13 masters need no conversion. Parsed this session: 6 have `paths`, 7 have none (`freemarker.md` `['**/*.ftl']`, `java.md` `['**/*.java']`, `python.md` `['**/*.py']`, `shell.md` `['**/*.sh']`, `spring-boot.md` `['**/*.java', '**/application*.properties', '**/application*.yml']`, `testing.md` `['**/*Test.java', '**/*Tests.java']`; `architecture`, `best-practices`, `coding-general`, `communication`, `documentation`, `git-workflow`, `prose-style` print `{}`) [VERIFIED: probe run over the real files].
- Skill masters use the Agent Skills format: `SKILL.md` with `name` and `description`. Both existing skills parse to exactly `['name', 'description']`, descriptions of 421 and 428 characters (spec maximum 1024) [VERIFIED: probe; CITED: agentskills.io/specification]. Claude, Cursor and OpenCode all read this file.
- Transition benefit: until 10.1.1, running sandboxes read `rules/` directly, so keeping the Claude dialect means this PR cannot break them.

## Target Formats (what each agent reads)

### Claude Code rules
- User-level rules live in `~/.claude/rules/` and apply to every project; a rule without `paths` loads at launch [CITED: code.claude.com/docs/en/memory, "User-level rules" and "Rules without `paths` frontmatter are loaded at launch"].
- `paths` takes a YAML list of globs: `paths:` then `  - "src/api/**/*.ts"`. Brace expansion is supported. Patterns are relative to the session's primary working directory for user-level rules [CITED: same page].
- "`paths` is the only field Claude Code reads from a rule; any other field is ignored without an error." Claude removes the frontmatter before loading the rule [CITED: same page].
- If the YAML does not parse, Claude ignores the frontmatter and loads the rule as if it had no `paths` [CITED: same page]. A broken frontmatter therefore silently widens a scoped rule; the reader's strictness (and a test that re-parses every Claude output with `yaml.safe_load`) guards this.
- Block-level HTML comments in CLAUDE.md files are stripped before injection [CITED: same page]. The page says this for CLAUDE.md only; for rule files it is `[ASSUMED]` (cost if wrong: a few tokens per rule).

### Cursor rules
- Project rules are `.mdc` in `.cursor/rules`; "A plain `.md` file in `.cursor/rules` is ignored" [CITED: cursor.com/docs/context/rules].
- Frontmatter fields: `alwaysApply`, `description`, `globs`. `alwaysApply: true` means "Always included. Globs and description are ignored."; `alwaysApply: false` with `globs` means auto-attached to matching files [CITED: same page].
- `globs` format: the docs show comma-separated strings (example `docs/**/*.md, docs/**/*.mdx`). A Cursor staff reply (2025-12-16) says: "The format is frontmatter with globs being comma separated values, no brackets or quotes." [CITED: forum.cursor.com/t/rule-frontmatter-format/146274]. So render `globs: **/*.java, **/application*.properties` unquoted. That line is not valid YAML, so never run a YAML parser over Cursor output.
- A global `~/.cursor/rules` is the open risk: a Cursor staff reply (2026-07-02) says native support for `~/.cursor/rules` is "tracked, but there's no ETA", with workarounds (plugins, or a User Rule that reads the files); a forum thread on global rules for the CLI shows users unable to find a way; the CLI docs say it reads `AGENTS.md` and `CLAUDE.md` "at the project root (if present)" and `.cursor/rules` [CITED: forum.cursor.com/t/support-for-cursor-rules-for-global-mdc-rules/144819; forum.cursor.com/t/global-rules-with-cursor-cli/132240; cursor.com/docs/cli/using]. Phase 06.1 read the shipped CLI and found a home rules service reading `**/*.mdc` but did not run it (06.1-RESEARCH A3, MEDIUM to LOW). This is D-19's attended check in Phase 10.1.1; it does not change this phase, but it is why the profile should not hard-wire "one file per rule" as the only layout forever (see Open Question 2).

### Skills (all three agents)
- Agent Skills spec: `SKILL.md` with required `name` (1 to 64 characters, lowercase letters, digits and hyphens, no leading, trailing or doubled hyphen, must match the parent directory) and `description` (1 to 1024 characters); optional `license`, `compatibility`, `metadata`, `allowed-tools`; optional `scripts/`, `references/`, `assets/` and "any additional files or directories" [CITED: agentskills.io/specification].
- Claude: `~/.claude/skills/<skill-name>/SKILL.md`; a `<skill-name>` entry can be a symlink to a directory; `name` is optional there and defaults to the directory name [CITED: code.claude.com/docs/en/skills].
- Cursor: scans `~/.cursor/skills/`, `~/.agents/skills/` and (legacy) `~/.claude/skills/`; `name` "Must match the parent folder name" [CITED: cursor.com/docs/context/skills].
- OpenCode: `~/.config/opencode/skills`; the ID comes from the path, the `name` field is a display label [CITED: opencode.ai/docs/skills].
- So one skill format serves every target; the generator still renders it (D-07) so the output tree has one rule.

### OpenCode rules (Phase 10.2, for criterion 2 only)
- `AGENTS.md`, global at `~/.config/opencode/AGENTS.md`, plus an `instructions` list of paths and globs; falls back to `CLAUDE.md` when there is no `AGENTS.md` [CITED: opencode.ai/docs/rules]. A combined-file layout is what OpenCode needs; Cursor may need the same as the 10.1.1 fallback.

## Architecture Patterns

### System Architecture Diagram

```
  masters (edited by humans and agents)
  rules/*.md ----------------+            skills/<name>/SKILL.md (+ extra files)
   optional frontmatter:     |                         |
   paths: [globs]            v                         v
                       +-----------------------------------+
                       | reader.py                         |  fails closed:
                       | split frontmatter, yaml.safe_load |  unknown key, comma in glob,
                       | validate, normalise body          |  name != directory, bad YAML
                       +----------------+------------------+
                                        | typed model: list[Rule], list[Skill]
                                        v
   profiles.py  AGENT_PROFILE_LIST = [claude, cursor]
   (agent name, rule template, rule extension)
                                        |
                                        v
                       +-----------------------------------+      templates/
                       | render.py  render_all(repo_root)  |<---- _generated_header.j2
                       | one Jinja Environment, per agent  |      claude/rule.md.j2
                       | and kind template                 |      claude/skill.md.j2

### Pattern 1: Reader into a typed model
**What:** One function per master kind returns a frozen dataclass; a module-level `PracticesError` carries every failure. Sorted `rglob`, UTF-8, universal newlines (`Path.read_text` turns CRLF into LF).
**When:** always; the reader is the only place that touches master files.
```python
# Source: probe run this session; frontmatter split is plain string work, YAML via yaml.safe_load
from dataclasses import dataclass
from pathlib import Path

import yaml

ALLOWED_RULE_KEY_SET = {"paths"}


@dataclass(frozen=True)
class Rule:
    name: str
    master_path: str
    path_list: list[str]
    body: str


def read_rule(rules_dir: Path, master_file: Path, repo_root: Path) -> Rule:
    frontmatter, body = split_frontmatter(master_file.read_text(encoding="utf-8"), master_file)
    unknown_key_list = sorted(set(frontmatter) - ALLOWED_RULE_KEY_SET)

    if unknown_key_list:
        raise PracticesError(f"{master_file}: unknown frontmatter key {unknown_key_list[0]}")

    path_list = frontmatter.get("paths", [])
    check_path_list(path_list, master_file)

    return Rule(
        name=master_file.relative_to(rules_dir).with_suffix("").as_posix(),
        master_path=master_file.relative_to(repo_root).as_posix(),
        path_list=path_list,
        body=body.strip("\n"),
    )
```
`split_frontmatter` returns `({}, text)` when the text does not start with `---\n`; otherwise it cuts at the next `\n---\n`, loads the block with `yaml.safe_load`, requires a mapping (an empty block loads as `None`), and raises on anything else. `check_path_list` requires a list of non-empty strings with no `,` and no leading `/` surprises. Strip only newlines from the body, never spaces (two trailing spaces are a Markdown hard break).

### Pattern 3: One Jinja Environment, strict and byte-stable
```python
# Source: Jinja API docs (trim_blocks, lstrip_blocks, keep_trailing_newline, StrictUndefined,
# autoescape default False) and the probe output of this session
import json

import jinja2


def build_environment(templates_dir: Path) -> jinja2.Environment:
    environment = jinja2.Environment(
        loader=jinja2.FileSystemLoader(templates_dir),
        undefined=jinja2.StrictUndefined,
        keep_trailing_newline=True,
        trim_blocks=True,
        lstrip_blocks=True,
        autoescape=False,
    )
    environment.filters["yaml_str"] = _yaml_str

    return environment


def _yaml_str(text: str) -> str:
    return json.dumps(text, ensure_ascii=False)
```
`json.dumps(..., ensure_ascii=False)` yields a valid YAML double-quoted scalar and keeps `—` and quotes readable. Do not use Jinja's built-in `tojson`: it escapes `<`, `>`, `&` and `'` as `<` style sequences (valid, but unreadable in a committed file). `[ASSUMED]` for the `tojson` escaping detail (training knowledge); the `json.dumps` route needs no assumption.

### Pattern 4: Render to memory, then write or compare
`render_all(repo_root) -> dict[str, bytes]` returns `{"claude/rules/java.md": b"...", ...}` keyed by path relative to `generated/`, built in sorted order. Skill extra files are copied byte for byte (no header; a script or image cannot take a comment). Copy the executable bit: git tracks it, and sandbox edits leave scripts `644` on a macOS host (project memory `sandbox-edits-drop-exec-bit-on-mac`). No extra files exist in either skill master today [VERIFIED: `ls -la skills/*` shows only `SKILL.md`], so this is one small branch plus one test; the model field is `extra_file_list` of relative posix paths.
- `output.py`: delete `generated/` (guarded: the resolved path must be `<repo_root>/generated`), then write every entry, `Path.write_bytes`, creating directories. A removed master therefore removes its output.
- `check.py`: compute `render_all`, walk `generated/` sorted, compare the path sets and the bytes. Report missing files, extra files and changed files, with `difflib.unified_diff` for text. Exit 0 clean, 1 drift or a reader error, 2 usage (the sandbox repo's convention). A hand edit, a stale file and a deleted output all fail it (D-13).

### Anti-Patterns to Avoid
- **Parsing Cursor output with YAML:** the `globs` line is not YAML; test it as text.
- **Editing `generated/` in a fix:** always change the master and regenerate.
- **Jinja syntax inside a master:** D-04 stands. Note the rationale is narrower than "breaks `{{` samples": a body passed as a *value* is never re-evaluated, so `{{` in a code sample is safe today [CITED: jinja.palletsprojects.com API; VERIFIED: probe rendered body `code {{ config_dir }} {% if x %}` unchanged]. The real reason to keep it out is that placeholders would turn masters into templates; the decision is right, the "breaks code samples" argument is not needed.
- **A second copy of `tree_walk.py`:** D-05; two shallow folders need `sorted(rglob)`.
- **Passing the whole config or file system to templates:** pass only `rule`, `skill` and `master_path`; `StrictUndefined` then fails fast on a typo.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Frontmatter YAML | A regex or line parser for `paths:` lists | `yaml.safe_load` on the block between the fences | Quoting, folded and block scalars, lists; the master dialect will grow |
| File formats | Python f-strings that assemble `.mdc` or `SKILL.md` | Jinja templates (D-02) | Differences between agents belong in templates |
| Quoting a YAML string | Escaping by hand | `json.dumps(text, ensure_ascii=False)` as a filter | A JSON string is a valid YAML double-quoted scalar |
| Tree comparison | A custom diff walker | `render_all` map vs a sorted walk, `difflib.unified_diff` for the message | Standard library, deterministic |
| Test fixtures dir copying | Manual recursive copy | `shutil.copytree` into `tmp_path` | Rule: prefer a library helper over a hand-rolled loop |
| Environment and dependency management | A `requirements.txt` or a hand-made venv | `pyproject.toml` + `uv.lock` + `uv run --locked` | rules/python.md Project layout |

## Common Pitfalls

### Pitfall 1: A frontmatter typo widens a scoped rule
**What goes wrong:** `path:` instead of `paths:` is ignored by Claude (only `paths` is read, other fields ignored without an error), so a Java-only rule loads in every session. Broken YAML does the same.
**How to avoid:** reader rejects unknown keys and non-list `paths`; a test re-parses every Claude output with `yaml.safe_load` and asserts the `paths` list equals the master's.
**Warning signs:** a rule appearing in context for unrelated files.

### Pitfall 2: Cursor `globs` rendered as YAML
**What goes wrong:** quoted or bracketed globs are taken literally by Cursor (staff: "no brackets or quotes"), so the rule never attaches. A comma inside a glob (brace expansion) splits it.
**How to avoid:** Cursor template joins with `", "` unquoted; the reader rejects `,` in any master glob; a golden test pins the exact line. Whether Cursor trims the space after the comma is `[ASSUMED]`; the official docs example uses `, ` and the staff reply says comma separated values. Pin one form in a test so a change is deliberate.

### Pitfall 3: Non-deterministic or platform-dependent output
**What goes wrong:** `rglob` order differs between filesystems (the host is macOS); CRLF, a trailing newline, or Jinja swallowing the last newline makes the drift check flap.
**How to avoid:** sort every listing; read with `read_text(encoding="utf-8")`, write bytes you encoded yourself; `keep_trailing_newline=True` with a body stripped of trailing newlines and a template that ends in exactly one newline (probe confirmed output ends in a single `\n`); no timestamps, no absolute paths, no version stamps in headers; add `.gitattributes` with `generated/** linguist-generated` (GitHub collapses such files in PR diffs [CITED: docs.github.com customizing how changed files appear]) and `* text eol=lf` so a macOS checkout never rewrites line endings `[ASSUMED]` for the `eol=lf` effect.

### Pitfall 4: Stale output survives a removed master
**What goes wrong:** deleting `rules/x.md` leaves `generated/claude/rules/x.md`, and the linker keeps serving it.
**How to avoid:** the writer clears `generated/` before writing; the check compares path sets, not just file contents; a test removes a fixture master and expects drift, then expects the regenerated tree to lose the file.

### Pitfall 5: Transition window between this PR and Phase 10.1.1
**What goes wrong:** after merge, running sandboxes still link `rules/` and `skills/*` (masters), not `generated/`. The rewritten `best-practices.md` goes live in every Claude sandbox at once and mentions `generated/` and the `update-practice` skill; the new skill is linked by the existing linker (it links every non-hidden directory under `skills/`) but its commands need `uv` and network to run; Cursor sandboxes see nothing new until 10.1.1.
**How to avoid:** keep the Claude dialect in masters (no break); write the rewritten rule so it is correct both before and after the link move (it names the repo's layout, not the link targets); mention in the PR description that Cursor gains rules only with 10.1.1.

### Pitfall 6: A Linux `.venv` inside a clone the host also sees
**What goes wrong:** the best-practices clone sits in the sandbox directory, which the host also mounts. `uv run` creates `.venv` in the clone; a host-side `uv run` would try to reuse a Linux environment (the sandbox repo's own `pyproject.toml` comments warn of this for `.venv`).
**How to avoid:** `.gitignore` the `.venv/`; document that the generator is run in a sandbox; the `update-practice` skill runs it there. First `uv sync` needs PyPI access (through `UV_CACHE_DIR` in `state/cache` after the first run); behind a company proxy it needs the configured root certificate.

### Pitfall 7: `uv run` rewriting the lock
**What goes wrong:** a plain `uv run` updates `uv.lock` silently when `pyproject.toml` and the lock disagree, producing a surprise diff in the PR.
**How to avoid:** every documented command uses `uv run --locked ...`, which fails instead of rewriting.

### Pitfall 8: Writing the generator in the house style, forgetting the house rules
The user's rules apply to the new Python: banners of `#` plus 80 hyphens around sections, `Main / Entry Point` banner for modules with an entry, type hints on public functions, no docstrings unless asked, full variable names, `_list` and `_by_name_map` suffixes, blank lines around control flow, early returns, `pathlib`, ASCII-only comments, no planning IDs in code, no dashes as punctuation in comments and docs (rules/python.md, rules/coding-general.md, rules/prose-style.md, all read this session). Tests: pytest, `conftest.py` fixtures, real infrastructure over mocks, abstract fixture names (`rules/a.md`, `skills/a`).

### Drift check core
```python
def find_drift(repo_root: Path) -> list[str]:
    expected_by_path_map = render_all(repo_root)
    actual_by_path_map = read_output_tree(repo_root / "generated")
    drift_list: list[str] = []

    for relative_path in sorted(set(expected_by_path_map) | set(actual_by_path_map)):
        expected = expected_by_path_map.get(relative_path)
        actual = actual_by_path_map.get(relative_path)

        if expected is None:
            drift_list.append(f"extra file: generated/{relative_path}")
        elif actual is None:
            drift_list.append(f"missing file: generated/{relative_path}")
        elif expected != actual:
            drift_list.append(describe_change(relative_path, expected, actual))

    return drift_list
```
