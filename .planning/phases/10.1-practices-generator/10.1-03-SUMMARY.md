# Phase 10.1 Plan 03: Skills through the pipeline and a drift check that catches every difference Summary

**Skill masters (`merged`, `pr-reply`) now render through per-agent skill templates into committed `generated/<agent>/skills/<name>/`, extra files keep their bytes and exec bit, and `practices.check` fails on any hand edit, stale or deleted file, mode change or link.**

## Accomplishments

- `practices/reader.py` walks `skills/` with the same sorted, hidden-skipping, link-refusing walk as rules, and agrees with the sandbox linker's notion of a skill (a non-hidden folder). `read_skill` enforces the strict dialect; the name rule uses string methods only (no `re`).
- Two identical skill templates (one per agent, as the plan asks) render `name`, a JSON-quoted `description`, the generated header and the body. Output of `merged` is byte-identical between Claude and Cursor and its body equals the master body.
- `render_all` emits `<agent>/skills/<name>/SKILL.md` and each extra file as an `OutputFile` carrying the master's executable bit; keys stay sorted.
- `practices/check.py` reports `missing file:`, `extra file:`, `changed file:` (with a three-line-context unified diff for UTF-8 text) and `changed mode:`. `practices/output.py` refuses a linked or misplaced `generated/` and any link below it.
- 38 new tests: 17 skill reader tests (4 model and walk, 11 rejection rows, 2 more rejections), 9 skill output tests, 6 output tests, 6 added drift tests. The suite is 73 tests, all passing; `-k "reject or invalid"` selects 28, `test_check.py` holds 11.

## Decisions Made

- Refuse any skill key outside `name` and `description` rather than render without it; this matches the rule dialect from plan 02.
- A missing `skills/` folder fails the run, symmetric with `rules/`.
- `find_drift` entries are per file (multi-line for a changed text file) so the error count stays a file count.
- A whitespace-only description counts as empty (the plan names only "empty").

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Diff lines would have broken the differing-file count**
- **Found during:** Task 2 (design of the diff output)
- **Issue:** the plan says `main` prints everything `find_drift` returns, and the refusal message counts `len(drift_list)`. Appending the diff lines as separate list items would have turned "1 generated files differ" into a line count.
- **Fix:** one list entry per file; a changed text file's entry is the drift line joined with its diff lines. Printed output is exactly what the plan describes.
- **Files modified:** `practices/check.py`
- **Verification:** `tests/test_check.py#test_check_names_a_hand_edited_file` asserts both `+hand edit` on stdout and `1 generated files differ`.
- **Commit:** `b38f07a`

**2. [Rule 2 - Missing critical functionality] Whitespace-only description**
- **Found during:** Task 1
- **Issue:** a description of only spaces passes a bare length check but is useless to the agent that reads it.
- **Fix:** `_check_description` also refuses text that is empty after `strip()`; same message.
- **Files modified:** `practices/reader.py`
- **Commit:** `5ddcff5`
