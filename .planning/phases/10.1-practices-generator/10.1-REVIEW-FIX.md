### WR-03: `write_output` is not atomic

**Files modified:** `practices/output.py`, `tests/test_output.py`
**Commit:** aaeb881
**Applied fix:** test first: a map whose last entry clashes (a file `b1` and then `b1/c1.txt`) fails midway; the test asserts `generated/` and the repo folder listing are unchanged (it failed before). `write_output` builds the new tree in `tempfile.mkdtemp(dir=repo_dir)` beside `generated/`, then swaps with `os.replace`: the old tree moves aside, the new one moves in, and the old one is put back if the second move fails. The temp folder is removed in a `finally`. The link and resolve guards are unchanged. Design choice: rename-aside instead of the suggested `rmtree` then `replace`, because a failed `rmtree` would itself leave a half-deleted tree. A hard kill (SIGKILL) can still leave a hidden `.generated-*` folder in the repo root; it is untracked and holds no master data.

### IN-05: Frontmatter edge cases are accepted or mis-parsed silently

**Files modified:** `practices/reader.py`, `tests/test_reader.py`
**Commit:** 4aa1a67
**Applied fix:** test first (two duplicate-key cases and a BOM plus spaced-fence case all failed). A small `_UniqueKeyLoader(yaml.SafeLoader)` raises on a repeated key; the refusal reads "<master>: the frontmatter repeats the key 'paths'" and names the file. Decisions:
- BOM: accepted and stripped (masters are read as `utf-8-sig`), not refused. A BOM is invisible in editors and carries no meaning here; refusing would only confuse. The extra skill files stay byte for byte.
- Trailing whitespace on a fence line: accepted (`rstrip()`), not refused, for the same reason; a fence is the only thing on its line anyway.
- YAML 1.1 booleans: `disable-model-invocation: yes` is still read as true. The review fix did not list it, and the output is normalized to `true` or `false`, so no agent sees the `yes`.
