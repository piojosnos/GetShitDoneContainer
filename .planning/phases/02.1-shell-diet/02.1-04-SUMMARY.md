# Phase 2.1 Plan 04: Isolation read from docker inspect, guard cut to plain greps Summary

**New host check H-26 reads the sandbox's single bind mount, Privileged, CapDrop, CapAdd and SecurityOpt from docker inspect; the guard's isolation group shrinks from seven rules with awk parsers to two plain greps and a git diff.**

## Performance

- **Duration:** about 15 min
- **Completed:** 2026-10-15
- **Tasks:** 2
- **Files:** 5 changed across the two commits (none under .planning/ or .claude/)

## Accomplishments

- Task 1 (tracer): `tests/host/h26-isolation-by-inspect.sh` (mode 755, banner shape, `# Needs: test sandbox running`). `check_privileges` fails when Privileged is not `false`, CapDrop lacks `"ALL"`, CapAdd is neither `null` nor `[]`, or SecurityOpt lacks `no-new-privileges`, and then adds the raw `docker inspect gave:` line. `check_mounts` requires exactly the line `bind /home/sandbox/workspace`. It is last in `sandboxCheckList` of `tests/host/run-all.sh`, and `tests/host-checklist.md` now reads H-00..H-26 with an H-26 row. A smoke run with a stand-in `docker` gave PASS for a good line and FAIL naming `Privileged is not false` plus the raw line for `true`.
- Task 2: `tests/guard/isolation.sh` rewritten whole with two rules. `no_docker_socket_or_privileges` greps compose.yml for `docker.sock` and `privileged: true` and both Dockerfiles for `sudo`; `old_layout_untouched` is unchanged in code. The five parser rules (`no_other_mount_form`, `exactly_one_mount_and_not_over_home`, `runs_without_privileges`, `npm_builds_keep_their_cache_out_of_the_mount`, `images_leave_the_mount_point_empty`) are gone, and so is every awk in the file. In `sandbox-rules.sh`, `case_isolation_rules` became `case_isolation_rule` (clean copy passes; planted `privileged: true` fails and the line is named) and `case_state_and_cache_rules` became `case_state_folder_rule` without the npm cache and mount point cases.
