**Rule contract** (lib.sh `run_rules`, lines 99-117): a rule returns 0 or 1, prints indented detail lines (4 spaces) on failure, and `run_rules` prints `PASS: name` or `FAIL: name`. The D-02 missing-tool path must `echo "    shellcheck is not installed (it ships in sbx-base)"; return 1`. Sketch from RESEARCH.md:
```bash
shellcheck_passes() {
  local output

  if ! command -v shellcheck >/dev/null 2>&1; then
    echo "    shellcheck is not installed (it ships in sbx-base)"
    return 1
  fi

  output=$(shellcheck -S warning $SHELL_FILES 2>&1) && return 0
  printf '%s\n' "$output" | sed 's/^/    /'
  return 1
}
```
`hadolint_passes` is the same with `hadolint --config .hadolint.yaml $DOCKERFILES`. Pass `-S warning` on the command line (`severity=` in `.shellcheckrc` is ignored by 0.11.0); do not use `-x`. Follow user conventions: braces, blank lines around `if`.

## Shared Patterns

### D-11 comment banner (80 columns including `#`)
**Apply to:** every commented block in shell, Dockerfiles, `compose.yml`, the two config files.

Current banners are 82 wide (`# ` + 80 dashes) with long titles on one line. New rule lines are exactly `#` + space + 78 dashes = 80 characters. Shapes (from CONTEXT.md D-11):
```bash
# ------------------------------------------------------------------------------
# run_groups SUITE_DIR GROUP...: runs each group and counts its FAIL lines
# ------------------------------------------------------------------------------
# A group that crashes without a FAIL line counts as one failure.
# So a crash is never silent.
# ------------------------------------------------------------------------------
run_groups() {
```
No "why": title between two rules only. Title at most 80 columns, why at most two lines. File header: the script's purpose is the title, usage plus at most one other line below; see D-12. Dockerfile exception: `base/Dockerfile` line 1 `# check=skip=InvalidDefaultArgInFrom` stays first; the banner goes after it.

### Guard group skeleton
**Source:** `tests/guard/start.sh` lines 1-6 and 162-177, `tests/guard/lib.sh` `run_rules`.
**Apply to:** `linters.sh` and the surviving groups (`supply-chain.sh`, `start.sh`, `isolation.sh`).
Shebang, header, `set -u`, `. "$(dirname "$0")/lib.sh"`, rule functions returning 0/1 and printing 4-space-indented detail, then `require_no_arguments "$@" || exit 2; enter_repo_root || exit 1; run_rules ... || exit 1`.

### Search helper
**Source:** `tests/guard/lib.sh:28-58` `nowhere_matches REGEX FILE...`.
**Apply to:** all grep-based rules, for example `nowhere_matches 'docker\.sock|privileged:[[:space:]]*true' $COMPOSE`. Do not use `grep -E 'x\|y'` forms without running them through a real `bash script`; the interactive tool shell swaps in a different grep.

### Check reporting (host)
**Source:** `tests/host/lib-report.sh` (`add_problem`, `report_check ID "failure text" "pass text"`), `require_test_sandbox`, `in_container`.
**Apply to:** `h26`.

### Portability and conventions
Host-side code runs on stock macOS bash 3.2 with BSD tools (no `mapfile`, `declare -A`, `sed -i`, `readlink -f`); use `sed -E` with `#` delimiters. ASCII only, braces always, blank lines around control flow, full variable names, `fooList` collection suffixes, no planning IDs in comments.
