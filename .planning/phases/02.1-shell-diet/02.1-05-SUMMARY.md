## Accomplishments

- Task 1 (tracer): `installs_use_declared_pins` became `installs_use_pins`. Check A greps the npm install lines of both Dockerfiles, strips every quoted `NAME@${X_VERSION}` token with `sed -E` (`#` delimiter) and fails on any argument left over; check B refuses npx, uvx, npm exec, pip and uv installs. `no_pipe_to_shell_installers` now reads each `curl` or `wget` line with the next one (`grep -A1 | tr`), with `pipeRegex` and `substitutionRegex` byte for byte as before (compared against origin/main). `run_steps_of` is gone. The tracer verify passed end to end before expansion: nine supply-chain PASS lines, no awk in supply-chain.sh or lib.sh, planted unpinned, literal-version and npx installs fail `installs_use_pins`, and the line-break pipe, `bash <(curl ...)` and `sh -c "$(curl ...)"` still fail `no_pipe_to_shell_installers`.
- Task 2: `compose_checks_the_name_before_it_acts` and its awk block reader are deleted from start.sh (H-03 proves the name check on the Mac); the self-test lost its two name-check cases. start.sh, sandbox-rules.sh and the self-test lib.sh and helpers.sh are in the banner comment shape (lib.sh and helpers.sh changed in comments only at that commit).
- Task 3: `tests/guard/bundle-wiring.sh` is removed (all three rules), with `has_line`, `frontmatter_of` and the three bundle self-test cases. `claude/managed-settings.json` holds exactly the three Edit denies (`rules/**`, `.best-practices-skills`, `skills/**`). SANDBOX.md now says the deny covers every skill under `state/claude/skills/` (bundle, GSD and your own), that shell edits still work, that it is not a security boundary, and that `state/claude/CLAUDE.md` stays editable; no sentence still promises Claude can edit your own skills.

## Deviations from Plan

**1. [Rule 3 - Blocking] Bundle wiring removal committed before Task 1**
- **Found during:** Task 1
- **Issue:** the Task 1 verify requires no awk in lib.sh, but `frontmatter_of` (awk) could only go once `bundle-wiring.sh`, its last caller, was deleted in Task 3.
- **Fix:** removed bundle-wiring.sh, `has_line`, `frontmatter_of` and the three bundle self-test cases in their own commit first, then did Task 1.
- **Commit:** 335b355

**2. [Rule 3 - Blocking] Rule code tightened to meet the 900-line cap**
- **Found during:** Task 3
- **Issue:** after the plan's edits the guard and self-test were 1041 lines, and comment trimming alone reached only 969.
- **Fix:** `report_lines` replaced `report_problems`; `versions_file_has_one_pin_per_line`, `pins_are_exact`, `dockerfile_args_have_no_defaults` and `every_dockerfile_arg_is_pinned` became one-pipeline-per-check; `start_hooks_have_two_digit_names`, `gsd_sync_runs_before_the_bundle` and `agent_image_keeps_base_state_folders` lost their hand-written loops. Behaviour is the same (the `BASE_IMAGE` exception still applies to the Claude Dockerfile only) but the FAIL detail text changed, for example `not an exact x.y.z version: NODE_VERSION=24`. The self-test expectations were updated to match. The self-test cases were folded into `plant_case` and `clean_copy_passes` helpers; every old case still exists, plus a new one for the hook-name rule, which had none, and each planted case now also checks a non-zero exit. The duplicate "state folders: a clean copy" case was dropped.
- **Commit:** ac7695d

**3. [Rule 1 - Bug] Plan title over 80 columns**
- **Issue:** the supply-chain header title the plan gives is 83 columns with its `# ` prefix, which fails the plan's own scan.
- **Fix:** shortened to `Guard rules on the supply chain: one GSD package, exact pins, no pipes`; other long titles were shortened the same way.

**Total deviations:** 3 (2 blocking, 1 bug). **Impact:** none on the rules that stay; the guard still fails every planted case it failed before, and the managed deny, SANDBOX.md text and rule list are as specified.
