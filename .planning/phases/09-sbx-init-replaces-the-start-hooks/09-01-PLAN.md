<objective>
Build `sbx-init`, the in-image command that replaces the container's entrypoint and start hooks, as a near copy of `sbx-selfcheck`: a `python3 -I` launcher, a runner that loads numbered step files from the base folder and the agent's folder, one OK or FAIL line per step, a flock run lock, and the init marker. The first real step makes the state folders the entrypoint used to make. Covers INIT-01 (the runner and the state folders step) and INIT-02 (rerun and lock), per D-05 to D-10, D-18, D-25 and D-26.

Purpose: every later plan of the phase adds a step file to this runner; the images, the wrappers and the host checks rely on its output, marker and exit codes.
Output: `base/init/` (launcher, runner, `steps/010_state_folders.py`), the init constants in `paths.py`, `init_hint()`, and the pytest suite `tests/selftest/init/`.

Claude's discretion choices recorded here (CONTEXT "Claude's Discretion"): the repo folder `base/init/` goes to `/usr/local/lib/sbx-init/` in the image, its `steps/` to `/usr/local/lib/sbx-init/steps/`, agent step files to `/etc/sbx/init.d/<agent>/`; the marker is `/home/sandbox/.sbx-init-done` and the lock `/home/sandbox/.sbx-init.lock`, both in the container layer (never under the mount); the step type is the self-check's own `Check` and `CheckResult` from `check_result.py` (shared, not copied). Honest asymmetry with the self-check runner, flagged: init merges the shared and the agent step files and sorts them by file name (the self-check runs shared then agent), because the ownership step (800) must run after the agent's GSD sync (050); and `AGENT_STEPS_DIR` lives in `paths.py` (the self-check keeps `AGENT_CHECKS_DIR` in `runner.py`) so the launcher test can point every init path into a temp folder through one module.
