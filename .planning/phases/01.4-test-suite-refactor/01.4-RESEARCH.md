## Summary

The phase is a pure restructure of test code plus text updates. No external package is involved, so there is nothing to install and no legitimacy audit to run. Baselines measured this session on `origin/main` in the dev sandbox, all green: `guard.sh` 23 rules (0.3 s), `host-selftest.sh` 295 cases (29 s), `bundle-selftest.sh` 111 cases (6 s, 0 SKIP because `claude` 2.1.285 is on PATH and equals the pin), `entrypoint-selftest.sh` 25 cases (0.05 s). That is 454 checks to preserve. Output of guard, bundle and entrypoint is deterministic (two runs diffed equal), so a before/after diff is a usable proof for those three.

Findings that shape the plans:

1. The fake docker is 476 lines between the heredoc markers (`MT/tests/host-selftest.sh:29-506`). Three of its 45 knobs are dead (no case sets them); only two more are clearly trivial. Honest estimate: dropping dead and trivial knobs removes about 30 lines; moving the fake to a file in the layout style (one banner and function per docker subcommand) adds about 50. The slim fake will be readable and in its own file, but it will not be dramatically shorter unless the planner cuts deeper (Tier 2 below, about 30 more lines) or removes whole check simulations (not recommended; H-14 and H-18 guard bundle security). The planner and the user should know this before D-05 is read as a promise of a large cut.
2. The fake is not only a fake docker. It also runs the real `base/sbx-start-lib.sh` and the real `claude/start.d/10-best-practices` (`MT/tests/host-selftest.sh:140-141, 268, 277-278`), so it couples the host self-test to the entrypoint and bundle code.
3. The three self-tests carry exact duplicates (`expect`, `equals`, `has_text`, `lacks_text`, the work-folder maker and cleaner, `report_and_exit`). That is the main SC3 reuse win, and it needs one new shared self-test library because `tests/host/lib*.sh` report with `pass`/`fail`/`add_problem`, not `expect`. Only a few `tests/host/lib*.sh` functions truly fit (`bundle_skill_names`, `claude_pin`, `make_run_dir`).
4. Guard rules 15 and 16 name self-test paths, and the guard's `grep` ignores missing files (`MT/tests/guard.sh:39` ends in `2>/dev/null`). A stale path would not fail; it would silently stop scanning. The proof must plant a violation in each new location.
5. D-14 changes the "Next" text that seven host-selftest cases assert on. Those cases must change in the same plan as `print_next_block`.
6. Repo memory rules: code, `.planning/` and `.claude/` never share a branch or PR; agents never push without a per-branch go and never merge. The plan split must keep planning-text edits (ROADMAP, REQUIREMENTS) in a separate PR from the code.

**Primary recommendation:** Make every suite a folder of small programs (one per check or rule group) run as child processes by a short `run-all.sh`, exactly like `tests/host/`; move shared assertion helpers into one new `tests/selftest/lib-expect.sh`; keep `fake-claude-api.js` in `tests/host/support/`; drop only dead and clearly trivial knobs (Tier 1); and prove preservation with sorted case-name lists, a rule-body diff for guard, and a "neutralise `add_problem`" mutation run before and after.

### Pattern 1: A suite is a runner plus small programs (recommended)

**What:** Each group file is a program with the layout rule (header, banners, functions, `Main / Entry Point`). It sources `lib.sh`, makes its own work folder, runs its cases, prints `PASS: ...` and `FAIL: ...` lines and exits non-zero when any case failed. `run-all.sh` runs the groups in a fixed order as child processes, copies their output through, counts lines starting `FAIL:`, and prints the same summary text as today.
**When to use:** all four suites; the symmetry is the point of D-07.
**Why:** a developer can run one group alone (`bash tests/selftest/host/h13-env-and-no-self-update.sh`); the file name matches the check under test; it matches how `tests/host/run-all.sh` runs its checks (`run_check` at `MT/tests/host/run-all.sh:58-71`).
**Cost to name:** each program repeats a 3-line preamble, and cases that today share state through globals must live in the same file (see Implicit State). Summary text stays identical if `run-all.sh` counts `^FAIL:` lines.

```bash
# Source: pattern of MT/tests/host/run-all.sh run_check, adapted (illustrative, not a final design)
# run_group FILE: runs one group program, copies its output, adds its FAIL lines to the total.
run_group() {
  local groupOutput

  groupOutput=$(bash "$suiteDir/$1" </dev/null 2>&1)
  printf '%s\n' "$groupOutput"
  failTotal=$((failTotal + $(printf '%s\n' "$groupOutput" | grep -c '^FAIL:')))
}
```

### Pattern 2: Work folder per program, removed by prefix only

**What:** keep the guarded cleanup: `case "$WORK" in */sbx-<prefix>.*) rm -rf "$WORK" ;; esac` (`MT/tests/bundle-selftest.sh:29-33`). With programs, each process owns one folder and removes only it, which satisfies "one work folder under TMPDIR, removes only that folder" per process. Put the maker and cleaner in `lib-expect.sh` taking the prefix as an argument (today three copies differ only by the prefix: `sbx-selftest.`, `sbx-bundletest.`, `sbx-entrytest.`).

### Pattern 3: Fake docker as a program in the layout style

`support/fake-docker` has the header, one banner and function per docker subcommand (`info`, `version`, `compose`, `container`, `image`, `run`, `build`, `volume`, `ps`, `cp`, `exec`), and a `Main / Entry Point` that logs the call then dispatches. The selftest `lib.sh` installs it with `cp` plus `chmod +x` into `$WORK/bin/docker` (as the heredoc is written and chmod'ed today, `MT/tests/host-selftest.sh:29, 507`), not a symlink, so it works whatever mode git stores. It needs no `.sh` suffix (D-06 fixes the name), so every glob that scans self-test files must include `tests/selftest/*/support/*`.

### Anti-Patterns to Avoid
- **Sourced case files with no `lib-` name:** breaks the "library or program, never both" rule in `best-practices/rules/shell.md` (Libraries and programs section) by blurring which files run.
- **A symlink for the fake docker:** fails if the committed file is not executable.
- **Exporting `FAKE_LOG` from a shared library:** `bundle-selftest.sh` already uses a variable of that name for its own log (`MT/tests/bundle-selftest.sh:587`); keep the fake's variables inside `selftest/host/`.
- **Copying more than one assertion library:** one `lib-expect.sh` for all three self-test suites.

## Common Pitfalls

### Pitfall 1: A guard path list goes stale and the rule silently stops scanning
**What goes wrong:** rules 15 and 16 name `tests/host-selftest.sh` and `tests/bundle-selftest.sh`; after the move the old names match nothing and `grep ... 2>/dev/null` hides it, so the rules pass while scanning less.
**How to avoid:** update the lists in the same plan that moves the files, and prove it by planting `Phase 1` in a scratch copy of one file per new folder (including `fake-docker` and `entrypoint/`) and expecting rules 15 or 16 to FAIL.
**Warning signs:** guard still green after deleting a self-test file.

### Pitfall 2: Wrong working directory in a deeper script
**What goes wrong:** the old scripts `cd "$(dirname "$0")/.."`; the cases use repo-root-relative paths (`tests/host/lib.sh`, `bash tests/host/$script`, `claude/Dockerfile`, `base/sbx-entrypoint`). Each new program lives two levels down (three for `selftest/*/`).
**How to avoid:** one helper in each suite `lib.sh` that cds to the repo root from its own path and sets `REPO`; every program calls it.

### Pitfall 3: Planning-ID text in new files
**What goes wrong:** the guard regex matches `Phase 1`, `D-04`, `CONTEXT.md`, `.planning`. Executors like to write "Phase 1.4" in a header comment.
**How to avoid:** no phase, decision or planning-doc names in any file under `tests/`. State the reason inline if a design choice is non-obvious.

### Pitfall 4: D-14 breaks seven host-selftest cases
**What goes wrong:** the cases at 667-668, 698, 712, 1171, 1203 assert the helper names printed by `print_next_block`.
**How to avoid:** edit `print_next_block` and those cases in one plan; run the host self-test and the Mac-independent `bash -n` before and after.

### Pitfall 5: The fake docker is not executable
**What goes wrong:** a symlink or direct execution of a file committed without the execute bit fails with "permission denied" and every host case reports confusing failures.
**How to avoid:** `cp` then `chmod +x` into `$WORK/bin/docker`, as the heredoc is installed today.

### Pitfall 6: Shared globals between bundle cases
See Implicit State. Splitting by function name alone breaks `case_hostile_list_lines`, `case_shared_prefix`, `case_locked_config` and the fake-API pair.

### Pitfall 7: The fake couples to real start scripts
Edits to `base/sbx-start-lib.sh` or `claude/start.d/10-best-practices` change host-selftest results. Keep `FAKE_REPO` exported and do not copy those scripts into the fake's folder.

### Pitfall 8: Summary text and counts change
Programs exit by their own FAIL count; if `run-all.sh` counts groups instead of `^FAIL:` lines the final line changes from "N case(s) failed." to something else. Count lines to keep the text identical (the proof compares it).

### Pitfall 9: Separate branches for code and planning
Repo memory: code, `.planning/` and `.claude/` never share a branch or PR. Edits to ROADMAP and REQUIREMENTS go on a separate planning branch; the code branch is cut from updated `origin/main`. The agent never pushes without a per-branch go and never merges.

### Pitfall 10: The mutation proof is slow
With `add_problem` neutralised, the host self-test took 5 min 13 s here (failing checks wait out their polling loops, for example H-08's 10 s marker wait). Run it in the background, once for the baseline and once for the result.

### Pitfall 11: bash 3.2 and `set -u`
An empty array is unbound under `set -u` in bash 3.2 (`MT/tests/host/lib-report.sh:180`). Guard files and anything sourced from `tests/host/` must test the count first or avoid arrays.
