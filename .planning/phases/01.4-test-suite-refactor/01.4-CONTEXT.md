# Phase 1.4: Test suite refactor - Context

**Gathered:** 2026-10-06
**Status:** Ready for planning

<domain>
## Phase Boundary

The test suite becomes small enough to read and change. The big fake docker inside `tests/host-selftest.sh` shrinks to a slim fake in its own file. The four single-file suites (`tests/guard.sh`, `tests/host-selftest.sh`, `tests/bundle-selftest.sh`, `tests/entrypoint-selftest.sh`) are split into folders with the same shape `tests/host/` already has, and follow the script layout rule. Every check that runs today still runs and still catches what it catches today. Bug fixes in the host tests belong to Phase 1.5, not here.

</domain>

<decisions>
## Implementation Decisions

### Where the host checks run against a real Docker
- **D-01:** Real Docker runs only on the user's Mac, with the Docker Desktop already there. The user runs `tests/host/run-all.sh`. No GitHub Actions runner, no dind sidecar, no separate VM: all too complex for this project.
- **D-02:** Docker inside the dev sandbox was checked and rejected. The sandbox runs as uid 1001 with no capabilities, seccomp on and user namespaces blocked. `--privileged` is effectively the host socket (root in the Docker Desktop VM, which mounts the Mac folders); `seccomp=unconfined` plus rootless Podman weakens isolation. The sandbox configuration stays as it is.
- **D-03:** Split of proof: the Mac run covers the success paths; the slim fake covers the failure paths. Roadmap wording to update: Phase 1.4 SC2 "with real Docker covering the host checks" becomes "the Mac run covers the success paths; the slim fake covers the failure paths"; Phase 1.5 "run against a real Docker" becomes "run on the Mac".

### The fake docker
- **D-04:** Keep a small fake docker. It exists for the agent: to catch its own mistakes before the Mac run, and to prove each check can fail (one or two injected failures per check, SC4).
- **D-05:** Knobs that only test trivial branches go. Today there are about 480 lines of fake and 178 `FAKE_` references; the planner decides which survive under D-04.
- **D-06:** The fake lives in its own file, not a heredoc, and it is obvious that it is the fake docker (clear file name and header): `tests/selftest/host/support/fake-docker`. This replaces the roadmap's `tests/host/support/` location, because `tests/host/` is the real Mac suite and the fake belongs next to its only user. **Reversibility:** reversible.

### Suite layout and entry points
- **D-07:** Every suite is a folder, run with `bash tests/<suite>/run-all.sh`, the same shape `tests/host/` already has (runner, libraries, one file per check group, `support/` when needed). Target layout:
  ```
  tests/
    guard/                 rules on the files; no Docker
      run-all.sh
      lib.sh
      <rule-group>.sh ...
    selftest/              Linux self-tests the agent runs; no Docker
      host/                the host checks against the fake docker
        run-all.sh
        lib.sh
        <case-group>.sh ...
        support/fake-docker
      bundle/              the best-practices start hook
        run-all.sh ...
      entrypoint/          the container start hooks
        run-all.sh ...
    host/                  the Mac suite against real Docker (unchanged shape)
      run-all.sh ...
    host-checklist.md
  ```
- **D-08:** `tests/entrypoint-selftest.sh` is included for symmetry, even though the roadmap did not list it and it may stay one check file inside its folder.
- **D-09:** The old paths are removed: `tests/guard.sh`, `tests/host-selftest.sh`, `tests/bundle-selftest.sh`, `tests/entrypoint-selftest.sh`. No compatibility shims. Every reference moves to the new commands: `tests/host-checklist.md`, script headers (for example `tests/host/h18-scope-and-deny.sh`, `tests/host/support/fake-claude-api.js`), guard rules that name test paths, and the roadmap text (Phase 1.4 SC2 and SC3, Phase 6 "runs `tests/guard.sh`"). **Reversibility:** costly: undoing it touches every doc and header that names a suite command.
- **D-10:** The future CI phase (Phase 6) is not a constraint on this layout; its text is simply updated to the new guard command.
- **D-11:** Library names inside each suite follow the Phase 1.3 rules: one topic per library, a function goes in a library only when several files use it, one-file helpers stay in the file. Reuse `tests/host/lib*.sh` where they fit (SC3).

### Manual helpers (backlog 999.1)
- **D-12:** The manual helpers (`tests/host/manual/h07-login.sh`, `h09-rebuild-resume.sh`, `h13-doctor.sh`, `h19-bundle-behaviour.sh`) are diagnostic tools, not a required gate. The user runs them sparingly, by judgment, or when something goes wrong. No trigger table, no automatic "due" detection.
- **D-13:** `tests/host/run-all.sh` passing on the Mac is the gate for this phase and the ones after it.
- **D-14:** Wording follows D-12: `tests/host-checklist.md` drops "do the manual pass" as a required step and describes each helper as a diagnose-when-needed tool, with one line on what it proves. The end-of-run text in `tests/host/run-all.sh` (`print_next_block`, "Manual pass (needs a terminal), in this order") changes to match or goes away; the cleanup command stays.
- **D-15:** This decision closes backlog 999.1 (Test 4 of the Phase 1.3 UAT); remove it from the roadmap backlog.

### Behaviour preservation
- **D-16:** Every check that runs today still runs and still catches what it catches today; each deliberately broken case still fails (SC4). Where a fake knob is dropped (D-05), the Mac run must still cover the success path it guarded.

### Decisions after research
- **D-17:** The fake docker drops only its dead knobs (`FAKE_INFO_FAIL`, `FAKE_IMAGE_ARCH`, `FAKE_BASE_LAYERS`). `FAKE_SAFE_DIR` and `FAKE_SHARE_EXISTS` stay, so no self-test case is dropped and D-16 holds strictly.
- **D-18:** The fake docker is too complex to own long term. Add a backlog entry at the end of the roadmap: retire the fake docker by running the host checks against real Docker from the agent side, either Docker-in-Docker in the dev sandbox (accepting the isolation trade-off, changing only that container) or GitHub Actions on each PR. Not done in this phase.
- **D-19:** Each group file in a suite is its own small program that `run-all.sh` runs (same shape as `tests/host/`); one group can run alone. Cases that share state stay in one file.
- **D-20:** After D-14, the end of `tests/host/run-all.sh` prints the cleanup command plus one line: "If something looks wrong, see tests/host/manual/". The self-test cases that assert that text change to match.
- **D-21:** `tests/host/support/fake-claude-api.js` stays where it is. The old suite paths in `REQUIREMENTS.md` (CI-01, HT-03) are updated in the planning PR together with the roadmap text.

### Claude's Discretion
- How the guard rules and self-test cases are grouped into files, and the file names.
- Which `FAKE_` knobs survive, within D-04 and D-05.
- Where `tests/host/support/fake-claude-api.js` lives: it is used by both the bundle self-test and H-18, so it may stay in `tests/host/support/` or move; pick the clearer place and update both users.
- How each plan proves no check was lost (for example a before/after list of case and rule names).
- Plan and wave split.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `tests/host/lib.sh`, `lib-docker.sh`, `lib-report.sh`, `lib-sandbox.sh`, `lib-bundle.sh`: topic libraries from Phase 1.3; reuse where the self-tests need the same helpers.
- `tests/host/manual/lib-manual.sh`: the manual helpers' shared library; unchanged by this phase except for wording.
- `tests/host/support/fake-claude-api.js`: the fake API the bundle self-test and H-18 use.

### Established Patterns
- `tests/host/` is the model shape: `run-all.sh` runner, `lib*.sh` topic libraries, one file per check, `manual/`, `support/`.
- `tests/guard.sh` is already one function per rule with a protecting comment; the split groups those functions into files.
- `tests/host-selftest.sh` copies `tests/host/*.sh` and puts the fake docker first on `PATH`; the fake logs every call so cases can prove no real sandbox name and nothing destructive reaches Docker. Keep that safety property.
- Each self-test makes one work folder under `TMPDIR` and removes only that folder at exit; keep it.

### Integration Points
- Guard rules that read `tests/host/h[0-9][0-9]-*.sh` headers and other test paths must follow the move.
- Old paths are named in `tests/host-checklist.md`, `tests/host/h18-scope-and-deny.sh`, `tests/host/support/fake-claude-api.js` and in each suite's own header and usage line.

</code_context>

<specifics>
## Specific Ideas

- Symmetry is the driving principle: once you know one suite, you know them all (`bash tests/<suite>/run-all.sh`).
- The location of a file shows where it runs: `guard/` and `selftest/` on Linux, `host/` on the Mac.
- Prefer the right design over the low-churn one; churn is a cost to name, not a reason to settle.

</specifics>
