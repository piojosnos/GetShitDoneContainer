## Phase Goal

ROADMAP.md Phase 2.2 goal (verbatim): "The best-practices bundle lives in its own GitHub repo. Every sandbox keeps its own clone in its sandbox folder, starts with the latest version, and can send improvements back as PRs. Updates survive restarts and rebuilds, and reach other sandboxes only after the user reviews and merges them."

Not in user-story form; quoted verbatim as in earlier phases.

This plan gives the user and Claude the bootstrap and the right to edit: the managed settings let Claude change the clone from any project folder (BP-04), the three wrappers run the first-run order by hand (D-01), and a sandbox can no longer be named after one of its own folders.

Planning notes:
- The tracer (Task 1) is fully provable here: the planner ran it this session against a prototype hook with Claude 2.1.285 and the repo's fake API (`tests/host/support/fake-claude-api.js`). The managed file cannot be installed in this sandbox (`/etc/claude-code` is not writable), so the rehearsal passes the same JSON with `--settings`, its paths rewritten to a temp folder; research found deny and additionalDirectories merge the same way across scopes. H-18 proves the real managed file in the image on the Mac (plan 06).
- The negative control matters: without additionalDirectories the clone edit is refused, so the setting, not the mode, is what allows it.
- sbx-bundle-clone calls the hook instead of repeating the link code (discretion item; research recommendation). Its success path needs `/etc/sbx/start.d`, so it is proven on the Mac by H-27 (plan 06); here the refusal and the failed clone run for real.
- sbx-claude warns when `~/.claude/rules` does not resolve to the clone (one `-ef` test), not only when the clone folder is missing: that also catches a clone made on the Mac while the sandbox runs (research pitfall 8) and still names sbx-bundle-clone (D-04). Pause: 5 seconds (research recommendation, discretion).
- `state` was already a broken name (the project folder would be the state folder); both reserved names get one message.
- Reversibility: settings and wrappers are reversible (one file each, a rebuild).
