## First clone of a new sandbox

| Option | Description | Selected |
|--------|-------------|----------|
| Start hook clones over HTTPS | Needs network on first start and a public repo | |
| Clone on the Mac before `up` | Works with private; one more manual step | |
| Seed clone baked by `build.sh` | Offline first start; puts the bundle back in the image | |
| Shell first, then wrapper scripts | User runs `sbx-gh-login`, `sbx-bundle-clone`, `sbx-claude` by hand | ✓ |

**User's choice:** Shell first; simple wrapper scripts for gh login, clone and running Claude. Repo URL easy to change in the image.
**Notes:** Visibility "could be both"; Claude picked private (can be made public later, not the reverse).

## Copy vs symlink

| Option | Description | Selected |
|--------|-------------|----------|
| Symlink into the clone | Pull or edit is live; no headers or deny rules on copies | ✓ |
| Copy plus resync hook | Keeps proven sync; needs a post-merge hook | fallback |

**User's choice:** `git pull` must update a running sandbox; Claude must be able to answer about, amend and PR the practices; the clone must live in the Mac folder so git works with the container down.

## Start-time pull

| Option | Description | Selected |
|--------|-------------|----------|
| Pull only on a clean `main`, else skip | Never touches work in progress | |
| Always try, ignore failure | Can leave a half-merged clone | |
| No automatic pull | User pulls on the Mac, in the sandbox, or via Claude | ✓ |

**User's choice:** Don't pull automatically; the user manages that lifecycle.
**Notes:** Amends roadmap criterion 4 and BP-05.
