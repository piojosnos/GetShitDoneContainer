## Phase Goal

ROADMAP.md Phase 2.2 goal (verbatim): "The best-practices bundle lives in its own GitHub repo. Every sandbox keeps its own clone in its sandbox folder, starts with the latest version, and can send improvements back as PRs. Updates survive restarts and rebuilds, and reach other sandboxes only after the user reviews and merges them."

Not in user-story form; quoted verbatim as in earlier phases.

This plan moves the Mac checks onto the new model: a fixture clone in the run folder stands in for the bundle repo, and H-14, H-15 and H-17 prove on real Docker what plans 01 and 03 built. Plan 06 rewrites the rest (H-16, H-18, H-19) and adds H-27.

Planning notes:
- Docker does not run here. The tracer's end-to-end proof is the Mac assertion path without Docker: the new lib-bundle functions build the fixture origin and clone with real git, the real hook links them, and `check_bundle_links` plus `report_result` print PASS, then FAIL once the link is swapped for a copy. The planner ran this rehearsal against a prototype this session.
- `git init --initial-branch` needs git 2.28 (research assumption A10, Mac git unknown). The helpers use `git symbolic-ref HEAD refs/heads/main` instead, which works on any version, and `git clone --bare` of a seed folder; a bare repo whose HEAD names a missing branch clones to an empty folder (research pitfall 6).
- Found by the planner, not in research: the guard rule `no_compromised_gsd_package` passes `tests/host/support/*` to grep, and a folder there makes grep exit 2, which the rule reports as a failure. Task 1 changes that glob in the same commit that adds the fixture folder.
- Claude lists a symlinked rule by its resolved path (research pitfall 2), so H-15 matches `/home/sandbox/workspace/best-practices/rules/FILE`.
- H-14 and H-15 get names that say what they check now; run-all.sh and (in plan 07) the checklist follow.
- Fixture commits use `-c user.name=sbx-hosttest -c user.email=sbx-hosttest@example.invalid -c commit.gpgsign=false`, never the Mac user's identity (research pitfall 10).
- Reversibility: test code only; reversible.

## Conventions carried into every edit

- Host checks run on the Mac with stock bash 3.2 and BSD tools: no `readlink -f`, `sed -i`, `stat -c`, `find -printf`, `grep -P`, `mapfile`, `readarray`, `${var,,}` or associative arrays in host-side code. GNU flags are fine only inside text run by `in_container` or `docker run` (the H-14 probe uses `find -printf` there today).
- A host check never deletes on the Mac: it makes fresh folders under the run folder or moves things aside with `mv`; the cleanup command run-all.sh prints removes the run folder.
- Each check keeps its header (`# H-NN: ...` title, a `# Needs:` line), `require_no_arguments`, `require_test_sandbox ID` where it needs the sandbox, and ends with `report_check`.
- 80-column banners with at most two why lines; braces always; blank lines around control flow; full names; ASCII only; no dash punctuation; no planning IDs.
