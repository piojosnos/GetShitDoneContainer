# Phase 01.2: Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| repo working tree -> Docker build context | everything sent to the daemon could land in an image layer | repo files (low; untracked export tarball must never cross) |
| image (root-owned files) -> container start as sandbox | the hook runs as sandbox and writes into the host-mounted state folder | bundle rules and skills |
| state/claude (agent-writable) -> start hook | the skill list file is read by a script that deletes folders | skill names (untrusted input) |
| Claude session (possibly prompt-injected) -> synced rules and skills | the agent could rewrite the instructions every later session loads | standing instructions (integrity) |
| image build -> /etc/claude-code | policy above user and project settings; a broken file affects every Claude run | managed settings |
