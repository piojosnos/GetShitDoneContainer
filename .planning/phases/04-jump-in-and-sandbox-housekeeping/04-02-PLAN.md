## Phase Goal

ROADMAP.md Phase 4 goal (verbatim): "The user gets into any registered sandbox with one command, and can see and clean up their sandboxes without risking code, login, or history."

Not in user-story form; quoted verbatim as in earlier phases.

This plan lets the user see their sandboxes: `sbx-list` prints every registered sandbox with its status and folder, marks a running sandbox on an older image, and lists labelled containers that have no registry entry. It is built on the library of plan 01 (`runs_older_image`) and proven docker-free, then on the Mac by H-32.

Planning notes (each a choice the user can object to at review):
- Research open question 3, adopted: `paused` and `restarting` read `stopped`, so the list keeps the three values of D-05. Both states are rare for a container that runs `sleep infinity`.
- The marker text is `running, older image` and the note under the table reads `older image: sbx-start NAME recreates it on the current image; that closes its open shells and Claude sessions` (wording is Claude's discretion per D-06).
- A broken entry is a row (`broken entry` plus the entry file's path), not a failure of the whole list (Claude's discretion). The reason is not repeated in the row: `sbx-start NAME` prints it, which keeps the list free of a second error format.
- The leftover section is headed `Containers with the sbx.name label but no registry entry (sbx-add NAME HOST_PATH registers one again):`. It suggests only `sbx-add`: `sbx-rm` needs a registry entry, and no file in `bin/` other than `bin/sbx-rm` may name it (the data guard rule). Research open question 4, adopted: removing such a leftover stays plain `docker`, documented in SANDBOX.md (plan 04).
- `printf` with fixed widths instead of `column -t`: a name is at most 31 characters, `running, older image` is 20, and `column` splits paths with spaces.
- `sbx_usage` changes from `Usage: NAME ARGS` to print no space when ARGS is empty, so `sbx-list` prints `Usage: sbx-list`; every existing usage line stays byte for byte.
- Reversibility: reversible (one script and its output format; nothing parses the list).

- Comment shape: a banner is a rule line of `# ` plus 78 dashes (80 columns), a title line, a rule line, then at most two "why" lines and a closing rule; with no why, the title sits between two rules. - Shell: `set -eu` in the bin scripts, `set -u` in tests; libraries set no options and run nothing; functions plus a `# Main / Entry Point` banner over a short list of calls; braces always; a blank line before and after every `if`/`for`/`while`/`case` block (an `else` stays cuddled); full camelCase variable names; list variables end in `List`.
