The tracer of this phase: one command, `sbx-selfcheck`, runs the shared checks of the base image and every checks file an agent image drops into `/etc/sbx/selfcheck.d`, and prints one PASS or FAIL line per check with a fix line under each FAIL. Recorded choices (Claude's discretion in CONTEXT.md):
- Folder `/etc/sbx/selfcheck.d`; each checks file declares a module-level `CHECK_LIST` of `Check(name, function)`; the line count is the list length, which is what H-34 pins.
- Python sources live in `base/selfcheck/`, `claude/selfcheck/`, `cursor/selfcheck/`, never in a `*/bin/` folder: the guard runs shellcheck on every `*/bin/*` file and shellcheck refuses a Python file.
- The launcher sits next to the library in `/usr/local/lib/sbx-selfcheck/` and `/usr/local/bin/sbx-selfcheck` links to it, the same pattern as `cursor-agent`; the launcher finds the library through its own resolved path, so `python3 base/selfcheck/sbx-selfcheck` also runs from the repo.

- The self-check block sits in the base Dockerfile before `USER sandbox` (it needs root for the folders), so the smoke test stays the last `RUN`; any base change rebuilds both agent images anyway.

base/selfcheck/sbx_selfcheck.py (the library; the image puts it in /usr/local/lib/sbx-selfcheck/). Public names, each with type hints:
- `AGENT_CHECKS_DIR = Path("/etc/sbx/selfcheck.d")`.
- `CheckResult`: a frozen dataclass with `passed: bool`, `detail: str`, `hint: str`.
- `passed(detail: str) -> CheckResult` with an empty hint; `failed(detail: str, hint: str) -> CheckResult` raises `ValueError("a failed check needs a fix hint")` when `hint.strip()` is empty.
- `Check`: a frozen dataclass with `name: str` and `function: Callable[[], CheckResult]`.
- `sandbox_name() -> str`: `SBX_NAME` from the environment, or the text `NAME` when it is unset or empty.
- `mac_hint(action_text: str, command_text: str) -> str` returns `f"{action_text}: on the Mac run: {command_text}"`. Four builders on it, with these exact action texts: `rebuild_hint()` is "rebuild the image and recreate the sandbox" with `sbx-upgrade NAME`; `restart_hint()` is "restart the sandbox" with `sbx-stop NAME, then sbx-start NAME`; `start_hint()` is "run sbx-selfcheck in a sandbox started with sbx-start" with `sbx-start NAME, then sbx-shell NAME`; `shell_hint()` is "open the sandbox shell with sbx-shell" with `sbx-shell NAME`. NAME is `sandbox_name()` at call time.
- `environment_values_result(expected_value_by_name_map: Mapping[str, str], environment: Mapping[str, str] | None = None) -> CheckResult`: `environment` defaults to `os.environ`. For each name in map order, a problem `NAME is not set` or `NAME is 'ACTUAL', expected 'EXPECTED'`. All right: PASS with detail `NAME=VALUE, NAME=VALUE`. Else FAIL with the problems joined by `; ` and the hint `"open a fresh shell with sbx-shell; if it stays, " + rebuild_hint()`.
- `load_check_module(module_path: Path)`: loads one file through `importlib.util.spec_from_file_location` under the module name `sbx_selfcheck_agent_` plus the file stem, and returns the module.
- `collect_checks(shared_check_list: list[Check], checks_dir: Path) -> list[Check]`: a copy of the shared list, then for each path in `sorted(checks_dir.glob("*.py"))` the module's `CHECK_LIST` appended in its order. A missing folder needs no branch: the glob simply yields nothing. A file that raises while loading (any `Exception`), or whose `CHECK_LIST` attribute is missing, becomes one `Check` named `load-` plus the file stem whose function returns `failed(...)` with the detail `PATH did not load: TYPE: TEXT` (or `PATH defines no CHECK_LIST`) and `rebuild_hint()`. Build that Check through a small helper function that takes the name and detail as parameters, so no loop variable is captured late.
- `run_check(check: Check) -> CheckResult`: calls the function; any `Exception` becomes `failed(f"raised {TYPE}: {TEXT}", "this is a bug in the self-check or a broken image; " + rebuild_hint())`.
- `outcome_lines(name: str, result: CheckResult) -> list[str]`: replaces every carriage return and newline in detail and hint by a space; a pass gives `[f"PASS: {name}: {detail}"]`, a failure gives `[f"FAIL: {name}: {detail}", f"      fix: {hint}"]` (six spaces, as the host checks indent details).
- `run_selfcheck(shared_check_list: list[Check], checks_dir: Path, output: TextIO) -> int`: collects the checks, runs each in order, writes its lines at once and flushes, counts failures, then writes `sbx-selfcheck: {total} checks, {failed} failed` and returns 0 when none failed, else 1. No other outcome than PASS and FAIL exists (D-03).
- `main(argument_list: list[str], shared_check_list: list[Check], checks_dir: Path) -> int`: any argument prints `Usage: sbx-selfcheck (no arguments)` to stderr and returns 2 without running a check; else `run_selfcheck(..., sys.stdout)`.

base/selfcheck/sbx-selfcheck (the launcher; mode 100755 in git, set with `git update-index --chmod=+x` if the file system drops it): first line exactly `#!/usr/bin/python3 -I`; a header comment saying it checks the sandbox it runs in, prints one PASS or FAIL line per check, exit 0 when all passed, 1 when one failed, 2 for a usage error. Its code sets `sys.dont_write_bytecode = True`, inserts `str(Path(__file__).resolve().parent)` at the front of `sys.path`, imports `sbx_selfcheck` and `shared_checks`, and exits with `sbx_selfcheck.main(sys.argv[1:], shared_checks.CHECK_LIST, sbx_selfcheck.AGENT_CHECKS_DIR)`. Keep it a short `run()` function called under `if __name__ == "__main__":`.

base/selfcheck/shared_checks.py (the shared checks; names no agent, per D-01): constants `SANDBOX_UID = 1000`, `SANDBOX_GID = 1000`, `SANDBOX_USER = "sandbox"`; `user_result(expected_uid: int, expected_gid: int, expected_name: str) -> CheckResult` reads `os.getuid()`, `os.getgid()` and the user name through `pwd` (an unknown uid reads as `unknown`); PASS detail `uid 1000, gid 1000, name sandbox`; FAIL detail `runs as uid U, gid G, name N; expected uid 1000, gid 1000, name sandbox` with `shell_hint()`. `check_user_sandbox()` calls it with the constants. `CHECK_LIST = [Check("user-sandbox", check_user_sandbox)]`.
