## Design (Claude's discretion under D-02 to D-04)

- WR-01 reports the folder, not the entry: a folder that lists but cannot be searched is the same fact as a folder that cannot be listed, so it gets the same `(unreadable)` name and the same owner fix. The two failure points share one helper, which also shortens `scan_owned_state`. The entry loop stops at the first stat failure of a folder, because every other entry fails the same way and the folder must be named once.
- WR-02 accepts a list only, as both real checks files declare; a tuple or generator is a bad shape. The check on the shape is one small function, and a bad shape is one load failure for the whole file (no partial run of its checks), with the same rebuild fix as every other load failure.
- No README change: its troubleshooting row already says a `load-...` line means a checks file in the image is broken or missing; Task 2 makes that true for a malformed list.
