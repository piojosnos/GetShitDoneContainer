# Phase 06.1 Plan 03: Cursor start hooks Summary

**A Cursor sandbox now starts like a Claude one: `02-no-self-update` sets the static channel in `state/cursor/cli-config.json` through jq, `05-gsd` syncs the image's GSD with `--cursor`, and `10-best-practices` links the bundle skills in no-rules mode; the guard and a dockerless self-test cover all three.**

## Accomplishments

- `cursor/start.d/05-gsd` differs from the Claude hook by exactly three substitutions (`diff` over the sed output is empty). It keeps `timeout 300`, the hidden installer output and the fail-closed version check.
- `cursor/start.d/02-no-self-update` has `check_inputs`, `make_config_folder` and `set_static_channel`. The static channel makes the CLI skip its update check; the hook runs first, before any shell can start the CLI.
- `cursor/start.d/10-best-practices` is the thin hook ending `exec sbx-link-bundle "${CURSOR_CONFIG_DIR:-}" no-rules`, so `sbx-bundle-clone` relinks through it in a Cursor sandbox too.
- `cursor/Dockerfile` copies the hooks and runs `chmod 755` before `USER sandbox`; `.dockerignore` admits `cursor`. `cursor/` holds only the Dockerfile and `start.d/`.
- Guard: `HOOK_DIRS="claude/start.d cursor/start.d"`; the name rule and the GSD order rule loop over it; `cursor/start.d/*` joins `SHELL_FILES` (so shellcheck reads it) and both supply-chain scans. Still 17 rules.
- Self-test: 45 to 53 PASS in the entrypoint suite; new group `update-hook.sh` (5 cases), `case_cursor_sync` (3), `case_cursor_hook` (1). The fake GSD accepts `--cursor`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A new cli-config.json was not stable across starts**
- **Found during:** Task 3 RED run, case "a rerun leaves the file as it was"
- **Issue:** the plan has the hook write `{"channel":"static"}` with printf for a missing file. The second start runs jq over it, which rewrites the compact line in its own indented layout, so the file changed on every start after the first.
- **Fix:** the first write uses `jq -n '{channel: "static"}'`, the same layout the update path produces. The first-start expectation (channel static, one stdout line, empty stderr) is unchanged.
- **Files modified:** `cursor/start.d/02-no-self-update`
- **Commit:** `cfa5e7f`

**2. [Rule 1 - Bug in my own test] A redirect swallowed the case's PASS line**
- **Found during:** Task 3, checking the nine required labels
- **Issue:** `expect ... jq -e ... >/dev/null` redirects `expect`'s own output, so the keys case printed nothing and could not fail visibly.
- **Fix:** the case compares `jq -r` output with `equals`. A scratch mutation that drops the other keys makes it print FAIL.
- **Files modified:** `tests/selftest/entrypoint/update-hook.sh`
- **Commit:** `cfa5e7f`

**3. [Rule 2 - docs follow code] tests/README.md row for the entrypoint suite**
- The row named only the Claude hooks. It now names both agents' hooks, `sbx-link-bundle` and the Cursor self-update setting. Not in the plan's file list.
