# Bundle rules and skills that do not work in Cursor

Read from the best-practices bundle at commit `ced3c0e` on 2026-11-14. Nothing in the bundle was changed (decision D-10: list, do not rewrite).

## How Cursor loads the bundle in this sandbox

- Skills: `10-best-practices` links the bundle's `skills/*` into `~/.cursor/skills` (`state/cursor/skills`). Cursor reads a `SKILL.md` with `name` and `description` there.
- Rules: not linked. Cursor reads global rules only from `.mdc` files, and every bundle rule is `.md`, so a rules link would be inert. The Cursor hook runs `sbx-link-bundle` in `no-rules` mode, which also leaves a user-made `~/.cursor/rules` alone.
- GSD: its own Cursor install warns about `.claude` path references it could not replace (about 368 in 118 files at 1.15.0). That is GSD's limit, not the bundle's.

All nine files are not loaded in Cursor (`.md`, not `.mdc`). The last column is the Claude-only text found by a fresh grep for `.claude`, `CLAUDE.md`, `AskUserQuestion`, `/gsd-` and a `paths:` key.

| `git-workflow.md` | not loaded (`.md`) | line 44 names `/gsd-execute-phase`; line 46 names `/gsd-ship` and `/gsd-pr-branch` (in Cursor GSD skills are mentioned by name, not as slash commands) |

The three `paths:` files need a conversion, not just a rename: `paths:` becomes `globs:` and the file gets a `.mdc` extension. The other six only need the extension and `alwaysApply: true`.
