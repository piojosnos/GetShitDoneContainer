## Summary

The refactor keeps behavior. I compared every removed twin file on `origin/main` (`claude|cursor/selfcheck/{030,040,060,070,080,100,110,120}_*.py`, `claude|cursor/init/{050,900}_*.py`) with `agent_check_list`, `gsd_sync_step_list` and `best_practices_links_step_list` plus the two `AGENT` descriptions. They match on:

- the check and step names;
- the environment maps;
- the home links (one for Claude, two for Cursor);
- the login files and hints;
- the image roots;
- the versions prefix (`claude X | ccusage Y | ` and `cursor-agent X | `);
- the GSD agent option.

Other points checked:

- **Import paths:** the builders import correctly under both launchers. `sbx-init` appends `sbx-selfcheck` and `sbx-selfcheck/agents`, and `base/Dockerfile` copies `base/selfcheck/*.py` and `base/init/*.py`.
- **Closures:** they bind per call, so there is no late-binding bug.
- **Check order:** the selfcheck order changed (`claude-no-home-copy`, `claude-managed-settings` and `cursor-self-update-off` now come after the built checks). The phase decision D-04 accepts this, and `test_inventory.py` pins the new order. The init step order is kept.
- **Tests:** `tests/unit/selfcheck` and `tests/unit/init` pass (459 tests).

No blockers. The findings cover three things:

- A new seam built for the third agent fails open on an empty description.
- Two wiring tests cannot detect the wiring they claim to test.
- The only `monkeypatch` in the repository, against the project rule.

## Warnings

### WR-01: An agent description with empty collections yields checks that pass vacuously (fail open)

**File:** `base/selfcheck/agent_description.py:17-27`, `base/selfcheck/agent_checks.py:42-105`
**Issue:** `AgentDescription` does no validation. The builder turns an empty field into a PASS with an empty or meaningless detail. I ran this with a description that had `home_link_list=[]`, `environment_value_by_name_map={}` and `image_root_list=[]`:

```
agent3-env True ''
agent3-home-links True ''
agent3-image-root-owned True '0 roots: everything under them is owned by root and not writable by group or others'
agent3-image-paths-protected True 'nothing under  is writable or mounted'
```

With the old per-agent files this could not happen, because each list was hard-coded next to its check. The description is now the one seam the next agent fills in, which is the stated goal of this phase. A forgotten field silently turns four security and setup checks into no-ops. The project rule is "Fail closed: an input the script cannot use ... stops with an error (never skip silently)".

Nothing checks consistency either. `login_file` is not required to sit under `config_dir`. The `*_CONFIG_DIR` value in `environment_value_by_name_map` is not tied to `config_dir`. Each pair is written twice by hand in `claude_shared.py:21-25` and `cursor_shared.py:22-26`.

**Fix:** Validate in the dataclass. A raise at import time becomes one `load-` FAIL line through `step_files.load_list`, so the error is visible in both `sbx-selfcheck` and `sbx-init`:

```python
@dataclass(frozen=True)
class AgentDescription:
    ...

    def __post_init__(self) -> None:
        for field_name in ["home_link_list", "environment_value_by_name_map", "image_root_list", "versions_field_list"]:
            if not getattr(self, field_name):
                raise ValueError(f"agent {self.name}: {field_name} is empty")

        if not self.login_file.is_relative_to(self.config_dir):
            raise ValueError(f"agent {self.name}: {self.login_file} is not under {self.config_dir}")
```

Add one test that an empty `image_root_list` raises.

### WR-02: The best-practices wiring tests cannot detect a wrong `config_dir`

**File:** `tests/unit/selfcheck/test_agent_checks.py:125-133`, `tests/unit/init/test_init_agent_steps.py:59-65`
**Issue:** Both tests claim to show that the builder passes `agent.config_dir`. Both compare the builder's result with a direct call of the same helper. The agent is named `agent1`, and the real `BEST_PRACTICES_DIR` never has `generated/agent1/`. So `clone_failure` returns early in both `best_practices_links_result` and `link_best_practices`, before `config_dir` is read. I checked this directly:

```
best_practices_links_result(Path('/nonexistent/a'), BEST_PRACTICES_DIR, 'agent1')
  == best_practices_links_result(Path('/etc'), BEST_PRACTICES_DIR, 'agent1')   -> True
link_best_practices(Path('/nonexistent/a'), ...) == link_best_practices(Path('/'), ...)  -> True
```

A builder that passed `HOME_DIR` or `agent.login_file.parent` instead of `agent.config_dir` would still pass both tests. The tests also read the live clone at `/home/sandbox/workspace/best-practices`. Their outcome therefore depends on the state of that clone, not on fixtures.

**Fix:** Give the builders the same injection seam `gsd_sync_step_list` already has. Then build a temp clone with `generated/agent1/rules` and `generated/agent1/skills/skill1`, as `make_trees` does in `test_init_best_practices_linker.py`:

```python
def best_practices_links_step_list(agent: AgentDescription, best_practices_dir: Path = BEST_PRACTICES_DIR) -> list[Check]:
    def step_best_practices_links() -> CheckResult:
        return link_best_practices(agent.config_dir, best_practices_dir, agent.name)
    ...
```

Assert that `agent1.config_dir / "rules"` is a link after the step runs. Assert that the check passes on that tree and fails on an empty `config_dir`. Do the same for `agent_check_list(agent, best_practices_dir=...)`.

### WR-03: `monkeypatch` introduced against the project rule, and it is not needed

**File:** `tests/unit/selfcheck/test_agent_checks.py:61-62`
**Issue:** `.claude/CLAUDE.md` says "No monkey-patching; use dependency injection or config overrides". `bp-python` says the same. This is the only `monkeypatch` use in `tests/`; `origin/main` has none. Nothing ever sets `SBX_TEST_VAR1`, so the `delenv` is not needed. It exists only because `_env_check` closes over the `os.environ` default of `environment_values_result` and offers no seam.
**Fix:** Drop the `monkeypatch` fixture and the `delenv` line. Better still, pass an `environment_map` through the builder, as `environment_values_result` already accepts one:

```python
def agent_check_list(agent: AgentDescription, environment_map: Mapping[str, str] = os.environ) -> list[Check]:
```

Then test with `{"SBX_TEST_VAR1": "value1"}` for a PASS and `{}` for a FAIL.

## Info

### IN-01: `frozen=True` with list and dict fields gives false immutability

**File:** `base/selfcheck/agent_description.py:17-27`
**Issue:** The fields `home_link_list`, `environment_value_by_name_map`, `image_root_list` and `versions_field_list` are mutable. `claude_shared.AGENT.home_link_list.append(...)` succeeds, and `hash(AGENT)` raises `TypeError: unhashable type: 'list'`. One `AGENT` instance is shared by every check and step closure.
**Fix:** Use `tuple[Path, ...]` and `tuple[tuple[str, str], ...]` for the lists, and `Mapping[str, str]` wrapped in `types.MappingProxyType` for the map. The `_list` suffix can stay.

### IN-02: The success path of the shared versions prefix has no unit test

**File:** `base/selfcheck/agent_checks.py:110-135`
**Issue:** `_versions_prefix_text` replaces two hand-written f-strings with a loop. That loop handles the `" | "` separator and the trailing separator, and the multi-field Claude case. The only unit test (`test_agent_checks.py:116-120`) reaches the missing-pin branch and stops. A separator regression shows up only in the host integration run.
**Fix:** Once the builder takes `versions_file` and `versions_line_file` (see WR-02), add one test with two fields and a matching temp versions line.

### IN-03: The launcher-path tests copy the launchers' `sys.path` lines instead of running them

**File:** `tests/unit/selfcheck/test_agent_checks.py:34-45`, `tests/unit/init/test_init_agent_steps.py:24-36`
**Issue:** `LAUNCHER_PATH_CODE` copies the `sys.path` setup of `base/selfcheck/sbx-selfcheck:20-22` and `base/init/sbx-init:21-25`. If a launcher drops the `agents` directory or changes the order, these tests still pass. They test their own copy.
**Fix:** Run the copied launcher file itself, as `test_init_launcher.py` does for `sbx-init`. Or at least assert that the launcher source contains the lines the test relies on.

### IN-04: `test_agent_descriptions.py` mirrors the descriptions literal for literal

**File:** `tests/unit/selfcheck/test_agent_descriptions.py:13-56`
**Issue:** The test restates every field of both `AGENT` values. Any intended change needs two edits, and the test catches only a typo that was made in one place and not the other. The behavior-level tests (`test_agent_checks.py`, `test_inventory.py`) already cover the wiring.
**Fix:** Keep only the assertions that encode a rule. For example: `config_dir == STATE_DIR / name`, `login_file` is under `config_dir`, and the `*_CONFIG_DIR` environment value equals `str(config_dir)`. Or move these into the WR-01 validation.

### IN-05: README understates what a new agent must add

**File:** `README.md:426`
**Issue:** "A new agent writes its description and its own checks." A new agent also needs:

- the three thin files `030_agent_checks.py`, `init/050_gsd_sync.py` and `init/900_best_practices_links.py`;
- the Dockerfile `COPY` lines for `selfcheck/lib/` and `init/`.

A reader who follows the sentence literally gets an image with no shared checks and no GSD sync or links steps.
**Fix:** "A new agent writes its description, the three one-line files that load the builders (`030_agent_checks.py`, `050_gsd_sync.py`, `900_best_practices_links.py`) and its own checks."

### IN-06: `copy_init_layout` uses one name for two different directories

**File:** `tests/unit/init/test_init_agent_steps.py:109-132`
**Issue:** Inside the helper, `agent_steps_dir` is `tmp_path / "agents1" / agent_name`, the per-agent folder. The helper returns `tmp_path / "agents1"`, the parent, and the caller binds that to `agent_steps_dir` (line 72). The same name means two different levels, which invites an off-by-one-level edit.
**Fix:** Name the inner one `agent_dir` and the returned one `agent_steps_dir`, matching `copy_selfcheck_layout` in `test_agent_checks.py:184-200`.
