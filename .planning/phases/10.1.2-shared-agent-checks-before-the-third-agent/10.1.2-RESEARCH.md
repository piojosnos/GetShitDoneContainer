## Summary

Claude and Cursor each ship 8 selfcheck files and 2 init step files that differ only in data. [VERIFIED: claude/selfcheck/*.py, cursor/selfcheck/*.py, claude/init/*.py, cursor/init/*.py, all read this session] Each file builds exactly one `Check(name, function)` whose name is `<agent>-<suffix>` and whose function calls one existing base helper (`environment_values_result`, `home_links_result`, `login_file_result`, `gsd_synced_result`, `best_practices_links_result`, `image_ownership_result`, `protected_paths_result`, `versions_line_result`, `gsd_sync_result`, `link_best_practices`). The refactor is mechanical: add a frozen `AgentDescription` dataclass and two builders (one in `base/selfcheck/`, one in `base/init/`), put one `AGENT = AgentDescription(...)` into each `<agent>_shared.py`, and replace the 8 + 2 twin files per agent with thin files.

No Dockerfile change is needed. The base Dockerfile already copies every `base/selfcheck/*.py` to `/usr/local/lib/sbx-selfcheck/` and every `base/init/*.py` to `/usr/local/lib/sbx-init/`, and the agent Dockerfiles copy `<agent>/selfcheck/*.py`, `<agent>/selfcheck/lib/*.py` and `<agent>/init/*.py` by glob. The two runners and the two launchers do not change.

Two real traps. (1) The init order forces two thin step files per agent, not one (GSD sync at 050, links at 900, with the shared `800_state_owner` between them); D-03 says "one thin step file", so this needs a one-line confirmation. (2) The pytest `pythonpath` is a superset of the image's import paths, so a builder put in the wrong base directory passes every unit test and fails only in the image; a subprocess test with the launcher's exact `sys.path` closes that gap.

**Primary recommendation:** `base/selfcheck/agent_description.py` (dataclass), `base/selfcheck/agent_checks.py` (`agent_check_list(agent)`), `base/init/agent_steps.py` (`gsd_sync_step_list(agent)` and `best_practices_links_step_list(agent)`); thin files `<agent>/selfcheck/030_agent_checks.py`, and the existing names `<agent>/init/050_gsd_sync.py` and `<agent>/init/900_best_practices_links.py` reduced to one line each; fold 14 twin test files into 3 new ones; prove "output stays the same" with a before/after snapshot diff.

### Pattern 1: Description plus check builder

**What:** `AgentDescription` is data only. The builder makes one `Check` per concern with a nested function (precedent: `load_failure_check` in `base/selfcheck/step_files.py` returns a `Check` over a nested `report_load_failure`). No lambdas (project rule: imperative over functional).

Field names are suggestions (discretion); collection suffixes follow the project rule.

```python
# base/selfcheck/agent_description.py
from dataclasses import dataclass
from pathlib import Path


@dataclass(frozen=True)
class AgentDescription:
    name: str
    config_dir: Path
    home_link_list: list[Path]
    login_file: Path
    login_hint: str
    environment_value_by_name_map: dict[str, str]
    image_root_list: list[Path]
    versions_field_list: list[tuple[str, str]]   # (label, pin name)
    gsd_option: str
```

```python
# base/selfcheck/agent_checks.py (sketch; banners and separators per project style)
def agent_check_list(agent: AgentDescription) -> list[Check]:
    return [
        _env_check(agent),
        _home_links_check(agent),
        _credentials_check(agent),
        _gsd_synced_check(agent),
        _best_practices_links_check(agent),
        _image_root_owned_check(agent),
        _image_paths_protected_check(agent),
        _versions_line_check(agent),
    ]


def _home_links_check(agent: AgentDescription) -> Check:
    def check_home_links() -> CheckResult:
        link_target_list = []

        for home_link in agent.home_link_list:
            link_target_list.append((home_link, agent.config_dir))

        return home_links_result(link_target_list)

    return Check(f"{agent.name}-home-links", check_home_links)


def _versions_line_check(agent: AgentDescription) -> Check:
    def check_versions_line() -> CheckResult:
        pin_name_list = []

        for _, pin_name in agent.versions_field_list:
            pin_name_list.append(pin_name)

        pin_map, missing_result = pin_map_or_missing(pin_name_list)

        if missing_result:
            return missing_result

        prefix_text = ""

        for label, pin_name in agent.versions_field_list:
            prefix_text += f"{label} {pin_map[pin_name]} | "

        return versions_line_result(prefix_text)

    return Check(f"{agent.name}-versions-line", check_versions_line)
```
The prefix loop yields exactly `claude X | ccusage Y | ` and `cursor-agent Z | `, so the printed detail is unchanged. Env order is preserved by dict insertion order (`CLAUDE_CONFIG_DIR=..., DISABLE_UPDATES=1`).

### Pattern 2: Step builders, two thin files per agent

The init order is pinned: [VERIFIED: tests/unit/init/test_init_inventory.py:23-30]
```
STEP_ORDER_BY_AGENT_MAP = {
    "claude": ["state-dirs", "claude-gsd-sync", "state-owner", "claude-best-practices-links"],
    "cursor": [
        "state-dirs",
        "cursor-gsd-sync",
        "cursor-self-update-off",
        "state-owner",
        "cursor-best-practices-links",
    ],
}
```
`init_runner` sorts shared and agent step files together by file name (shared `010_state_dirs`, `800_state_owner`; agent `050`, `060`, `900`). GSD sync must sit before 800 and links after 800, so one thin step file (one file position) cannot hold both. [VERIFIED: base/init/init_runner.py `step_file_list.sort()`; claude/init/900_best_practices_links.py header `it runs last, after the ownership step`]. The code does not say why links must follow the ownership step; the order is pinned by that test and the file headers, so keep it.

So keep the two existing step file names, each one line:
```python
# claude/init/050_gsd_sync.py            # claude/init/900_best_practices_links.py
from agent_steps import gsd_sync_step_list    from agent_steps import best_practices_links_step_list
from claude_shared import AGENT               from claude_shared import AGENT

STEP_LIST = gsd_sync_step_list(AGENT)         STEP_LIST = best_practices_links_step_list(AGENT)
```
```python
# base/init/agent_steps.py (sketch)
def gsd_sync_step_list(
    agent: AgentDescription,
    sync_function: Callable[[Path, str], CheckResult] = gsd_sync_result,
) -> list[Check]:
    def step_gsd_sync() -> CheckResult:
        return sync_function(agent.config_dir, agent.gsd_option)

    return [Check(f"{agent.name}-gsd-sync", step_gsd_sync)]
```
The `sync_function` parameter moves from the step function to the builder (the old test passed it to `STEP_LIST[0].function(record_call)`); the new test passes a recorder to the builder and calls `function()`. `Check.function` is typed `Callable[[], CheckResult]`, so a zero-argument closure is the better fit.

Alternative if the user insists on one thin step file: a single file at one position would move one of the two steps and break the pinned order and the "links last" header; not recommended. See Open Question 1.

### Anti-Patterns to Avoid
- **Runner discovers the description:** rejected by D-03 (hidden behavior); keep explicit thin files.
- **Putting the check builder in `base/init/` or importing `gsd_sync`/`best_practices_linker` from `base/selfcheck/`:** `sbx-selfcheck` cannot import `/usr/local/lib/sbx-init/`. Unit tests would still pass (see Pitfall 2).
- **Keeping the old order with extra machinery:** D-04 says do not.
- **Lambdas / `functools.partial` chains for the closures:** project style is nested `def`.
- **Planning IDs in committed code or comments** (project rule). The thin-file headers say what the file does and where the image puts it, nothing else.

## Common Pitfalls

### Pitfall 1: One thin step file cannot keep the init order
**What goes wrong:** D-03 says "one thin step file"; one file holds one position. Putting both steps in one file moves either GSD sync after `800_state_owner` or the links before it.
**Why it happens:** init sorts all step files by name; the two steps sit on either side of the shared 800 step.
**How to avoid:** two thin step files (`050_gsd_sync.py`, `900_best_practices_links.py`), one builder function each. The CONTEXT discretion clause ("File-name prefix of the thin files, as long as the step order init needs is kept") already allows this; ask the user to confirm the "one thin step file" wording.
**Warning signs:** `test_the_merged_steps_of_an_image_run_in_the_fixed_order` fails.

### Pitfall 2: pytest `pythonpath` hides wrong import placement
**What goes wrong:** the pytest `pythonpath` is `[".", "base/selfcheck", "base/init", "claude/selfcheck/lib", "cursor/selfcheck/lib", "tests/integration"]` [VERIFIED: pyproject.toml:16], a superset of what either launcher sees. A builder in the wrong directory, or `agent_checks.py` importing `gsd_sync`, imports fine in tests and fails in the image as `FAIL: load-claude-030-agent-checks` (load-failure check name built in `step_files.load_list`). The agent Dockerfiles only `py_compile` the files, which does not import them [VERIFIED: claude/Dockerfile `python3 -m py_compile /etc/sbx/selfcheck.d/claude/*.py ...`].
**How to avoid:** add one unit test that runs a subprocess `python -I` with `sys.path` set to exactly the launcher's directories (copy `base/selfcheck/*.py` plus the agent lib into a temp layout, as `tests/unit/init/test_init_launcher.py` `layout1` already does for `sbx-init`) and loads each agent's thin files through `runner.dir_check_list` / `init_runner.collect_steps`, asserting no `load-` name. Keep `agent_description.py` stdlib-only so it never creates a cycle.
**Warning signs:** none in unit tests; only `./host-test.sh` on the host would show it.

### Pitfall 3: Name drift
**What goes wrong:** check names are now built with f-strings; a typo changes a printed name and an integration scenario asserting it fails only on the host (for example `agent.links_step` in `tests/integration/test_first_run_and_relink.py:295-301` expects `FAIL: claude-best-practices-links: ` and `sbx-init: stopped at claude-best-practices-links`).
**How to avoid:** the rewritten inventory tests keep the explicit name lists for both agents (reordered, see below); `test_inventory.py` already checks the name pattern `^[a-z0-9]+(-[a-z0-9]+)*$`.

### Pitfall 4: Inventory tests pin the old order
**What goes wrong:** `test_the_claude_check_names_are_the_thirteen_in_order` and the Cursor twin assert the old interleaved order [VERIFIED: tests/unit/selfcheck/test_inventory.py:127-156 lists]. With the shared file at `030` the Claude order becomes: `tool-claude`, `claude-off-path`, `tool-ccusage`, then the eight built (`claude-env`, `claude-home-links`, `claude-credentials`, `claude-gsd-synced`, `claude-best-practices-links`, `claude-image-root-owned`, `claude-image-paths-protected`, `claude-versions-line`), then `claude-no-home-copy`, `claude-managed-settings`. Cursor: `tool-cursor-agent`, `cursor-off-path`, the eight built, `cursor-self-update-off`.
**How to avoid:** D-04 allows the change. Update both expected lists to the new order (still pinning names), or compare as sorted lists; do not add code to keep the old order.

### Pitfall 5: Test helpers load by file name
**What goes wrong:** `load_agent_check(agent, "030_env")` and similar (14 test files) fail with FileNotFoundError after the twin files go [VERIFIED: tests/unit/selfcheck/helpers.py:56-57]. Also `test_init_gsd_sync.py:210`, `test_init_best_practices_linker.py:70,76` and `test_init_self_update.py:19` load `050_gsd_sync.py` / `900_best_practices_links.py`; their assertions (`step_module.AGENT_CONFIG_DIR`, `STEP_LIST[0].function(record_call)`) no longer hold on a thin file.
**How to avoid:** see the test plan below.

### Pitfall 6: Vocabulary clash on "shared"
README and the glossary already use "shared checks" for the base image's `checks/` directory ("The base image holds the runner and the shared checks") and `claude_shared.py` for "what the checks of one agent share". The new list is shared across agents, not across images. Pick one term for the new list and add a GLOSSARY row (suggested: "agent description" for `AgentDescription`/`AGENT`; keep "shared checks" for base). Project rule: code, tests and docs follow GLOSSARY.md. Also note `runner.collect_agent_checks` has a local variable named `agent_check_list` (runner.py); it does not import the builder, so there is no clash, but a reader may confuse them.

### Pitfall 7: `uv run` on the host
Never run bare `uv run` on the host (repo `.venv` belongs to the dev sandbox); host validation is `./host-test.sh` only. [VERIFIED: .claude/CLAUDE.md Frameworks section]
