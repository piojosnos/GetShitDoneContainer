# Phase 10.1.2: Shared agent checks before the third agent - Context

**Gathered:** 2026-11-25
**Status:** Ready for planning

<domain>
## Phase Boundary

The selfcheck files and init steps that Claude and Cursor repeat with only different data become one shared list, built from a small per-agent description. Each agent keeps only its truly specific checks and steps, so the OpenCode image (Phase 10.2) starts from the shared list instead of a third copy. One phase, one code PR.

Not in scope: OpenCode itself (Phase 10.2); any change to what a check or step tests.

</domain>

<decisions>
## Implementation Decisions

### Scope
- **D-01:** Both kinds of twins move to the shared list:

  | Kind | Twin files (in `claude/` and `cursor/`) | What differs today |
  |---|---|---|
  | selfcheck | `030_env` | env map (Claude adds `DISABLE_UPDATES=1`) |
  | selfcheck | `040_home_links` | home link list |
  | selfcheck | `060_credentials` | login file name, login hint |
  | selfcheck | `070_gsd_synced`, `080_best_practices_links` | only the import |
  | selfcheck | `100_image_root_owned`, `110_image_paths_protected` | `IMAGE_ROOT_LIST` |
  | selfcheck | `120_versions_line` | pin names and labels of the prefix |
  | init | `050_gsd_sync` | the `--claude` / `--cursor` flag |
  | init | `900_best_practices_links` | only the import |

  The init twins were not in the roadmap goal; they are included because the same reason (no third copy) applies, and it keeps checks and steps symmetric.

### Shape
- **D-02:** One typed per-agent description (a dataclass, for example `AgentDescription`) holds every value the table above shows as differing: name, config dir, home links, login file and hint, env map, image roots, versions-line pins and labels, GSD flag. It lives in each agent's `lib/<agent>_shared.py` next to today's constants.
- **D-03:** A shared builder in the base image turns a description into the check list (and one into the step list). Each agent ships one thin check file, `CHECK_LIST = agent_check_list(AGENT)`, and one thin step file the same way. The runners do not change; the wiring stays explicit. Rejected: the runner finding the description and adding the shared checks by itself (hidden behavior). **Reversibility:** reversible.

### Output
- **D-04:** Guideline, kept simple: what `sbx-selfcheck` and `sbx-init` print keeps the same check and step names (`claude-env`, `cursor-credentials`, `claude-gsd-sync`, ...) and the same counts (`test_inventory.py`, `AgentSpec.selfcheck_count` 55 and 53, `init_step_count` 4 and 5). The order of the lines may change. Do not build anything to keep the old order.

### What stays per agent
- **D-05:** These stay as they are, per agent:
  - `010_tool_claude` / `010_tool_cursor_agent`: the version checks really differ (Cursor needs a throwaway `HOME`). Sharing only the off-path half is not worth it.
  - Claude only: `020_tool_ccusage`, `050_no_home_copy`, `090_managed_settings`.
  - Cursor only: selfcheck `050_self_update_off`, init `060_self_update_off`.

### Claude's Discretion
- Names of the dataclass, the builder module and its functions, and of the thin files.
- File-name prefix of the thin files, as long as the step order init needs is kept (GSD sync early, best-practices links last).
- How the unit test twins (`test_claude_env.py` / `test_cursor_env.py`, ...) fold: tests of the shared builder plus a test of each agent's description values.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `environment_values_result`, `home_links_result`, `login_file_result`, `versions_line_result`, `pin_map_or_missing`, and the image ownership and protected paths helpers in `base/selfcheck/`: the twins already only call these; the builder calls them the same way.
- `best_practices_links.py` and `agent_config.py` in `base/selfcheck/`: already take the agent name and config dir.

### Established Patterns
- A check file exports `CHECK_LIST` (an init step file `STEP_LIST`) of `Check(name, function)`; files load in file-name order.
- Agent `lib/*.py` goes to `/usr/local/lib/sbx-selfcheck/agents/`, which is on the import path and never loaded as checks.

### Integration Points
- The Dockerfiles' `COPY` lines for `selfcheck/*.py`, `selfcheck/lib/*.py` and `init/*.py`.
- `tests/unit/selfcheck/helpers.py` (`load_agent_check`) and `tests/unit/init/init_helpers.py`.

</code_context>
