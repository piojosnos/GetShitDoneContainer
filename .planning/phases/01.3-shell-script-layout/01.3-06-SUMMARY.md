**base/sbx-entrypoint restructured into named start steps behind a source guard, and a start hook file that is not executable now stops the start with an [sbx] ERROR instead of being skipped, proved by a new Linux self-test**

## Accomplishments

- `base/sbx-entrypoint` has a header, globals (`ws`, `state`, `hookDir`), a Helpers banner (`is_mount`, `die`), one banner and function per start step (`check_workspace_mount`, `check_project_and_state_folders`, `create_state_dirs`, `run_start_hooks`) and a `Main / Entry Point` banner. Every die message, the project-folder check and the exit codes are unchanged.
- `run_start_hooks` skips anything that is not a regular file, prints `[sbx] ERROR: start hook <path> is not executable; the container was not started.` and exits 1 on a regular file without the execute bit, and keeps the existing `failed` branch. This closes the accepted residual of the previous phase.
- Main sits behind `if [ "${BASH_SOURCE[0]}" = "$0" ]`, with `exec "$@"` inside it, so the arguments are still the script's own.
- `tests/entrypoint-selftest.sh` has 8 cases and 19 PASS lines: executable hook, non-executable file with a later hook that must not run, failing hook, folder and dotfile, empty folder, link to a non-executable file, sourcing runs nothing, direct run stops at the start checks and never runs the command.
- `SANDBOX.md` (Safety checks bullet, troubleshooting sentence) and the `base/Dockerfile` Start hooks comment describe the new rule; no Dockerfile instruction changed.

```bash
docker run --rm --network none --cap-drop ALL --security-opt no-new-privileges:true -e SBX_NAME=hosttest --mount "type=bind,source=$RUN/h17,target=/home/sandbox/workspace" --mount "type=bind,source=$HOOKS,target=/etc/sbx/start.d,readonly" sbx-claude:local sh -c 'echo command-ran'; echo "exit=$?"
```

Expected: `[sbx] ERROR: start hook /etc/sbx/start.d/10-check is not executable; the container was not started.`, `exit=1`, no `command-ran`. Then `chmod 755` the hook and run again: `command-ran` and `exit=0`.
