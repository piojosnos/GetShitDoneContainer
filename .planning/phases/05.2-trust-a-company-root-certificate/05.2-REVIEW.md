## Summary

The certificate path is mostly sound. The `build.sh` awk splitter was run on a PEM holding cert, private key, cert: it produced two `.crt` files and neither contains a key. `build.sh` itself, the Docker build and BSD awk were not run (no Docker or Mac in the review sandbox). The EXIT trap, `set -eu` handling, bash 3.2 syntax and BSD tool usage look correct; the Dockerfile `if`/`&&` chain fails the build when a step fails. No blockers. The warnings concern a coupling between `build.sh` and the Dockerfile, Node trust that only reaches interactive shells, and docs that claim more than the code delivers.

## Warnings

### WR-01: Dockerfile keytool loop depends on file names that only build.sh produces

**File:** `base/Dockerfile:112-114`
**Issue:** The first RUN installs every `/mnt/*.crt`; the second imports only `/usr/local/share/ca-certificates/sbx-extra-ca-*.crt`. The `sbx-extra-ca-N` naming comes from `build.sh` and appears nowhere in the Dockerfile. A hand-run `docker build --build-context cacert=./dir` with other names passes the first RUN, then the unmatched glob reaches keytool as a literal and the build fails with `keytool error: ... file not found`, which does not point at the naming rule.
**Fix:** Let the first RUN own the naming: `i=0; for f in /mnt/*.crt; do i=$((i+1)); install -m 644 "$f" "/usr/local/share/ca-certificates/sbx-extra-ca-$i.crt"; done`. Alternatively name the dependency in the comment above the second RUN.

### WR-02: Node trust is interactive-shell only; the Claude Code row of the README table is unverified

**File:** `base/Dockerfile:119`, `README.md:75-80`
**Issue:** `NODE_EXTRA_CA_CERTS` is appended to `/etc/bash.bashrc`, which returns early for non-interactive shells. Node processes started without an interactive bash (`docker exec` commands, the entrypoint and start hooks, Claude hook or MCP processes spawned from a non-interactive parent) get no extra root and fail with `UNABLE_TO_VERIFY_LEAF_SIGNATURE`. The README documents this for `docker exec` only, and its table says Claude Code trusts the root via the system store, which nothing in the repo establishes.
**Fix:** Either say in the README that Claude Code's trust is observed, not guaranteed, or make Node trust image wide when a root is present (a launcher wrapper that exports the variable if `/etc/sbx/extra-ca.pem` exists, or the variable in `/etc/environment` and the entrypoint).

### WR-03: README says an unset variable builds "exactly as without it", which is not true

**File:** `README.md:60`, `README.md:53`, `base/Dockerfile:17,41-48`
**Issue:** With `SBX_CA_CERT` unset the Dockerfile still has the `FROM scratch AS cacert` stage and the `RUN --mount=type=bind,from=cacert` step: one extra empty layer, and a changed cache chain, so the first build after this change rebuilds everything after the apt step even without a proxy. The image content is equivalent; "exactly" and "changes nothing" overstate it.
**Fix:** Reword to "Unset or empty, the image holds no extra certificate (the build adds one empty layer)", and note the one-time rebuild after this change.

## Info

### IN-01: Certificates are not checked to be CA certificates

**File:** `build.sh:113-118`
**Issue:** `openssl x509 -noout -in` only proves the block parses. A leaf certificate would be installed as a trust anchor without comment.
**Fix:** Optionally show subject and issuer in the banner; a `CA:TRUE` check would mean parsing openssl output, which the code avoids on purpose.

### IN-02: CRLF files are carried through unchanged

**File:** `build.sh:108`
**Issue:** `print > out` keeps `\r` on every line; a PEM with Windows line endings goes into the stores with CRs. Untested against the Debian tooling and Node's loader.
**Fix:** `{ sub(/\r$/, ""); print > out }` in the awk (works on BSD awk).

### IN-03: `awk -v dir=` interprets backslash escapes in the path

**File:** `build.sh:108`
**Issue:** A `TMPDIR` containing a backslash would be mangled. Rare on macOS.
**Fix:** Pass the folder through the environment: `ENVIRON["extraCertDir"]`.

### IN-04: Stale header comment in the base Dockerfile

**File:** `base/Dockerfile:6`
**Issue:** The header says the stages copy only files from pinned official images; the new `FROM scratch AS cacert` stage is neither pinned nor copied from.
**Fix:** Add "(plus the empty cacert stage, see below)", or move the explanation next to the stage.

### IN-05: ZSCALER.md and the README troubleshooting rows differ on the Node workaround

**File:** `ZSCALER.md:129`, `README.md:429`
**Issue:** The README offers `sbx-shell` or `-e NODE_EXTRA_CA_CERTS=/etc/sbx/extra-ca.pem` on `docker exec`; ZSCALER.md gives only the first.
**Fix:** Align the two rows.
