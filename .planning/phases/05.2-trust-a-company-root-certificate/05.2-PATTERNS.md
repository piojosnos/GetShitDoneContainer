### `build.sh` (script, batch)

**Analog:** `build.sh` itself (lines 1-80).

**Header and strict mode** (lines 1-9): shebang `#!/usr/bin/env bash`, a `# ----` block with title, `Usage:` and one note, then `set -eu`. Update the Usage note so it mentions `SBX_CA_CERT`.

**Function block style** (lines 11-18, `check_versions_file`): every function has a `# ----` block with `name: one-line purpose`, and optional extra lines. Errors go to stderr, prefixed `build.sh: `.
```bash
check_versions_file() {
  if [ ! -f ./versions.env ]; then
    echo "build.sh: versions.env is missing next to build.sh" >&2
    exit 1
  fi
}
```
Note: the existing functions `exit 1`. RESEARCH says new functions should `return 1` and Main does `prepare_extra_cert || exit 1` (user shell rule). Do not copy the `exit` here.

**buildArgList handling** (lines 33-52): a global array filled by `collect_build_args`, `local` for loop vars, `local pinCount=0`, blank lines around control flow, full names, `List` suffix.
```bash
  local pinName
  local pinCount=0

  buildArgList=()

  for pinName in $(grep -oE '^[A-Z_]+' versions.env); do
    buildArgList+=(--build-arg "$pinName")
    pinCount=$((pinCount + 1))
  done
```
The cert does NOT join `buildArgList` (a build arg would need a non-pin ARG, which the guard forbids). It goes through `--build-context` as an extra option to the base build only.

**build_image and extra options** (lines 54-69): extra options come right after `docker build` through `shift 2` and `"$@"`.
```bash
build_image() {
  local dockerfile=$1
  local imageTag=$2

  shift 2

  echo "build.sh: building $imageTag"
  docker build "$@" -f "$dockerfile" "${buildArgList[@]}" -t "$imageTag" .
}
```
Pass `--build-context "cacert=$extraCertDir"` as an option before `"$@"` in the base call only. Use an `if`/`else` around the base build, no new array (bash 3.2 treats an empty array under `set -u` as unbound).

**Echo/banner style:** the only existing output is the one-line `echo "build.sh: building $imageTag"`. There is no banner yet; the new starred banner is the first. Keep the `build.sh: ` prefix on the text lines and use `*` framing lines as in RESEARCH `print_cert_banner` (lines 397-415 of the research file).

**Main block** (lines 71-80): `# ---- Main / Entry Point`, then `cd "$(dirname "$0")"` (so a relative `SBX_CA_CERT` would resolve against the repo, hence the absolute-path check), then calls in order.
```bash
cd "$(dirname "$0")"

check_versions_file
load_versions
collect_build_args
build_image base/Dockerfile sbx-base:local "$@"
build_image claude/Dockerfile sbx-claude:local "$@"
```
New order: `collect_build_args`, `prepare_extra_cert || exit 1`, `print_cert_banner`, conditional base build, claude build, `print_cert_banner`.

**Source for new function bodies:** RESEARCH.md "Code Examples: build.sh" (`prepare_extra_cert`, `print_cert_banner`, Main). It is already in this file's style. Portability: BSD awk, `mktemp -d "${TMPDIR:-/tmp}/..."` (precedent in `host-test.sh`), no `sed -i`.

### `base/Dockerfile` (config, batch)

**Analog:** `base/Dockerfile` itself.

**`# ----` comment block style** (lines 33-37 and 63-67): three-part block, title line, explanation lines, closing rule, then the instruction directly below.
```dockerfile
# ------------------------------------------------------------------------------
# GitHub CLI from the release tarball, checked against its checksums
# ------------------------------------------------------------------------------
# The cli.github.com apt repo cannot pin a version.
# ------------------------------------------------------------------------------
ARG GH_VERSION
```

**Multi-stage head** (lines 8-17): all `ARG` pins first, then one `FROM ... AS name` per source image, the final `FROM ${UBUNTU_IMAGE}` last. The new stage joins here as a literal `FROM scratch AS cacert` (no pin, hence the guard carve-out), before the final `FROM`.
```dockerfile
FROM ${HADOLINT_IMAGE} AS hadolint
FROM scratch AS cacert
FROM ${UBUNTU_IMAGE}
```

**Where step one goes:** right after the apt `RUN` (lines 26-31), above the Node block (line 33). Line 24 says "No ARG above this RUN, so a pin bump keeps it": the new step has no ARG either.

**Multi-line RUN style** (lines 53-61, 76-85): `&&` at line starts, 4-space continuation indent, `\` continuation. The shell is bash with pipefail (line 19), so `compgen -G` is allowed.

**Fail-loud guard idiom** (line 39) for contrast: `: "${NODE_VERSION:?... build with ./build.sh}"`. The cert step is the one optional input, so it uses `if ...; then ...; fi` instead.

**`COPY --from` shape** (lines 68, 90, 97-98): `COPY --from=jdk /opt/java/openjdk /opt/java/openjdk`, and `COPY --from=shellcheck --chmod=755 /bin/shellcheck /usr/local/bin/shellcheck`. Step two (Java `cacerts` import) must come after `COPY --from=jdk` (line 68) and the Maven block, before the `uv` copy (line 90). The bind mount in step one is `RUN --mount=type=bind,from=cacert,target=/mnt ...`, the RUN-side counterpart of `COPY --from`.

**ENV block** (lines 116-131): "docker exec shells never run the entrypoint, so they get these from ENV." Do NOT add anything here: ENV cannot be conditional, and D-05 forbids settings in a no-cert image. Node gets `export NODE_EXTRA_CA_CERTS=...` appended to `/etc/bash.bashrc`, the same mechanism as the tool-versions line:
```dockerfile
    && printf '%s\n' 'cat /etc/sbx/tool-versions' >> /etc/bash.bashrc
```
(line 165). Do not touch lines 157-165 (D-07, host test h30).

**Smoke test last** (lines 177-190): stays the last `RUN`; mount point must stay empty. No change needed.

**Source for new step bodies:** RESEARCH.md "Code Examples: base/Dockerfile: the stage and step one" and "step two" (marker file `/etc/sbx/extra-ca.pem`, one `keytool` import per `sbx-extra-ca-N.crt`, npm `cafile`, `/etc/pip.conf`, `/etc/uv/uv.toml`). ### `tests/guard/supply-chain.sh` (test, transform)

**Analog:** the `BASE_IMAGE` carve-out in `dockerfile_args_have_no_defaults` (lines 115-125 of the file).

**Existing carve-out pattern** (the `grep -Fvx` shape):
```bash
dockerfile_args_have_no_defaults() {
  local ok=0

  grep -E '^ARG .*=' $BASE | report_lines "$BASE: an ARG with a default value: " || ok=1
  grep -E '^ARG .*=' $CLAUDE | grep -Fvx 'ARG BASE_IMAGE=sbx-base:local' | report_lines "$CLAUDE: an ARG with a default value: " || ok=1
  grep -E '^FROM ' $BASE | grep -Ev '^FROM \$\{[A-Z_]+\}( AS [a-z]+)?$' | report_lines "$BASE: FROM must take its image from a pin: " || ok=1

  return "$ok"
}
```
**Change:** on the `FROM` line add `| grep -Fvx 'FROM scratch AS cacert'` between the `grep -Ev` and `report_lines`. One literal exact-line match, no regex loosening. Update the function's `# ----` title line (currently "no ARG default, every FROM takes a pin") to say the one literal stage is the empty default of the optional certificate context.

**Rule-block style** (lines 113-114): `# ---- name: summary ----`. No self-test plants this FROM rule (`tests/selftest/guard/sandbox-rules.sh` plants only `ARG NODE_VERSION=1.2.3`), so selftests stay unchanged.
