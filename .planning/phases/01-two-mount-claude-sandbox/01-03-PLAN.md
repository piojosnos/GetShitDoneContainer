## Phase Goal

ROADMAP.md Phase 1 goal (verbatim): "The user can run a Claude Code sandbox on their Mac. Code lives in `<sandbox>/workspace` and Claude state lives in `<sandbox>/state/claude`. Nothing is mounted over `/home/sandbox`, and the Claude login survives recreating the container and rebuilding the image." (The Goal line is not in user-story form, and none is invented here. See 01-01-PLAN.md.)

<objective>
Make the sandbox fail loudly instead of losing data. Without its mounts, the container refuses to run (entrypoint mount check). A mistyped `SBX_DIR` is caught before start (layered D-10 defense), and the container gets no extra privileges.

Purpose: D-10 plus LAY-04. The silent failure modes (a state dir auto-created at a typo'd path, or a container writing state into its own layer) are exactly what the old layout could not detect. RESEARCH Pitfall 1 shows `create_host_path: false` alone is not reliable across Compose versions, so this plan adds the detection and documentation layers. It does NOT implement the `env_file` sentinel fallback: that is a conditional follow-up that depends on host check H-10 and needs user approval (see 01-04).
Output: new `base/sbx-entrypoint`; updated `base/Dockerfile`, `claude/Dockerfile`, `compose.yml`, `SANDBOX.md`, `tests/static-check.sh`.
</objective>

1. Create base/sbx-entrypoint from RESEARCH Pattern 3.
   - Line 1 is `#!/usr/bin/env bash`, then `set -eu`.
   - Then a why-comment block in the style of ClaudeCode/docker-entrypoint.sh. It says: this runs only at container start and never in docker exec shells, so it holds no environment. It checks that every state and workspace path is a real, writable bind mount, because otherwise data would land in the container layer and vanish on recreate. It installs nothing and changes no ownership.
   - Define `is_mount()` as an awk match of field 5 of `/proc/self/mountinfo` against the path. This needs no util-linux `mountpoint`.
   - Loop over `/home/sandbox/workspace`, `/home/sandbox/.local/state/sbx/shell`, `/home/sandbox/.local/state/sbx/gh`, `/home/sandbox/.local/state/sbx/git` and the unquoted `${SBX_MOUNTS:-}`. It is left unquoted on purpose so an agent image can list several paths.
     - A path that is not a mount prints `[sbx] ERROR: PATH is not a bind mount; its data would be lost on recreate.` plus a second `[sbx]` line pointing to `docker compose up` and SANDBOX.md, to stderr, then `exit 1`.
     - A path that is not writable prints `[sbx] ERROR: PATH is not writable by USER.` (using `id -un`), then `exit 1`.
   - The last line is `exec "$@"`.
   - Make it executable (`chmod 755`) so git records mode 100755.
