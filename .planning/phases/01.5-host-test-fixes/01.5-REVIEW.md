# Phase 01.5: Code Review Report

**Reviewed:** 2026-10-07
**Depth:** standard
**Files Reviewed:** 62
**Status:** issues_found

## Summary

Reviewed the sandbox start code (`base/`, `compose.yml`), SANDBOX.md and the checklist, the guard rules, the host checks and their libraries, and the Linux self-tests with the fake docker. I also ran the guard and the three Linux self-test suites in the code worktree: the guard and all three self-test suites pass, so the findings below are about what those suites cannot see, not about red tests.

The start-code changes (`enter_project_folder`, the writable-state check, the literal state-name split, the `working_dir` move to the mount point) are correct as written, and the self-tests exercise them against the real entrypoint and library copies. I found no blocker.

The main concern is the open H-03 gap spreading further than the one assertion: the false belief "Compose refuses an uppercase `SBX_NAME`" is also written into SANDBOX.md, the checklist, the fake docker model and the H-03 self-test, and it hides a real hazard (case-colliding names share one Compose project). The other warnings are weak spots in the new test machinery: H-10 passes on any failed start, `run_timeout` never escalates past SIGTERM, and `reset_state` runs an unguarded `rm -rf`.

## Warnings

### WR-01: The "uppercase `SBX_NAME` is refused" assumption is baked into docs, the checklist and the fake docker, and hides a project collision

**File:** `SANDBOX.md:17`, `SANDBOX.md:208`, `tests/host-checklist.md:41`, `tests/selftest/host/support/fake-docker:167`, `tests/selftest/host/h03-variable-interpolation.sh:37-38`, `tests/host/h03-variable-interpolation.sh:3,82`
**Issue:** The real Mac run showed Compose 2.40 lowercases the top-level project name and exits 0, so `SBX_NAME=HostTest` renders `name: sbx-hosttest`. The H-03 assertion itself is the known gap. Beyond it, the same false assumption is stated as fact in:
- `SANDBOX.md:17`: "`MyProject` is rejected; `myproject` works."
- `SANDBOX.md:208` (troubleshooting row): "Invalid project name | `SBX_NAME` must be lowercase."
- `tests/host-checklist.md:41`: the H-03 row says "an uppercase name is refused".
- `fake-docker` `compose_config`: models an "is not a valid project name" refusal for uppercase that real Compose does not produce, so the self-test `H-03: a config that accepts an uppercase name fails` (and the `FAKE_CONFIG_NO_CASE_CHECK` knob) proves a behaviour that does not exist.
- `runner-healthy.sh` counts the `HostTest` probe as one of exactly two config-only calls.

It also hides a hazard nobody tests: `container_name` stays `sbx-${SBX_NAME}` (mixed case) while the Compose project name is lowercased. `SBX_NAME=Foo` with one `SBX_DIR` and `SBX_NAME=foo` with another then map to the same project `sbx-foo` and the same service. Running `docker compose up` for the second very likely recreates, and so removes, the first sandbox's container, because Compose matches containers by project and service label. Nothing in the entrypoint validates the name either; the only validation was assumed to be Compose.
**Fix:** Decide the policy rather than the assertion. Either (a) validate in the entrypoint and in `compose.yml` docs that `SBX_NAME` matches `^[a-z0-9][a-z0-9_-]*$` (the entrypoint can refuse any other value with a `[sbx] ERROR`, which H-03 or a new check can drive through `docker run -e SBX_NAME=HostTest`), or (b) document that Compose lowercases the name and that names differing only by case collide. Then update SANDBOX.md lines 17 and 208, the checklist row, the H-03 header and PASS text, and replace the fake's invented refusal with the real Compose behaviour (`name:` lowercased, exit 0) so the self-test stops asserting a false model.

### WR-02: H-10 passes on any failed start, without checking why it failed

**File:** `tests/host/h10-missing-folder-refused.sh:63-81`
**Issue:** After the start on the missing folder, the check passes whenever `upStatus` is non-zero and the path was not created. A start that fails for an unrelated reason (the 120 s `run_timeout` returning 143, a missing image, Docker Desktop file-sharing denial) is reported as "a missing folder is refused". H-20, added in the same phase, does check the container log for the expected message, so the two sibling checks now hold different standards. `upOutput` is already captured and printed on the FAIL paths, but never examined on the PASS path.
**Fix:** Require the refusal to name the bind source, for example:
```bash
if ! printf '%s\n' "$upOutput" | grep -Eqi 'does not exist|no such file|bind source'; then
  fail H-10 "the start failed (rc=$upStatus), but not because the folder is missing.$restartNote" \
    "last output: $lastLines"
  return 1
fi
```
Place it after the `pathExists` branch and before the final `pass`. Add a self-test case where `FAKE_UP_RC=1` makes the start fail for another reason.

### WR-03: `run_timeout` only sends SIGTERM and then waits forever

**File:** `tests/host/lib-sandbox.sh:66-93`
**Issue:** On timeout the watcher calls `kill_tree` (SIGTERM only) and the main shell then runs `wait "$commandPid"` with no upper bound. A command that ignores or delays SIGTERM (a `docker compose up --wait` that is mid-cleanup, a hung `docker exec` client) leaves the runner blocked indefinitely, which defeats the point of the time limit and the "never waits for input" promise in `run-all.sh`. The self-test `run-timeout.sh` only uses `sleep`, which dies on SIGTERM, so it cannot see this.
**Fix:** After `kill_tree`, give the tree a short grace period and then send SIGKILL to the same collected list, for example:
```bash
kill_tree "$commandPid"
sleep 5
kill -9 $(tree_pids "$commandPid") 2>/dev/null
```
Collect the pid list before the first signal so children are not lost, and add a self-test case with `trap '' TERM` in the slow function.

### WR-04: `reset_state` runs `rm -rf` on unguarded variables

**File:** `tests/selftest/host/lib.sh:64-66`
**Issue:** `rm -rf "$WORK/state" "$WORK/tmp"` expands to `/state` and `/tmp` if `WORK` is ever empty (a group that calls `reset_state` before `start_group`, or a failed `make_work_folder`). The groups run `set -u`, which does not catch an empty string. The sibling `cleanup_work` in `lib-expect.sh:148-156` carefully refuses to delete anything whose name lacks the `sbx-<prefix>.` marker, so the two rules are inconsistent, and `/tmp` here also holds the session scratch data of the user running the self-test.
**Fix:** Use the same guard style as `cleanup_work`:
```bash
reset_state() {
  rm -rf "${WORK:?}/state" "${WORK:?}/tmp"
  mkdir -p "$WORK/state" "$WORK/tmp"
  : >"$FAKE_LOG"
}
```

**File:** `SANDBOX.md:182`

### IN-07: `create_state_dirs` reads only the first line of `SBX_STATE_DIRS`

**File:** `base/sbx-start-lib.sh:53`
**Issue:** `read -r -a` on a here-string stops at the first newline, so a multi-line `SBX_STATE_DIRS` would silently drop every folder after the first line. The value comes from the image `ENV` today and is a single line, so this is latent only. The previous unquoted expansion handled newlines.
**Fix:** Either document "one line, space separated" next to the comment, or split without losing lines: `IFS=$' \t\n' read -r -d '' -a stateFolderList <<< "..." || true`.
