### Mistyped sandbox name fails fast (P1 WR-01)
- **D-04:** A mistyped `SBX_NAME` against a valid `SBX_DIR` must fail at start with a clear `[sbx]` error, and nothing is created on the Mac. Approach: `working_dir` points at a folder that always exists (`/home/sandbox/workspace`), the entrypoint checks `workspace/$SBX_NAME`, then `cd`s into it before `exec`. **Reversibility:** reversible: one compose line and a few entrypoint lines.
- **D-05:** `docker exec` shells then start in `workspace/` unless they pass `-w`. Accepted; every place that runs `docker exec` and relies on the start folder (tests, docs) passes `-w` or `cd`s. The Phase 4 jump-in script will pass `-w`.
- **D-06:** Add an automated host check to `tests/host/run-all.sh` for "valid `SBX_DIR`, mistyped `SBX_NAME`": the start is refused and no folder appears. Update SANDBOX.md and the `compose.yml` comment so they promise only what now happens.
- **D-07:** P1 WR-02: fix the `base/Dockerfile` comment only (Compose is asked not to create the folder, but may ignore that; the entrypoint refuses). No `env_file` sentinel: H-10 already passes on the user's Compose.

### Gap closure: sandbox name rule (after the Mac run, 2026-10-07)
The Mac run showed that real Compose 2.40 lowercases the top-level project name, so an uppercase `SBX_NAME` is never refused (H-03 failed; review WR-01). `Foo` and `foo` then share one Compose project, and starting one can replace the other's container.
- **D-13:** One safe name rule, `^[a-z][a-z0-9-]{0,30}$`: starts with a lowercase letter, then lowercase letters, digits or `-`, 31 characters at most. No `_`, no `.`, so the name is valid as a Compose project, container name, hostname and folder name. Docs, error messages, tests and the guard all state this same rule.
- **D-14:** Enforce it in two places. (a) The entrypoint refuses a name that breaks the rule, with an `[sbx] ERROR` that names the variable, the value given, the rule in plain words and a valid example. (b) A Compose level refusal so a bad name is stopped before Compose creates or replaces anything; the candidate is a field that Docker requires in lowercase, such as an image reference `sbx-${SBX_NAME}`, which is not yet measured on real Compose. Both are proven in ONE Mac run of `tests/host/run-all.sh` (no separate probe run): H-03 asserts the real Compose refusal, a host check asserts the entrypoint refusal. If the Compose level refusal does not hold on the Mac, that run's FAIL line is the evidence and the gap returns to planning.
- **D-15:** The docs say exactly what happens: `SANDBOX.md` (the name rule, the error, the examples that currently say `MyProject` is rejected), `tests/host-checklist.md` (H-03 row), the `compose.yml` error text and comments. The fake docker models only what real Compose does (no invented "project name" refusal); a guard rule keeps docs and code on the same pattern.
- **D-16:** Fold in the review warnings: WR-02 (H-10 must check the refusal it expects, not any failed start), WR-03 (`run_timeout` escalates to SIGKILL when a command ignores SIGTERM), WR-04 (guard `reset_state`'s `rm -rf` against empty variables). Each keeps the red then green commit rule (D-09). Info items IN-01 to IN-07 stay open.
