Kept out of Phase 1.3 so that identical output stays the proof of a safe restructure, and placed after Phase 1.4, which settled that the host checks run on the Mac. From the Phase 1.3 discussion."

Planning notes:
- Spec-less probe fallback skipped (no requirement IDs; visible skip).
- CR-01 approach (Claude's discretion in CONTEXT): the tree kill from research Pattern 1, because the time limit must hold for a shell function and the review's pkill -P alone kills only direct children and lets the function run its next statement.
- Research Pitfall 1: bash exec-optimises a one-command function, so the red test uses a function with two statements.
- Research Pitfall 2: a strict "this run" identity in compose_down would break the second Mac run (run-all.sh removes the previous run's sandbox while RUN is already the new folder). The rule is split: loose for cleanup, strict before a check acts.
- Research Pitfall 3: H-10 and the new mistyped-name check leave an exited container whose mount is a folder inside the run folder; the loose rule accepts "the mount or its parent is named sbx-hosttest-*".
- The review's identity example "a parent directory containing the text" is covered by two cases: a mount whose name only contains the prefix (old-sbx-hosttest-copy) and a mount two levels below a run folder.
- Reversibility: library internals behind an unchanged interface; reversible.
