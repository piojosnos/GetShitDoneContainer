## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The guard's grep -P term matched inside pgrep -P**
- **Found during:** Task 1 (green), first full suite run
- **Issue:** `host_tests_are_portable` looked for the plain substring `grep -P`, so tree_pids (`pgrep -P`, which BSD pgrep supports) broke the guard; the plan expects the portability rule to pass.
- **Fix:** Term changed to `\bgrep -P`, driven by a new red/green pair with two cases in tests/selftest/guard/host-rules.sh (pgrep -P is not named; grep -P still is).
- **Files modified:** tests/guard/host-tests.sh, tests/selftest/guard/host-rules.sh
- **Commits:** 49d172b (red), 0bab297 (green)

**2. [Rule 1 - Bug] The child-gone case could not fail at red as planned**
- **Found during:** Task 1 (red)
- **Issue:** Inside a command substitution the caller waits until the function's child closes stdout, so at red the 8 s sleep had already ended when the case looked for it and the case passed.
- **Fix:** That case runs the function with a plain call and polls the child's pid afterwards; the timing case keeps the command substitution. Result at red matches the plan's three FAIL lines.
- **Files modified:** tests/selftest/host/run-timeout.sh
- **Commit:** 113f683

**3. Case split in the identity group (no impact).** The two refusal cases each check the status and the "Refusing compose down" text as two PASS lines, so the group prints 9 lines instead of 7. The run-timeout group has exactly the 6 PASS lines the plan counts.

**Total deviations:** 2 auto-fixed (1 blocking, 1 bug), 1 shape note. **Impact:** one extra red/green pair in the guard self-test; no scope change.
