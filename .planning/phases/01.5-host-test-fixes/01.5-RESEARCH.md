## Summary

This is a shell and test-infrastructure phase: no packages, no new runtime. Every finding is in code that already exists in the 1.4 layout, and almost every fix is small. The risk is not the fixes but (a) proving them honestly (the guard and the self-test assertions currently pass on missing input, so they come first), (b) the shared fake docker and run lists that every later fix touches, and (c) a handful of interplay traps found while reading: a strict "this is the current run's sandbox" check would break leftover-container removal on the second Mac run; the new H-20 check leaves an exited container behind that the cleanup guard must accept; bash can hide the `run_timeout` bug for one-command functions, so the red test must use a multi-command function.

All the key bugs were reproduced in this session: `run_timeout` with a multi-command function takes 7 s for a 2 s limit and leaves the child alive; three `sleep 25` orphans remain after one H-08 self-test group; `nowhere_matches`, `lacks_text` and `lacks_match` return success on a missing file; the guard passes with `tests/host/manual/` absent and with `docker compose down --rmi all` planted in a host check. A tree-kill `run_timeout` (pgrep -P, parent first) was prototyped and fixes the function case and the watcher's own `sleep 1` leftover.

**Primary recommendation:** Execute in five sequential plans: (1) make the instruments fail closed (guard, `lacks_*`, runner-list rule, new guard self-test suite); (2) fix the host library (`run_timeout` tree kill, sandbox identity split, env scrub and `--env-file /dev/null`, Coexistence baselines, H-08 orphan, blank lines); (3) fix the individual checks (H-01, H-02, H-03, H-05, H-06, H-09, H-13); (4) the mistyped-name chain (compose `working_dir`, `enter_project_folder`, H-20, `-w` edits, wording and state-folder fixes); (5) docs, dispositions (separate `.planning` branch) and the single Mac `run-all.sh` checkpoint. Each fix is a red commit then a green commit.

## Architecture Patterns

### System Architecture Diagram

```
 run-all.sh (Mac)  ---- 1 info line: docker context + DOCKER_HOST (not scrubbed)
   |  scrub: COMPOSE_* (+3), SBX_DIR   every `docker compose -f F --env-file /dev/null`
   v
 build -> compose up (working_dir = workspace, always exists)
   |
   v
 container PID 1: sbx-entrypoint
   check_workspace_mount -> check_project_and_state_folders (live now)
   -> create_state_dirs -> run_start_hooks -> enter_project_folder -> exec "$@"
   |                                                  ^ refused: [sbx] ERROR, exit 1, nothing created on the Mac
   v
 checks (docker exec -w <project> where the start folder matters)
   run_timeout -> tree kill (pgrep -P, parent first)
   H-20: SBX_DIR=$RUN/h20 (has state/, no hosttest/) -> up refused, no h20/hosttest, message in `docker logs`
   Coexistence: before/after of old containers and old folders (git), failures are results

 Dev sandbox (Linux)                                  
   guard  -> fail closed scans, suite lists, blank lines, env-file, docs promises
   selftest/guard  -> proves the guard rules can fail (scratch repo copies)
   selftest/host   -> fake docker (+ new switches) runs the real host scripts and the real start library
   selftest/entrypoint -> start-folders.sh calls the real library with ws/state overridden
```

### Pattern 1: Tree-kill timeout (CR-01, 1.3 WR-02)
**What:** The watcher collects the command's process tree first, then signals every pid parent first, so a function cannot run another statement after its child dies. The watcher's own `sleep 1` is removed the same way. `tree_pids` and `kill_tree` are shared by `run_timeout` and the H-08 cleanup (two users, so they belong in `lib-sandbox.sh`).
**Prototype, run this session (bash 5.3, Linux). Result: a multi-command function with a 2 s limit returned 143 after 2 s and left no `sleep`; the old code took 7 s and left the child alive:**
```bash
# --------------------------------------------------------------------------------
# tree_pids PID: prints PID and every descendant, parent first, one per line.
# --------------------------------------------------------------------------------
tree_pids() {
  local rootPid=$1
  local childPid

  printf '%s\n' "$rootPid"

  for childPid in $(pgrep -P "$rootPid"); do
    tree_pids "$childPid"
  done
}

# --------------------------------------------------------------------------------
# kill_tree PID: stops PID and every descendant; a PID that is already gone is not an error.
# --------------------------------------------------------------------------------
kill_tree() {
  kill $(tree_pids "$1") 2>/dev/null

  return 0
}
```
In `run_timeout` replace `kill "$commandPid" 2>/dev/null` (line 46) with `kill_tree "$commandPid"`, and `kill "$watcherPid" 2>/dev/null` (line 51) with `kill_tree "$watcherPid"`. The return code stays 143 on timeout.
**Why not the alternatives:** `pkill -P "$commandPid"` alone, as the review suggests, kills only direct children and leaves the function running its next statement; collecting the whole tree first fixes both. `pgrep -P` is documented for macOS [CITED: https://www.unix.com/man_page/osx/1/pgrep/].

### Pattern 2: Real library, overridden globals (entrypoint self-test)
The library keeps `ws`, `state` and `hookDir` as globals so tests can point them at a work folder. `state` is computed at source time, so a test must set both after sourcing:
```bash
( . "$START_LIB"; ws=$WORK/ws; state=$ws/state; SBX_NAME=demo; check_project_and_state_folders ) >"$WORK/out" 2>&1 </dev/null
```
`is_mount` reads `/proc/self/mountinfo`, so a work folder is never a mount: the failure path of `check_workspace_mount` is testable as is; the success path needs `is_mount() { return 0; }` redefined after sourcing.

### Pattern 3: Fake docker runs the real code
`fake-docker` already runs the real `claude/start.d/10-best-practices` and `run_start_hooks`. Extend that: compose up runs the real `check_project_and_state_folders`, and emulates the one daemon behaviour behind the bug (create a missing `working_dir` under the mount) from the real `compose.yml`. Then the red H-20 case fails because of the real `compose.yml` line and turns green when that line changes. The daemon behaviour is documented: "If the path doesn't exist, Docker creates it inside the container" [CITED: https://docs.docker.com/reference/cli/docker/container/run/].

### Anti-Patterns to Avoid
- **A function as the target of `run_timeout` without a test that forces the failure.** A one-command function (`slow() { sleep 7; }`) is exec-optimised by bash 5.3 and is killed correctly, so it hides the bug. Verified this session: `slow() { sleep 7; true; }` captured under `$(...)` took 7 s for a 2 s limit. The red test must use a multi-command function.
- **`2>/dev/null` on a scan.** It converts "could not read" into "nothing found". Let grep's message through and fail the rule on status above 1.
- **Applying the strict "current run" identity to `compose_down`.** See Pitfall 2.
- **Planning or finding IDs in new code** (`CR-01`, `D-04`, `Phase 4`). The guard's regex does not yet cover `WR-`, `CR-`, `IN-`; add `\b(CR|WR|IN)-[0-9]{2}\b` to `PLANNING_ID_REGEX` (verified: no current hit in tests, base, claude, compose.yml, SANDBOX.md).

```awk
{
  line = $0
  if (endMark != "") { if (line == endMark) { endMark = "" } prev = line; next }
  text = line; sub(/^[ \t]+/, "", text)
  if (text ~ /^(if|for|while|until|case)[ (]/ && prev != "") {
    before = prev; sub(/^[ \t]+/, "", before)
    if (before !~ /^#/ && before !~ /(\{|then|do|else|;;|\)|in)$/ && before !~ /\\$/) { printf "%s:%d: %s\n", FILENAME, FNR, text }

}
```

### Red/green discipline (D-09)

- One fix = two commits on the code branch: `test(...)` (red) then `fix(...)` (green). Group them as TDD-style tasks in the plans.
- **Red commit contents:** only test side files (new group file or case, its `groupList` entry, new fake switches, the new guard rule when the rule is the test). Switches default off so every other group stays green.
- **Red commit verification** (per task, not per suite): run the targeted group and require a non-zero exit and the expected FAIL line, for example `bash tests/selftest/host/run-timeout.sh; test $? -ne 0`. The suite `run-all.sh` is expected to exit 1 at a red commit, and only because of that group. Also run `bash tests/guard/run-all.sh` and `bash -n` on touched files (green at red unless the guard rule is the test).
- **Green commit verification:** the targeted group passes, then all four suites plus `bash -n`.
- **Guard-rule fixes** (docs, comments, list completeness): the red commit adds the rule and its fixture case; the rule fails on the real tree (or the fixture) first.
- Cases that need a Docker-created folder or `docker volume ls` filter are proven in the fake at the red/green commits and again for real by the Mac run (D-11): H-20, H-09, H-03 additions.
- **The human must not squash-merge the PR.** The two-commit history is the "fails before" proof; a squash removes it. Say so in the PR text.
- **Branch prerequisites.** Code goes on a branch cut from the updated Phase 1.4 branch (or from `main` after 1.4 merges); open the PR against that same base. `.planning/` edits (disposition files, state) go on a separate branch and PR from code. No push without the human's go (project AGENTS.md).

### Shell portability constraints (macOS bash 3.2, BSD tools)

- No bash 4 features on the host side: no `mapfile`, `declare -A`, `${var,,}`, `&>>`, `|&`, `wait -n`, `coproc`, `local -n`. Under `set -u` bash 3.2 treats an empty array as unbound: test `${#arr[@]}` first (the library already does this). The new code uses none of these.
- `read -r -a` and `<<<` are used only in `base/sbx-start-lib.sh`, which runs in the Ubuntu container (bash 5). Do not use them in `tests/host/` or `tests/guard/`; the awk rule above is written to ignore a `<<<` in the host files anyway.
- GNU-only idioms to keep out of Mac-side files: `sed -i`, `sed -r`, `grep -P`, `readlink -f`, `realpath`, `date -d` or `--date`, `sort -V`, `xargs -r`, `stat -c` (allowed only inside `in_container` or `docker exec`), `timeout`, `mktemp --tmpdir`, `ps --ppid`, `find -printf`.
- Allowed on both: `pgrep -P`, `kill`, `mkfifo`, `printf`, `tr`, `cmp`, `awk` with POSIX features.
- Linux-only tools (`setsid`, `pgrep -s`, `ps -o sid=`) are fine in `tests/selftest/` only; the guard does not scan self-tests for portability.
- Untestable here: bash 3.2 and BSD awk are not installed. Mitigate by keeping new code to constructs already used elsewhere in `tests/host/`, by the portability rule, and by the final Mac run.
- Project rule from `best-practices/rules/shell.md`: a function that cannot recover returns non-zero, it does not `exit`; fail closed; a banner above every function; end with a `Main / Entry Point` block; a helper goes into a shared library only when two or more scripts use it.

## Common Pitfalls

### Pitfall 1: The red test passes by accident (CR-01)
**What goes wrong:** `slow() { sleep 7; }` is killed correctly because bash exec-optimises the single command, so the "red" test is green.
**Why:** The function's subshell becomes the sleep. Verified this session.
**Avoid:** Use a function with two statements, or `sh -c '...; exec sleep'` as above.
**Warning sign:** The red commit's group passes.

### Pitfall 2: Strict identity breaks the second Mac run
**What goes wrong:** Tying `assert_test_sandbox` to the new run folder makes `remove_leftover_test_container` refuse to remove the previous run's sandbox, and the run ends with `FAIL: SETUP`.
**Why:** `run-all.sh` leaves the sandbox running by design; `RUN` is a fresh folder each run.
**Avoid:** Split the rule as in "Sandbox identity". Keep a runner case with an old run folder and label `hosttest` that must still pass.

### Pitfall 3: H-20 leaves an exited container that the cleanup guard may refuse
**What goes wrong:** After the refused start the container exists, exited, mounting `$RUN/h20`. If `compose_down` required a mount equal to `$RUN` it would refuse, and the real sandbox would not come back.
**Avoid:** The loose rule accepts "the mount or its parent is named `sbx-hosttest-*`". Have the fake keep the container on refusal so the self-test sees this.

### Pitfall 4: Counts and lists that change with H-20
`runner-healthy.sh` (19 PASS lines, `Summary: 19 passed`), `runner-failures.sh` (`18 passed, 1 failed`, twice), the chain `NOT RUN` expectations, `tests/selftest/host/run-all.sh` `groupList`, `tests/host/run-all.sh` `chainCheckList`, the checklist title and chain text. Missing one fails a group or (after plan 01) the suite-list guard rule.

### Pitfall 5: Changing `lacks_text` flips an existing case
A case whose file does not exist at that moment was passing vacuously. After the change it FAILs. That is the point; fix the case's file, not the helper. Run all suites after plan 01.

### Pitfall 6: grep returns 2 even when it also found matches
`grep -En regex a b` returns 2 if any file is unreadable, even with hits. Treat status above 1 as a failure before looking at hits.

### Pitfall 7: Unprivileged-folder cases need a non-root user
`[ -w ]` is true for root. The dev sandbox user is uid 1001 (`id` run this session). The `start-folders.sh` group must include `expect "runs as a non-root user" test "$(id -u)" -ne 0` so a root run fails loudly instead of passing vacuously.

### Pitfall 8: Real-Docker messages differ by Compose version
The uppercase-name error reads `"MyCoolProject" is not a valid project name: it must contain only characters from [a-z0-9_-] and start with [a-z0-9]` in the issue tracker [CITED: https://github.com/docker/compose/issues/10512] and other versions say "invalid project name". Assert on non-zero status plus the stable words `project name`, not on a full message.

### Pitfall 9: `tmpfs` rejection cannot be verified here
Rejecting `tmpfs` means parsing the filesystem type after the `-` separator of `/proc/self/mountinfo`. The Docker Desktop VirtioFS value for a bind mount has not been observed in this repo, and a wrong guess refuses every start on the Mac. Recommended: wording only ("is not a mount point"), as CONTEXT allows.

### Pitfall 10: Planning IDs and forbidden words in new code
`planning-ids.sh` flags `Phase [0-9]`, `D-NN`, `CONTEXT.md`, `.planning`; add the finding-ID term. The start guard flags install words in the entrypoint and hooks. The unattended rule flags `read` and `docker exec -t`. The delete rule flags `rm`, `prune` and (after this phase) `--rmi`, `docker kill|stop`. New test and entrypoint comments must not contain these.

### Pitfall 11: Old layout guard
`old_layout_untouched` diffs `ClaudeCode/`, `OpenCode/` and `README.md` against a fixed commit. `README.md:35` shows the old `docker exec` form; leave it.

### Pitfall 12: Fake `-w` must be added before any test passes `-w`
`fake-docker:552-554` drops leading `-x` words and treats the next word as the container name. A test that adds `-w DIR` before the fake handles it fails with "No such container: DIR". Land the fake change in the same red commit as the first test that needs it.
