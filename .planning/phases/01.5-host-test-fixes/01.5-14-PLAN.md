## Phase Goal

ROADMAP.md Phase 01.5 goal (verbatim): "The known bugs in the host tests and the entrypoint, found by the Phase 1 and Phase 1.1 code reviews, are fixed and each fix is proven on the Mac. Kept out of Phase 1.3 so that identical output stays the proof of a safe restructure, and placed after Phase 1.4, which settled that the host checks run on the Mac. From the Phase 1.3 discussion."

Gap closure: the second half of D-14. The entrypoint refuses a bad name (plan 12), but only after Compose has already created or replaced a container: with the lowercased project name, starting Foo replaces the container of foo. A Compose level refusal stops that before anything happens. This plan adds it, points H-03 at it, and makes the fake docker model it.

Planning notes:
- Spec-less probe fallback skipped (no requirement IDs; visible skip).
- Why an image name: D-14 names "a field that Docker requires in lowercase, such as an image reference sbx-${SBX_NAME}". The project name, the container name, the hostname, networks and volumes all accept uppercase or are lowercased by Compose; only an image repository name must be lowercase. The sandbox image cannot carry the name (every sandbox shares sbx-claude:local), so the name goes into the image of a second service that never runs a container.
- What is known from the Compose 2.40.0 source (docker/compose tag v2.40.0, read while planning): `create` runs ensureImagesExists before ensureNetworks and before any container is made or replaced; the image check inspects the image of every service, including a service with scale 0; an inspect that says "not found" is skipped (a valid name is fine although sbx-NAME-name-check never exists), any other inspect error stops up with "unable to get image ..."; `up --wait` does not wait for a service with scale 0; pull_policy never means no pull.
- What only the final Mac run can prove (unmeasured, assumption M1): the Docker Desktop daemon answers the inspect of an image name with an uppercase letter with an "invalid reference format ... must be lowercase" error rather than "not found", so Compose 2.40 stops. H-03 asserts exactly that, so if it does not hold, the Mac run shows one H-03 FAIL line with the real output, and the gap returns to planning (D-14).
- Assumption M2 (unmeasured): a valid name's `up -d --wait` is unaffected by the name-check service. Every compose up of the Mac run proves it; if it does not hold, the test sandbox does not start (SETUP failure, the sandbox checks NOT RUN) and compose-up.log shows why.
- Fake docker claims and their status, stated in its header: the uppercase image name refusal and its message text are claims confirmed by H-03 on the Mac; Compose lowercasing the project name is measured (the fake's config answer is made to match it in plan 15).
- The up probe uses SBX_DIR=/sbx-hosttest-no-such-folder (a new name, because /sbx-hosttest-config-only marks config-only probes in the runner's log cases). It runs in the no-sandbox stage, when no test container exists.
- Task 2 is a protective guard rule, not a red/green pair; its commit must not be listed as a red commit in the SUMMARY.
- Reversibility: a service block of four lines in compose.yml; removing it undoes the change. No checkpoint: D-14 already chose the image-name refusal.
