### Why H-03 fails (root cause, confirmed in the code)

- `compose.yml:12`: `name: "sbx-${SBX_NAME:?SBX_NAME is required (lowercase letters, digits, - and _)}"`. Compose lowercases this name and exits 0.
- `tests/host/h03-variable-interpolation.sh` `check_uppercase_refused` requires a non-zero exit and the text "project name". Real Compose gives exit 0 and `name: sbx-hosttest`.
- `tests/selftest/host/support/fake-docker` `compose_config` prints `"sbx-X" is not a valid project name ...` for uppercase. Real Compose never does. Plan 06 recorded this as assumption A1 ("only the Mac run proves it"); the Mac run disproved it.
- The false claim is also stated as fact in `SANDBOX.md:17` ("`MyProject` is rejected"), `SANDBOX.md:208` ("Invalid project name | `SBX_NAME` must be lowercase."), and `tests/host-checklist.md:41` ("an uppercase name is refused"). These are still on the code branch, so the docs promise a refusal the sandbox does not perform.
- Real hazard behind it (review WR-01): `container_name` stays `sbx-${SBX_NAME}` (mixed case) while the Compose project is lowercased, so `Foo` and `foo` with different `SBX_DIR` values map to one project and one service. Starting the second can recreate and remove the first sandbox's container. Nothing in the entrypoint validates the name.
