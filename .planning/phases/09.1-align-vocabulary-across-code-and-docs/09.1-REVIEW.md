## Summary

The rename sweep is mechanically sound. I traced every renamed identifier, env var, check name, step name, file path and message across the repo and found no missed reference that is read somewhere:

- `BEST_PRACTICES_REPO_URL` and `SBX_BEST_PRACTICES_DIR` agree across `versions.env`, `base/Dockerfile` (ARG and ENV), `base/bin/sbx-best-practices-clone`, `paths.py`, the `env-best-practices` check, `230_versions_record.py` and the host checks. `build.sh` derives its build args from `versions.env`, so the pin rename needs no `build.sh` edit.
- `AGENT_CONFIG_DIR`, `make_state_dir`, `state_dir_name_list`, `host_hint`, `BEST_PRACTICES_DIR`, `UNREADABLE_DIR`, `best_practices_links` and the `sandboxDir`, `newSandboxDir` and `projectDir` shell variables have no stale reader or importer left. No local variable in the touched shell scripts collides with the new `sandboxDir` the library sets.
- `pyproject.toml` testpaths, the `supply-chain.sh` scan globs, `host-test.sh` step names and functions, `tests/host/run-all.sh` check lists and the `lib-expect.sh` source path (`../host/lib.sh`, same depth as before) all point at the new locations. File modes are preserved on every rename.
- Rewrapped message strings (`_incomplete_clone_result`) concatenate to the same text as before. Init step order and check order are unchanged because the numeric prefixes were kept.
- No non-ASCII characters, no dash-as-punctuation in prose and no planning IDs were added to source, tests or docs. No bash 4 features were introduced.

The defects that remain are documentation lines that the sweep rewrote or added and left inaccurate, plus a few missed vocabulary retirements the glossary itself says are retired.

## Warnings

### WR-01: New tests/README.md sentence contradicts the suite it describes

**File:** `tests/README.md:40`
**Issue:** The line added under `## tests/unit/sbx/` says the suite "runs whole `bin/sbx-*` scripts as processes against the stand-in docker, component-style". The table directly below it says the opposite: `DOCKER_HOST` points at a socket that does not exist, `build.sh` runs with no `docker` on the PATH, and `tests/unit/sbx/image-tag.sh` states "It adds no stand-in". The only stand-in in the suite is an `xattr` stand-in in `fix-modes.sh`. The sentence introduces a stand-in docker that does not exist (the project treats the fake docker as retired) and an undefined term ("component-style") into a doc whose job is to say exactly what each suite does and does not catch.
**Fix:** Delete the sentence, or replace it with one that matches the table:
```markdown
`tests/unit/sbx/` runs the real `bin/sbx-*` scripts as processes with no Docker available (no socket, no `docker` on the PATH).
```

### WR-02: README says the container creates the state subdirectories; sbx-init does

**File:** `README.md:132`
**Issue:** The sweep rewrote this line ("subfolders" to "subdirectories") and kept the claim "The container creates the subdirectories of `state/` itself." That is false for the current design. `compose.yml` runs `sleep infinity` with no entrypoint, and `README.md:469` says "The container checks nothing when it starts". The `state-dirs` step of `sbx-init` (`base/init/steps/010_state_dirs.py`) is what creates them, and `.claude/CLAUDE.md` now says the same ("Created by the `state-dirs` init step"). A reader of the Register section is told something that stops being true the moment they start the sandbox and see no `state/` subdirectories until they run `sbx-init`.
**Fix:**
```markdown
... and `/Users/you/sbx-demo/state`. `sbx-init` makes the subdirectories of `state/` when you first run it in the sandbox.
```

### IN-01: README Upgrade section uses "the clone" for the tools clone

**File:** `README.md:277-280`
**Issue:** "the clone whose `bin/` is on your PATH", "from that clone" and "that clone's `versions.env`" all mean the tools clone. `GLOSSARY.md:27` retires bare "the clone" in this meaning and notes that "best-practices clone" is a different clone. In this README the same section family also discusses the best-practices clone, so the bare word is ambiguous.
**Fix:** Write "tools clone" in all three places ("Change the pin in `versions.env` of the tools clone whose `bin/` is on your PATH ...").

**Fix:** Use "labeled".

### IN-03: .gitignore still headed "Mac test run"

**File:** `.gitignore:43`
**Issue:** `### Mac test run ###` over `host-test.log` is the project's own header (not third-party template text like `### Mac OS ###`), so it is a "Mac" stand-in for the host that the glossary retires. The file is outside the review list, which is probably why it was missed. Related, and not caused by this phase: line 38 reads `.DS_Store.mvn` (a missing newline glued two patterns together), so `.DS_Store` is not ignored; `git status` shows `?? .DS_Store`.

```gitignore
### Host test run ###
host-test.log
```
and split line 38 into `.DS_Store` and `.mvn` lines.

### IN-04: .claude/CLAUDE.md still describes retired start-hook error handling and a wrong compose file name

**File:** `.claude/CLAUDE.md:94`, `.claude/CLAUDE.md:205`
**Issue:** The sweep rewrote the entrypoint and start-hook material to the `sbx-init` design but left two stale spots. Line 205 still documents "Start errors in containers: `start_error MESSAGE` prefixed with `[sbx] ERROR:`", a function that no longer exists (the start hooks are gone; the shipped `[sbx] ERROR:` prefix survives only in `sbx-gh-login` and `sbx-best-practices-clone`). Line 94 names the file `docker-compose.yml`, while the file is `compose.yml` (as the component table at line 326 says).
**Fix:** Replace line 205 with the `sbx-init` convention ("A failing init step returns `failed(problem, hint)`; the runner prints `FAIL: NAME: problem` and a `fix:` line") and change `docker-compose.yml` to `compose.yml` on line 94.

### IN-05: Near-identical module names in the two Python trees

**File:** `base/init/best_practices_link.py`, `base/selfcheck/best_practices_links.py`
**Issue:** After the rename, `link_best_practices` lives in `best_practices_link` (init) and `best_practices_links_result` lives in `best_practices_links` (selfcheck), and the first imports from the second. Both directories are on `sys.path` in `sbx-init` (`sbx-init` lines 22-25), so one missing or extra "s" in an import resolves to a different, existing module with no error until a name is missing. Before the sweep the names were `best_practices_link` and `bundle_links`, which could not be confused.
**Fix:** Give the init module a name that differs by more than one character (for example `best_practices_linker`), or leave it and note the pair in the module header comments.

### IN-06: Bare "wrapper" remains in .claude/CLAUDE.md

**File:** `.claude/CLAUDE.md:20`
**Issue:** "shell stays only for thin `exec` wrappers" uses bare "wrapper"; `GLOSSARY.md:36` retires bare "wrapper" in favor of "agent wrapper". The sentence is a general statement about thin shell, not only the two agent wrappers, so a different word fits better.
**Fix:** "thin `exec` scripts (the agent wrappers)" or "thin `exec` commands".
