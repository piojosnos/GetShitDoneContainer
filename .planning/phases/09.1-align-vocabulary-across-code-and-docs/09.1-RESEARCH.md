### Locked Decisions

### Glossary first, then the change
- **D-01:** The first plan builds the glossary and stops at a checkpoint for the user's review. Nothing is renamed before the glossary is agreed. Later plans apply it.
- **D-02:** The glossary lives in a standalone `GLOSSARY.md` at the repo root, linked from `README.md` and from `.claude/CLAUDE.md` so agents follow it. Match the existing docs' voice: short, schematic, a table.
- **D-03:** Each glossary entry records: the concept, the chosen term, the retired synonyms (with where they occur), and any term kept on purpose with its reason (for example "CA bundle: industry term").
- **D-04:** Two rules pick a term, so the review is not a set of separate debates: (1) an industry-standard term always wins; (2) otherwise the name users type or see (a command, check or step name) wins, and the prose follows it.
- **D-05:** Watch for real distinctions that only look like synonyms. Verify each candidate pair against the code before merging terms. Known example to check: "launcher" (64 uses) vs "agent wrapper" (6); `sbx-selfcheck`'s and `sbx-init`'s launchers may be a different thing from `sbx-claude` and `sbx-cursor`. Same care for "registry" vs "registration", "project folder" vs "sandbox folder" vs "host folder".

### What the sweep covers
- **D-06:** "bundle" changes only where it means the user's rules and skills repo. The CA certificate bundle (`base/selfcheck/checks/280_extra_ca.py`, the `extra-ca-system-bundle` check and its tests) keeps "bundle": it is the industry term.
- **D-07:** "the Mac" is not a project concept. The host machine is generic (macOS today, Windows or another Linux box tomorrow); use one universal term, "the host" unless the glossary review finds a better one. Mac-specific facts (Docker Desktop on macOS, BSD tools) stay named as such where they really are Mac-specific.
- **D-08:** Folder vs directory: one word for everything we own, prose and identifiers alike. ## Summary

This is a rename phase, so the research is a counted, classified inventory. The repo has 253 tracked files outside `.planning/`; every count below comes from `git ls-files | grep -v '^.planning/'` read this session. Baseline before any change: `uv run pytest` gives 463 passed, `bash tests/guard/run-all.sh` ends "All rules hold.", `bash tests/selftest/sbx/run-all.sh` ends "All cases pass." [VERIFIED: ran all three this session].

Findings that change how the planner should size and order the work:

1. **"Bundle" is 441 occurrences in 37 files.** 80 of them are the CA bundle (two files, keep). About 361 are the best-practices repo (rename). They sit in 16 file names, so a `git mv` pass comes first.
2. **"Folder" is the dominant word, not "directory".** 647 prose and identifier occurrences of "folder" (173 in the 7 docs, 474 in code and tests) against 25 of "directory". In identifiers it is the reverse: `*_dir` / `*_DIR` / `Dir` has 100 distinct names with 1338 uses; `*_folder` / `Folder` has 157 distinct names with 320 uses. Every env var we own already says `DIR` (`SBX_DIR`, `SBX_CONFIG_DIR`, `SBX_STATE_DIRS`, `SBX_BUNDLE_DIR`, `SBX_AGENT_BIN_DIR`). Only two check names and one step name say "folder". D-08's lean to "directory" is confirmed by both D-04 rules, but it is the largest edit in the phase (about 650 words, 7 file names, 3 check or step names, and about 80 test-pinned messages).
3. **Start-hook leftovers are tiny.** Outside `.claude/CLAUDE.md` (about 24 lines) there are only two stale comments (`claude/selfcheck/lib/claude_shared.py:15`, `cursor/selfcheck/lib/cursor_shared.py:16`: "The sbx commands and hooks sit under the base roots"). The scout's "about 20 files" over-counts. The tests that mention `start.d` assert its absence and stay.
4. **D-05 look-alikes: only one is a true synonym.** "launcher" and "agent wrapper" are different things (keep both). "registry", "registry entry" and "register" are different roles (keep), but the noun "registration" (3 uses, all in `.claude/CLAUDE.md`) is a stray synonym. "project folder", "sandbox folder" and "host folder" are different directories except "host folder", which is a stray synonym of "sandbox folder".
5. **Two homonyms the scout missed:** "config dir" means both `~/.config/sbx` (`SBX_CONFIG_DIR`, holds the registry) and the agent's config directory (`state/claude`, Python `CONFIG_DIR`). "the clone" means both the best-practices clone and the host clone of this repo ("tools clone").
6. **Mismatched names, not just synonyms:** the checks `wrappers-root-owned` and `claude-wrappers` / `cursor-wrappers` do not check wrappers (they walk the image roots for root ownership); the `sbx-selfcheck` bug hint says "the self-check" while `sbx-init`'s says "sbx-init".

**Primary recommendation:** Do plan 01 (glossary + checkpoint) and the independent best-practices repo cleanup first; then apply the glossary family by family (best-practices, host, directory, remaining pairs), each ending with pytest, guard and `selftest/sbx` green, then docs, then the two separate PRs (`.planning/`, `.claude/CLAUDE.md`), with the Mac `./host-test.sh` as the final gate.

## Common Pitfalls

### Pitfall 1: Folder to directory breaks pinned messages
**What goes wrong:** about 82 assertion lines (33 pytest, 49 shell) quote "folder" text. **How to avoid:** change the message and its assertion in the same commit; run pytest and `selftest/sbx` per plan. **Warning sign:** a `FAIL:` from `bash tests/selftest/sbx/run-all.sh` naming a `has_text` or `expect` line.

### Pitfall 2: A word the guard bans sneaks into `bin/`
**What goes wrong:** `host_scripts_keep_sandbox_data` fails if any `bin/` file other than `sbx-rm` contains the word rm, rmdir, prune, kill or down. Rewording "shut down", "break down" or "scripts that rm" trips it. **How to avoid:** run `bash tests/guard/run-all.sh` after every `bin/` edit.

### Pitfall 3: Python module name collision between the selfcheck and init twins
**What goes wrong:** the init launcher puts both `/usr/local/lib/sbx-init/` and `/usr/local/lib/sbx-selfcheck/` on `sys.path` (`sbx-init:21-25`), and pytest has `base/selfcheck` and `base/init` on `pythonpath` (`pyproject.toml`). The init file is `base/init/best_practices_link.py` (singular). A selfcheck module renamed to `best_practices_link.py` would shadow it. **How to avoid:** name the selfcheck module `best_practices_links.py` (plural, distinct) or `best_practices_check.py`; the glossary plan decides. **Warning sign:** `ImportError` or a wrong function found in `from best_practices_link import ...`.

### Pitfall 4: Stale glob in a guard rule
