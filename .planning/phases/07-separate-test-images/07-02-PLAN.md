<objective>
The test harness uses the test images. `./host-test.sh` and `host_init` set `SBX_IMAGE_TAG=test`, the context step prints the test image names, the linter stand-ins run from `sbx-base:test`, every host check takes its image names from `BASE_IMAGE` and `CLAUDE_IMAGE`, H-03 checks that Compose renders the Claude test image, and a new guard rule keeps every `:local` name out of the host test files. Covers IMG-01 (the run builds and checks its own tags) and IMG-02 (the run never names, and so never replaces, a `:local` image); decisions D-03, D-05, D-06 and D-08.

Purpose: plan 01 made the real scripts follow the tag; this plan makes the test run set it, and set it so that nothing in the caller's shell can undo it.
Output: the two exports, the image-name globals, the nine host checks on variables, the H-03 assertion, and guard rule `host_tests_never_name_the_local_tag` (19 rules).

Recorded choices:
- The image-name globals are `BASE_IMAGE` and `CLAUDE_IMAGE`, uppercase like the other `host_init` globals (`REPO_DIR`, `CONTAINER`, `RUN`). The research proposed lowercase names, but shellcheck reports a lowercase global set by a sourced library as unassigned (SC2154, verified at plan time), which would fail the guard's `shellcheck_passes` rule in every check. They are not exported, so `build.sh` never sees them.
- H-25's bare build of `claude/Dockerfile` gets `--build-arg "BASE_IMAGE=$BASE_IMAGE"` (not in the research inventory): without it the build falls back to the Dockerfile default, a `:local` base, which a test run must not use and which may be missing after `./clean.sh --yes`. `BASE_IMAGE` is not a pin, so the check still proves that a build without `build.sh` stops at the first missing pin.
- Research open question 2 (`print_next_block` printing the tag in its cleanup command): not done. `docker compose down` needs no image, and D-08 keeps the change to what the design needs.
- Research open question 3 (`docker image inspect` of all three test tags after the build): not done. The Mac gate (plan 03) lists the test images with `docker image ls`.
- Flagged assumption (IMG-02, unclassified probe row): see plan 01; this plan carries the mechanical half (unconditional tag, guard rule).
</objective>
