<objective>
The tracer of this phase: one variable, `SBX_IMAGE_TAG`, carries the image tag from the caller's shell through `bin/sbx-lib.sh`, `compose.yml` and `build.sh`, so `SBX_IMAGE_TAG=test` names `sbx-base:test`, `sbx-claude:test` and `sbx-cursor:test` everywhere, unset or empty keeps `:local`, and any other value is refused. Then a dockerless self-test group pins the behaviour down. Covers IMG-01 (the production half) and IMG-02 (the default stays `:local`, ROADMAP success criterion 3), and decisions D-01, D-02, D-04 and D-08.

Purpose: the test run (plan 02) can only stay off the user's images if the real scripts it runs read the tag. This plan builds that path and proves it without Docker.
Output: the tag in four production places, the renamed guard rule `compose_image_follows_agent_and_tag`, `tests/selftest/sbx/image-tag.sh`, and `start_group` unsetting the tag and the certificate.

Recorded choices:
- Assumption-delta detector: `detected: false`; no identity-model checkpoint.
- The tag check is duplicated in `build.sh` rather than sourced from `bin/sbx-lib.sh` (research open question 1): `build.sh` stays standalone and does not set `scriptName` or `repoDir`; two copies are within the repo rule (extract at three); the two copies use the same list name, global and wording, and one self-test text covers both.
- `build_image` in `build.sh` renames its local `imageTag` to `imageName`: it holds a full name such as `sbx-base:test`, and the old name would shadow the new global `imageTag`.
- The guard rule `compose_image_follows_the_agent` is renamed `compose_image_follows_agent_and_tag`, because it now checks the tag hand-off and the base of each agent build too.
- The agent Dockerfiles stay untouched: their comment ("BASE_IMAGE keeps a default because it names the local base tag, not a version") is still true, and the guard rule `dockerfile_args_have_no_defaults` allows exactly that ARG line.
