## Phase Goal

ROADMAP.md Phase 2 goal (verbatim): "The sandbox has the full development toolchain plus Claude Code, GSD, and ccusage baked into the image at versions pinned in one `versions.env`. Rebuilding with changed pins delivers the new versions into the sandbox while login and history persist."

This plan is the supply-chain gate of D-11: every new pin, and the carried ones, gets a human approval before a plan writes it into versions.env. The package-legitimacy seam flagged all four npm packages `too-new` (recency only); this is the blocking checkpoint that flag requires. It writes no code; the only file is the pin table in the phase folder.

Planning notes:
- Research resolved these values on 2026-10-08; digests move (the Ubuntu tag was rebuilt since STACK.md). Task 1 re-resolves every value on the day the plan runs, so the user approves what will actually be pinned.
- Open question 1 (GSD pin) is answered here: 1.15.0 is recommended for its age; 1.16.0 becomes the attended bump target (the helper in plan 06 bumps to it for real, never committed). The user may swap them.
- Open question 2 (checksums share an origin with the artifacts, Phase 1 WR-03) stays as D-09 decided: upstream checksum files. The table says so, and plan 09 records it in the disposition.
- Reversibility: a pin is one versions.env line; reversible. The approval is the gate, not a one-way door.
