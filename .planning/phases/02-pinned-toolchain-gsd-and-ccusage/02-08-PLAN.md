## Phase Goal

ROADMAP.md Phase 2 goal (verbatim): "The sandbox has the full development toolchain plus Claude Code, GSD, and ccusage baked into the image at versions pinned in one `versions.env`. Rebuilding with changed pins delivers the new versions into the sandbox while login and history persist."

This plan closes success criteria 2 and 3 on the Mac side: the images carry exactly the pins of versions.env, a build that skips build.sh stops with a clear message, and no self-installed Claude copy sits in `~/.local`.

Planning notes:
- The bare base build stops while it reads the FROM lines; BuildKit's message is expected to name the empty variable, for example "base name (${TEMURIN_IMAGE}) should not be blank" (research A2, a Mac assumption recorded in plan 09). - Bare builds use `--progress=plain` so the failing command's message is in the log; their logs are named h25-bare-*.log, which H-01's platform scan does not read, and their command lines start with `build --progress=plain`, which the runner's build cases do not count.
- Task 1 touches eight files because a new host check is tied by the guard to its run list, its self-test group, its checklist row and the runner counts.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo pins to running images | an image built before a pin change keeps running old tools until someone rebuilds |
| sandbox user to ~/.local | the image home is writable by the sandbox user, where a self-update would install a copy |
