## Phase Goal

ROADMAP.md Phase 2 goal (verbatim): "The sandbox has the full development toolchain plus Claude Code, GSD, and ccusage baked into the image at versions pinned in one `versions.env`. Rebuilding with changed pins delivers the new versions into the sandbox while login and history persist."

This plan delivers success criterion 5: ccusage daily, monthly and session run in the container shell and report this project's real Claude usage from `<sandbox>/state/claude`.

Planning notes:
- Research confirmed on arm64 that the packaged native binary is mode 0644 and the launcher can only add the execute bit for the file's owner; in a root-owned global install the sandbox user cannot, so the build adds it (research Pitfall 2). This closes the STATE.md blocker "confirm ccusage's native binary is executable on arm64" once H-24 passes on the Mac.
- JSON shapes were checked on 2026-10-08 with ccusage 20.0.26: daily and monthly `--json` print a "totals" object with "inputTokens", "outputTokens" and "totalTokens", and "period" per row ("2020-01-07", "2020-01"); `session --json --id ID` prints "sessionId" and "totalTokens"; `--since/--until` limit daily and monthly to the day, so transcripts written by other checks (H-15, H-18) never change the numbers. The fixed date 2020-01-07 at 12:00 UTC stays the same day in any time zone the container might use.
- The transcript file name is fixed (h24-usage.jsonl, overwritten each run) and the session ID is run-unique, so a stale file cannot pass and a second run does not double the totals.
- H-24 reads ccusage's stdout only; its stderr notices never reach a compared value.
- Task 2 touches eight files because a new host check is tied by the guard to its run list, its self-test group, its checklist row and the runner counts.
- Reversibility: one more agent tool behind a pin; reversible.
