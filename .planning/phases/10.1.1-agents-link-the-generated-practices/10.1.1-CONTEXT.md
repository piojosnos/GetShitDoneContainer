**Gathered:** 2026-11-24

<domain>
## Phase Boundary

The sandbox side of the practices generator. The init linker and the selfcheck stop linking the masters and link what the best-practices clone holds under `generated/<agent>/` into that agent's config directory: the rules folder whole, one link per skill. Cursor gets rules for the first time; Claude moves its links from the masters to `generated/claude/` on the next `sbx-init`. Unit tests, the integration scenario (both agents through `AgentSpec`) and an attended Mac step prove it. One phase, one code PR.

Not in scope: merging the Claude and Cursor selfcheck twins (Phase 10.1.2); OpenCode (Phase 10.2); any change to the best-practices repo.

## Implementation Decisions

### Carried forward from Phase 10.1 (see 10.1-CONTEXT.md)
- D-17 (rules folder linked whole, one link per skill), D-18 (existing sandboxes fix themselves on the next `sbx-init`), D-19 (proof: selfcheck, integration scenario, attended Mac step), D-20 (GLOSSARY.md gains "master" and "generated practices" when this repo first uses them). D-21's fallback order is settled by D-01 below: option 1 works, options 2 and 3 are dropped.

### Links, settled by a probe
- **D-01:** Links, not copies. A probe on 2026-11-24 in a fresh Cursor sandbox (`probe`) linked `state/cursor/rules -> ../../best-practices/generated/cursor/rules` and `state/cursor/skills/bp-merged -> ../../../best-practices/generated/cursor/skills/bp-merged`. `cursor-agent` listed the 7 always-applied rules, quoted the first bullet of `bp-prose-style` word for word, and listed `bp-merged`, `bp-pr-reply` and `bp-update-practice` next to the GSD skills. So the Cursor CLI reads `$CURSOR_CONFIG_DIR/rules`, follows a linked rules folder and follows linked skill folders.
  - Not listed, both as expected: the 6 glob-scoped rules (java, python, shell, testing, spring-boot, freemarker; they load only for matching files) and `bp-exp-pre-pr-review` (it has `disable-model-invocation: true`, so it is started by hand only, as in Claude).
- **D-02:** If links ever stop working for an agent, the fallback is to copy for every agent, not only the one that fails (symmetry: one mechanism). Copying costs: init must rewrite and prune copies on every run (they go stale after a `git pull`); a hand edit of a copy is lost silently instead of failing the drift check; and `bp-best-practices` finds the clone by resolving the rule's link with `realpath`, which a copy does not have, so that rule would change too. Not built in this phase; recorded so the choice is not reopened.

### Linker shape
- **D-03:** The `links_rules` flag goes away. Both agents link rules and skills, so there is one code path: the linker and the check take the agent name (or a value derived from it) and build the paths and link texts from it:
  - rules: `<config_dir>/rules -> ../../best-practices/generated/<agent>/rules`
  - skill: `<config_dir>/skills/<name> -> ../../../best-practices/generated/<agent>/skills/<name>`
  - the skill list is read from `generated/<agent>/skills/`, not from `skills/`.
  The same applies to `AgentSpec.links_rules` in `tests/integration/agent_specs.py` and to the per-agent init and selfcheck wrappers. **Reversibility:** reversible; OpenCode's shape is handled in Phase 10.2 if it differs.
- **D-04:** The own-link test keeps its rule "any link whose target lies under the clone directory is init's own" (D-18), with the whole clone as the root, not `skills/` or `rules/` alone. Otherwise Claude's old links (`../../best-practices/rules`, `../../../best-practices/skills/<name>`) would count as clashes instead of being replaced. The same root applies to the stale-link removal and to the selfcheck's stale-link problem.

### Clone without generated output
- **D-05:** Fail closed. A clone that has no `generated/<agent>/rules/` or `generated/<agent>/skills/` (any clone from before best-practices PR #23) fails the step and the check, like today's "incomplete clone" failure, with a fix line: `git -C <clone> pull`, then `sbx-init`. No fallback to the masters.
- **D-06:** Migration is a one-time manual checklist for the user's 3 to 5 sandboxes, in the phase's docs and the attended step: `git -C <sandbox>/best-practices pull`, then `sbx-upgrade <name>`, then `sbx-init` in the sandbox shell. The pull is needed because `sbx-upgrade` rebuilds the images but does not touch the clone.

### Proof
- **D-07:** Unit tests for the linker and the check move to the `generated/<agent>/` layout and cover: fresh link for both agents, Claude's old master links replaced (D-04), a clone without `generated/<agent>/` failing with the pull fix (D-05), stale skill links removed. Drop the tests that only exist because of the flag.
- **D-08:** The integration fixture repo (`tests/integration/support/best-practices/`) gains a hand-written `generated/claude/` and `generated/cursor/` tree (rules and skills). The generator lives in the best-practices repo and is not run here. The scenario asserts the new link texts for both agents. The selfcheck counts in `AgentSpec` stay the same (no check is added or removed).
- **D-09:** The attended Mac step repeats the probe question through the real init (no hand-made links): after `sbx-init`, `cursor-agent` lists the rules and skills and quotes a rule; the same for Claude. Optionally, with a `.py` file in play, one scoped rule (`bp-python`) shows up.

### Claude's Discretion
- Whether the linker takes the agent name or an agent-derived path pair; module and function names.
- Wording of the fix lines and the passed detail (for example "4 skills and 13 rules linked from ...").
- Layout of the fixture tree, as long as it mirrors `generated/<agent>/` (D-06 to D-08 of 10.1).

</decisions>
