# Phase 10.1.1 Plan 01: Agent-neutral linker and links check Summary

**One linker and one check, keyed on the agent name, link `generated/<agent>/rules` whole plus one link per generated skill for both Claude and Cursor, treat any link into the clone as init's own, and fail closed on a clone without generated output.**

## Performance

- **Duration:** about 15 min
- **Completed:** 2026-11-25T00:06Z
- **Tasks:** 2 (one tracer, one auto)
- **Files modified:** 16 (10 changed, 6 created)

## Accomplishments

- `link_best_practices(config_dir, best_practices_dir, agent_name)` and `best_practices_links_result(...)` replace the boolean rules flag; each of the four wrappers passes `AGENT_NAME` from `claude_shared` or `cursor_shared`. Cursor gets rules for the first time.
- Link texts are templates: `../../best-practices/generated/{agent}/rules` and `../../../best-practices/generated/{agent}/skills/{name}`. `generated_dir` is the one place that builds the clone path.
- The whole clone is the own-link root, so Claude's old links into the masters are replaced on the next `sbx-init`, and a dangling link for a dropped skill is removed.
- `clone_failure` checks `generated/<agent>/rules` then `generated/<agent>/skills`; the detail names the path relative to the clone, the pull hint is unchanged, and the config directory stays untouched.
- Six hand-written fixture files (one rule, two skills, per agent) mirror the real generated output; one Docker-free test links them and runs the check for both agents.
