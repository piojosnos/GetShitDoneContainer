# Phase 10.1.1: Code Review Report

**Reviewed:** 2026-11-25
**Depth:** standard
**Files Reviewed:** 20
**Status:** issues_found

## Summary

The linker and the links check are consistent with each other and with the tests: the link texts come from one shared template, init only ever calls `Path.unlink` on a symlink it has just proven to be one, and an exception in a step is turned into a FAIL by `run_one`. I found no blocker. The weak spots are the broadened "own link" rule, the silent pass on an empty generated skills directory, and the Edit protection that no longer matches what the `rules` link now points at.

## Warnings

### WR-01: `state/<agent>/rules` now points at generated files, but only `skills/**` is denied for Edit

**File:** `claude/managed-settings.json:7` (and `claude/selfcheck/090_managed_settings.py:56`)
**Issue:** The `rules` link used to point at the masters, so editing a rule through `state/claude/rules/x.md` was the intended path. It now points at `generated/claude/rules`, which README and the drift check say must never be hand edited. The deny list still covers `state/claude/skills/**` only, so the agent can edit a generated rule through the link and make the clone fail the drift check. Cursor has no deny list at all. README's "Edit protection" section describes the skills case only and does not mention that rules are now in the same situation.
**Fix:** Add `Edit(//home/sandbox/workspace/state/claude/rules/**)` to `managed-settings.json`, update `expected_deny_list` in the managed-settings check, and extend the README "Edit protection" bullets. If a rules deny is rejected on purpose, say so in README so the gap is documented.

### WR-02: An empty or partly checked-out `generated/<agent>/skills` passes and silently removes every own skill link

**File:** `base/selfcheck/best_practices_links.py:47-57`, `base/init/best_practices_linker.py:103-123`
**Issue:** `clone_failure` only tests `is_dir()`. With an empty `generated/<agent>/skills/` (a failed generator run, an interrupted pull) the step reports `OK ... 0 skills linked`, and `_remove_stale_links` removes every link into the clone, including the old master links, because no name is in `skill_name_list`. The sandbox then has no best-practices skills and `sbx-init` still prints OK. The phase goal says the step fails closed when the clone lacks the generated directories; an empty one defeats that in practice. The same holds for an empty `rules/`.
**Fix:** In `clone_failure`, treat a `skills` directory with no non-hidden subdirectory as incomplete (same message and pull hint), or have `link_best_practices` fail before the stale removal when `skill_name_list` is empty. Add a unit test for it in both test files.

### WR-03: "Own link" now means any symlink into the clone, so a deliberate user link is removed without a word

**File:** `base/selfcheck/best_practices_links.py:29-40`, `base/init/best_practices_linker.py:116-123`
**Issue:** The test is `target under <clone>`, with no check that the target is under `generated/<agent>/`. A link a user made on purpose, for example `state/claude/skills/draft -> ../../../best-practices/skills/draft` (a master not yet generated), or a link into another agent's `generated/` tree, is unlinked by `sbx-init` as "stale", and the check reports it as a problem. The README documents the migration reason, but not that a user's own link into the clone is also deleted. The deletion is limited to symlinks, so there is no data loss, but it is silent.
**Fix:** Keep the broad test only for the migration case: treat a link as own when its target is under `<clone>/skills/`, `<clone>/rules/` or `<clone>/generated/`, or at least print the removed names in the OK detail. State the rule in README ("a link into the clone is replaced or removed").

## Info

### IN-01: A problem hides a clash in the same result

**File:** `base/init/best_practices_linker.py:138-147`
**Issue:** `_result` returns only `problem_list` when it is non-empty, so clashes found in the same run are dropped from the output until the problems are fixed. The clash text "every other skill is linked" is also wrong when the clash is the `rules` link (the skills are linked, rules is the one left).
**Fix:** Join both lists in the detail, and word the clash sentence per path ("the rest is linked").

### IN-02: Correct links are unlinked and recreated on every `sbx-init`

**File:** `base/init/best_practices_linker.py:73-77`
**Issue:** An own link whose text already equals `link_text` is still `unlink()`ed and `symlink_to()`d. A running agent can see the path missing in between, and a failure of `symlink_to` after the unlink (disk full, read-only) leaves the link gone. The result is reported as a problem, so it is not silent, but the rerun is not a no-op.
**Fix:** `if entry.is_symlink() and link_text_of(entry) == link_text: return` before the replace.

### IN-03: The link texts assume the production layout, though the directories are injectable

**File:** `base/selfcheck/best_practices_links.py:18-19`, `base/init/best_practices_linker.py:29`
**Issue:** `link_best_practices(config_dir, best_practices_dir, agent_name)` takes both directories as parameters, but the link text is a fixed `../../best-practices/...`. It is only right when `config_dir` is `<ws>/state/<agent>` and the clone is `<ws>/best-practices`. The tests keep that shape by hand (sibling `state1/<agent>` and `best-practices`), so a mistaken layout in a test or a future caller produces dangling links with no error.
**Fix:** Compute the text with `os.path.relpath(generated_dir / "rules", config_dir)`, or document the layout assumption in the module header.

### IN-04: Docs drift

**File:** `tests/host-checklist.md:25`, `MIGRATION.md:143-145`
**Issue:** The checklist step 2 gives the expected link texts for `generated/cursor/` only, and says "in a Claude sandbox, `$CLAUDE_CONFIG_DIR`" without saying the texts then read `generated/claude/`. `MIGRATION.md` still describes `sbx-init` as "links the best-practices clone" and does not mention the one-time pull before the upgrade that README now requires; README points to MIGRATION.md for the old-layout clash.
**Fix:** Name `generated/claude/` for the Claude case in the checklist; add the pull-then-`sbx-upgrade`-then-`sbx-init` order to the MIGRATION.md section on the clone.

### IN-05: Test coverage gaps

**File:** `tests/unit/init/test_init_best_practices_linker.py`, `tests/unit/selfcheck/test_best_practices_links.py`
**Issue:** No test covers an empty `generated/<agent>/skills` (WR-02), a clash and a problem in one run (IN-01), or an own link into the other agent's `generated/` tree. The selfcheck tests use `agent1` only; the Claude and Cursor agent names are exercised for the happy path in the init tests alone. The last block of `test_the_integration_fixture_links_and_passes_the_check_for_each_agent` compares a directory listing taken through the link with the listing of its target, which tests the filesystem rather than the linker.
**Fix:** Add the three tests above; drop or replace the listing comparison by the check that the generated rule text differs from the master (already there).
