#### Linker shape
- **D-03:** The `links_rules` flag goes away. Both agents link rules and skills, so there is one code path: the linker and the check take the agent name (or a value derived from it) and build the paths and link texts from it:

Otherwise Claude's old links (`../../best-practices/rules`, `../../../best-practices/skills/<name>`) would count as clashes instead of being replaced. ## Summary

The change is small and fully contained in two shared Python modules (`base/init/best_practices_linker.py`, `base/selfcheck/best_practices_links.py`), four 20-line wrappers, one `AgentSpec` field, one integration test file, the fixture tree and docs. No Dockerfile changes: the Dockerfiles copy by glob (`base/init/*.py`, `base/selfcheck/*.py`, `claude/init/*.py`, `claude/selfcheck/*.py`, `claude/selfcheck/lib/*.py`, same for cursor), no new file is needed, and no test pins a file name or content of these modules except the inventory tests, whose step and check names do not change.

Today `links_rules` (a bool) selects between "rules/ is the needed dir and a rules link is made" (Claude) and "skills/ only" (Cursor). It is threaded through `clone_failure`, `linked_detail`, `best_practices_links_result`, `link_best_practices`, `_result`, both init wrappers, both selfcheck wrappers, and `AgentSpec`/`_live_target`/`_link_problem_list` in the integration tests. The three master paths (`RULES_LINK_TEXT`, `SKILL_LINK_TEXT_TEMPLATE`, and `best_practices_dir / "skills"` / `"rules"` in six places) are the only other things that encode the old layout. Replace the flag with an agent name and build every path and text from it.

One genuine hazard the planner must carry: the shared integration sandbox clones the fixture origin and runs `sbx-init` for every scenario. Once the linker fails closed (D-05), a fixture without `generated/<agent>/` breaks every integration scenario, not just the relink ones. The fixture tree must land in the same PR as the linker.

**Primary recommendation:** Add `AGENT_NAME` to `claude_shared.py` and `cursor_shared.py`, pass it through the four wrappers, build link texts, clone checks, skill list and own-link root from `(clone, agent_name)` in `best_practices_links.py`, drop `links_rules` everywhere (replace `AgentSpec.links_rules` by a `rules_extension` field), add `generated/{claude,cursor}/` to the fixture, and rewrite the unit tests in place.

    if not link.is_symlink():
        return False
    actual_text = link_text(link)
    ...
    target = os.path.normpath(os.path.join(link.parent, actual_text))

It is purely lexical (no resolve, no existence test), so a dangling link into the root still counts. The caller supplies `target_root`; today the rules link passes `clone/rules` and skills pass `clone/skills`. ## Common Pitfalls

### Pitfall 1: The fixture lands after the linker
**What goes wrong:** the shared sandbox fixture clones the fixture origin and runs `sbx-init`; `_require_success(init, ...)` fails the whole integration run.
**Why:** D-05 fails closed when `generated/<agent>/` is missing. [VERIFIED: tests/integration/conftest.py `shared_sandbox`: git clone of `best_practices_origin`, then `docker_exec(container, "sbx-init", 600)`; `best_practices_origin` is `shutil.copytree(SUPPORT_BEST_PRACTICES_DIR, seed_dir)`]
**How to avoid:** fixture tree and linker change in the same plan wave; add a no-Docker unit test that runs the linker and the check on the fixture tree (see Validation).
**Warning signs:** every scenario errors in fixture setup, not in an assertion.
