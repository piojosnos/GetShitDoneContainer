Fix review finding WR-02 of phase 10.1.1: an empty `generated/<agent>/skills/` (or `rules/`) in the best-practices clone must fail closed like a missing one. Today `clone_failure` only tests `is_dir()`, so init reports "0 skills linked" and `_remove_stale_links` deletes every own skill link.

Purpose: a pull or generator run cut short must never leave a sandbox with no best-practices skills while `sbx-init` prints OK.

Decisions taken here (the task left them to the planner):
- "Empty" for skills: no non-hidden subdirectory, exactly what `best_practices_skill_name_list` returns. "Empty" for rules: no non-hidden regular file (generated rules are `bp-*.md` / `bp-*.mdc` files). Hidden entries (a `.gitkeep`) do not count.
- Detail text: same builder (`_incomplete_clone_result`), same shape `CLONE exists but has no ...`, same hint byte for byte. A missing directory keeps its text unchanged. An empty one reads `CLONE exists but has no skill in generated/AGENT/skills/` (or `no rule in generated/AGENT/rules/`). Reusing the missing text verbatim was rejected because "has no ... directory" is false when the directory is there; a user who runs `ls` would be misled.
- Order: both missing tests first (the existing loop, untouched), then rules empty, then skills empty. This keeps every existing missing-directory test valid.
- The linker is not touched: it calls `clone_failure` before placing or removing anything, so one fix covers init and the check.

Output: one code commit on `feat/agents-link-generated-practices` (tests, fix, README row), the same commit cherry-picked onto the local `feat/agents-link-generated-practices-code`. No push.
